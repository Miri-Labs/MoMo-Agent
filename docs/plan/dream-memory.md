# 分类记忆与自动整理

2026-10-17，用户要求参考 Hermes Agent 的 Dream 系统，让 MoMo 自动整理记忆，并拆开单一 MEMORY 编辑页。实现位于独立分支 `codex/dream-memory-20261017`，合并前纳入远端 main 的后续改动，保留其他工作树的状态。

## 源码核对

- Hermes Agent 本体：`bebe448a2bdb57043ca8ebd820807bf7eed6320d`，`tools/memory_tool_store.py`、`plugin-catalog/hermes-dreaming.yaml`。本体区分 USER 与 MEMORY，写入时加锁，按条目更新；会话开始冻结快照。并不是本体自带一个统一的 Dream 引擎。
- 官方插件目录中的社区插件 `itpartypattaya/hermes-dreaming` 2.8.0：固定 `cbb7f6dd21e9ba828790e38399671807aee1e593`，核对 `dream.py`、`dream-precheck.py`。本地筛选先运行，有值得整理的事项才唤醒模型；候选需真实用户发言佐证，保留来源，重复发言按不同日期计算。容量接近上限也是整理触发条件。
- 本次借用分类、来源核对、无变化跳过、持久重试和用户修正优先的机制。Swift 实现复用已有模型连接与后台队列，不安装 Hermes、Python 服务、定时进程或外部记忆供应商。

## 存储与取用

| 文件 | 内容 |
| --- | --- |
| SOUL.md | 人格，后台不可修改 |
| USER.md | 个人资料与长期偏好 |
| RELATIONSHIPS.md | 人物与关系 |
| PROJECTS.md | 项目及持续背景 |
| GOALS.md | 长期目标、明确承诺及完成或取消状态 |
| EPISODES.md | 带发生时间的近期经历与录音讨论，自动条目30天后退出活跃记忆 |
| MEMORY.md | 其他长期事实及尚未分类的旧条目 |

旧文件保持原路径和原内容。新增分类为空；模型只可原样移动完整条目，不可通过后台整理改写、概括或删除旧事实。相同条目在目标分类已存在时合并为一份。多事实混在同一条目时暂留原处，避免分类丢失细节。

正文是自由 Markdown。分类只决定文件位置，不要求字段表单、固定标题、JSON 或 YAML。和 Hermes 一样，用 `\n§\n` 分隔可独立编辑的条目；每条可以包含多段、标题、列表和链接。模型通过 memory 工具的 JSON 参数提交 add / patch / remove / operations，正文按原样保存；助手正文不再承担 JSON 提案协议。新提取条目不再由程序加 `[进行中]`、`[录音讨论 时间]` 等固定前缀；来源、类型、处理游标和到期时间保存在旁置状态文件。明确完成承诺时保留原文，附一句自然的确认说明。单个模型新增条目上限 2 KiB，文件整体容量仍单独检查。

聊天保留每条请求冻结快照。旧请求未包含新分类仍可恢复；新消息读取分类预览，总内容最多 8 KiB，单条最多 2 KiB，完整条目轮流取用，省略数量随预览提供。`memory read` 可读取所需分类，避免把所有记忆塞进每次推理。分类内容变化也会使旧首页建议失效。

## 整理状态与手机开销

状态依次为：本地检查 → 持久登记尝试 → 有界 memory 工具调用 → 校验原话、当前版本和取消状态 → 提交分类及来源游标。没有内容或输入未变化时，跳过模型。成功后至少间隔 6 小时；失败登记至少 1 小时的退避，实际运行时间受现有后台队列和 iOS 调度影响。没有新资料时不会按时钟重复调用模型。低电量模式跳过自动整理。

复用 AutomaticInsights 和系统已有后台任务。开始聊天、更换模型、关闭 Agent 或关闭自动整理会取消生成；提交前再次核对。整理不依赖任何录音结束事件，不改变录音、传输、转写和回放状态。iOS 不保证夜间固定时间执行。

每轮最多检查 12 个近期会话，每库最多 200 个有界 Pi 记录；聊天输入最多48条、16 KB，范围为近30天，另取最近3天已形成文字的录音段落。两类合计最多80条、24 KB。不等待录制结束。历史读取以只读 SQLite 打开现有固定版本 Pi 数据，读取完即关闭，不启动旧 Harness，不恢复旧推理，不在网络请求期间保留该读取连接。查询格式属于固定 Vendor 版本的适配点，测试使用真实 Pi 写入的数据库核对。

一轮通常请求一次模型，工具校验未通过时最多请求一次修正，共用 120 秒截止点，每次模型调用仅一次 HTTP 尝试；不调用系统行动工具；聊天开始或系统后台时间到期可提前取消。后台不需要新增向量模型或常驻进程；原始对话仍在原库，Dream 状态保存内容哈希、来源标识、时间、状态和整理配置；memory read 会按条目提供最多8条来源说明，便于回查原始资料。

## 独立模型与推理设置

「个性与记忆 → 整理模型与推理」可以选择已保存连接，或跟随当前聊天连接；同一连接可以填写专供整理的模型 ID。复用该连接的地址、协议和钥匙串密钥，不改变聊天模型。明确选择的连接被删除后不转用其他连接。独立连接即使与聊天连接地址、模型相同，也使用其自己的密钥。

推理默认「服务商默认」，不隐式关闭或调整。用户可明确选择关闭、低、中、高；通过 Pi 的对应协议编码发送，服务商不支持时报告失败，不悄悄切换。仅显式设置推理时为该次独立连接声明推理能力，现有通用连接的默认行为不变。

输出预算从固定 3,000 tokens 改为默认 16,384，可选 4,096–65,536；计入 API 算在输出预算内的推理 token。实际预算最多为所配上下文的一半，界面显示该限制，输入另按剩余空间设限。完整 JSON 上限为 64 KiB；单轮条目数与每条内容仍受记忆约束。模型报告 length、正文为空或输出不合法时不提交记忆，保留原输入游标，显示截断或校验状态，后续可提高预算重试。修改配置会取消旧任务并使旧结果失效。

## 证据与并发

稳定偏好须有至少两个不同日期的用户原话支持；个人资料、关系、项目和明确承诺可从一次直接陈述记录。每处引文逐字匹配、至少六个字符，至少一处来自尚未处理的新输入。助手输出、工具正文、内部上下文和重试替换输入不成为佐证。新版本附件若提供独立 userText，则只读取用户输入文字。凭证样式及指令注入样式先做本地隔离；这些模式筛选不保证识别所有敏感信息，模型还须按提取规则判断。

录音的说话人尚不能可靠归属到用户，因此录音仅可生成带时间和来源的近期经历，程序强制禁止其生成用户偏好、关系、项目所有权或个人承诺，禁止据其关闭承诺。自动经历30天后从 EPISODES 移除，原始聊天、音频与转录不变。明确要求记住、纠正或忘记时，聊天工具可立即执行，无需等待跨日佐证。

承诺在内部保持未完成状态。用户在新聊天中明确说已完成或已取消，后台才更新状态，并保留原事实、原始来源及完成证据；时间经过、没有后续、录音中的第三方陈述均不能作为关闭依据。日期与责任人的修改继续通过用户明确纠正的 memory 工具完成。

每次整理冻结全部分类版本。用户修改、清空、关闭开关或后续资料变化都会使旧结果无法提交。手动删除或纠正条目时同时推进来源时间下限，避免用旧聊天重新创建该事实；旧事实的改写与遗忘继续由用户发起，承诺状态的自动更新只接受明确的新聊天证据。

分类变更、来源游标和整理状态用同一个锁和持久重做日志提交。中途退出后先恢复日志，再允许读写，防止只删除来源分类却没有写入目标分类。容量或任意候选校验失败时整批不写，保留原文和明确失败状态。日志不额外保存原始聊天副本。

## 与 Hermes 的逐项对齐和业务差异

| 能力 | 核对源码 | MoMo 实现与适配 |
| --- | --- | --- |
| 按条目读取、写入、匹配旧原文 | memory_tool_store.py 的 add/replace/remove、apply_batch | 复用既有 memory 工具、精确匹配、版本令牌和原子批次；保留本应用 patch 保全其他事实的已有契约 |
| 一轮冻结记忆 | memory_tool_store.py 的 system_prompt_snapshot | AgentPromptSnapshot；重试沿用旧快照，新消息读取新版本 |
| 本地判断有无工作 | dream-precheck.py 的 wakeAgent 和 memory_pressure | 内容哈希、待处理来源、容量上限、持久退避；无变化不发模型请求 |
| 真实人类发言佐证 | dream.py 的 promotion_ready / corroborate | 稳定偏好跨日核对；明确资料、项目与承诺当次记录。录音归为事件背景，不推断用户身份 |
| 去重和保留修改锚点 | dream.py 的 nearest_entry / _replace_anchor | 移动完整旧条目，目标已有相同条目时去重；承诺状态只使用精确旧条目锚点 |
| 来源、冷却、未完成不确认 | dream.py 的候选来源、cooldown、agent acknowledgement | 记录来源和处理游标，未完成不推进；取消、配置变更及用户修改后拒绝旧结果 |
| 与个人生活有关的时间状态 | MoMo 业务适配 | 一次咖啡是经历，不是偏好；一次明确承诺立即保留；有直接完成证据才结束，不把昨日讨论永远当待办 |

提取规则、允许的来源、晋升条件、事件保留和承诺生命周期各有独立约束。当前实现只做精确重复合并，不用模型概括来删减旧条目的细节。
