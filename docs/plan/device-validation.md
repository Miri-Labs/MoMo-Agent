# MoMo Agent 分层验证计划

日期：2026-10-13，状态核对于 2026-10-14。本表的真机验收项目均 **未执行**。已有 Mac 软件链路、iPhone 模拟器、公开朗读基线及等量存储验证；结果与适用边界见[实施记录](../implementation/status.md)，不计作本表的真机通过。

开发任务与本表测试编号的对应关系见[详细开发与验收计划](v0.1-execution-plan.md#10-开发任务与依赖)。后台行为在脱离 Xcode 调试器的条件下验收；调试运行结果另外记录。

完整用户流程、自动化边界、测试数据、质量判定和发布门槛见 [E2E 测试总方案](e2e-test-plan.md)；J01～J28 的操作、断言及与本表编号的映射见 [E2E 用户旅程](e2e-scenarios.md)。本表继续保存原子验证项，运行结果按 E2E 总方案汇总。

测试设备为 Apple Watch SE2 与配对的 iPhone 17 Pro。开始前记录系统版本、应用构建、模型哈希、音频参数、手机剩余空间和设备温度状态。电池续航不作为本轮软件方案的淘汰条件；因断电而终止的测试需记录实际覆盖时长。

## 1. 录音与传输

| ID | 操作与条件 | 验证结果 |
| --- | --- | --- |
| R01 | 前台开始录音，放下手腕，持续 30 分钟 | 原音可解码，时长和测试时钟一致；屏幕关闭期间持续采集 |
| R02 | 录音中返回表盘，再打开其他应用 | 记录真实状态变化，采集未丢失或缺口有准确记录 |

| R04 | 暂停、继续、停止后重新开始 | 用户暂停不被自动恢复；各区间归属正确 |
| R05 | 分别启用和关闭耳机，变化音频路由 | 记录实际输入；不悄悄改成手机麦克风 |
| R06 | 在多个文件边界附近播放带编号的连续语音 | 检测漏采、重复和编码尾部误差；统计边界偏差 |
| R07 | 录音中终止 Watch App，再次启动 | 已封口文件完整；活动文件按实际可恢复范围处理 |
| R08 | 录音中修改时区或跨午夜 | 按实际采集顺序回放，日期显示与时长一致 |
| R09 | 手机关闭 App 或离开连接范围 2 小时 | 手表保留录音与待传时长；重新连接后补齐 |

| R11 | 重复发送、乱序发送、丢失确认 | 手机不重复记录；确认可以重发；最终文件哈希一致 |
| R12 | 接收文件校验不通过 | 不发送成功确认，不覆盖已有正确文件 |
| R13 | 手表空间接近安全阈值 | 提示并记录停止原因，不删除未确认录音 |
| R14 | 手机没有可用存储空间 | 不错误确认接收；恢复空间后可补传 |
| R15 | 删除时断开设备连接，之后重新连接 | 已删除数据不会被重试传输恢复；删除状态可追踪 |
| R16 | 开始一轮目标 18 小时的采集 | 导出覆盖时长、缺口、文件数、传输积压和中断原因 |

| R18 | 对照允许 / 不允许录音期间的系统声音和触觉反馈 | 同时记录提醒是否出现、录音缺口及振动噪声；不把通知无震动直接归因为中断 |
| R19 | Watch 与 iPhone 先后更新，出现构建或协议版本差异 | 协议兼容时正常处理；不兼容时保留录音并明确提示，诊断可见双端构建 |
| R20 | 到达保留期时分别存在转写成功、无语音判定、失败和未处理文件 | 自动清理只执行已完成流程且符合策略的文件；明确删除另行处理 |

使用受控测试声源测量分片边界。腕部日常收音另做质量集，不能让靠近手表的扬声器成绩替代远场结果。

## 2. 中文转写质量集

准备约 90 分钟 SE2 原始录音，由人工标注语音区间和文字：

- 约 60 分钟含目标语音，覆盖普通话、中英混说、产品名与人名、数字与日期、不同距离、走路和衣袖摩擦背景。
- 约 20 分钟不含语音，覆盖静音、风声、交通声和摩擦声。
- 约 10 分钟包含电视讲话、音乐人声或多人重叠。单独标注，不能将真实存在的语音当成 VAD 误报。

所有候选使用同一份音频。固定切分、语言选项和文本归一化规则。比较 VAD 时用人工语音区间；比较 ASR 时同时报告使用人工区间和产品 VAD 区间的结果，以区分漏检与识别错误。

| 指标 | 记录方法 |
| --- | --- |
| 中文 CER | 明确标点、空格、繁简、数字归一化规则；同一规则计算全部候选 |
| 人名 / 术语 / 日期 | 按人工标注项报告正确率与实际错误例子 |
| 语音漏检 | 报告被 VAD 丢弃的语音时长和低声讲话样本 |
| 无语音时编造文字 | 在 20 分钟无语音集上单独统计输出 |
| 时间定位 | 抽样比较点击回放起点与人工标注的发声时间 |
| 模型重跑 | 结果版本可辨认；人工修订不会被自动覆盖 |

先比较 SenseVoiceSmall INT8 CPU 与可用的 Apple SpeechTranscriber。需要优化时再加入 SenseVoice Core ML 和 Paraformer。Apple 路线先验证中文资产可用且可断网运行，再纳入质量排序。

## 3. 持续性能与后台行为

| ID | 操作与条件 | 验证结果 |
| --- | --- | --- |
| T01 | 冷启动与模型已加载时分别处理固定样本 | 分别记录加载耗时和识别耗时 |
| T02 | 顺序处理 30 分钟、2 小时原始音频 | 记录端到端 RTF、峰值内存、温度变化与吞吐下降 |
| T03 | 分别使用 1 / 2 / 4 个线程 | 选择持续吞吐和手机可用性合适的配置 |
| T04 | 转写时切后台、锁屏 | 记录实际执行时间、暂停点和恢复结果 |
| T05 | 等待系统后台任务，再比较用户发起的继续处理 | 区分调度等待与模型计算，不能只计模型速度 |
| T06 | 强退 App、取消长任务、触发到期 | 已提交结果保留；重启不从整天开头重跑 |
| T07 | 断开外网，保留配对设备通信 | 录音、传输、已有模型转写、阅读与回放均可完成 |
| T08 | 中文模型未安装、下载中断、哈希不匹配 | 有具体错误与恢复入口；不静默切换到云端转写 |
| T09 | 首次开机未解锁与首次解锁后再锁屏 | 文件保护和任务状态符合设计；不可读时明确等待 |
| T10 | 连续 3 天导入每天 18 小时等量录音 | 记录每日新增、完成、积压；验证实际使用节奏能消化任务 |

端到端 RTF = 解码、VAD、识别和保存的实际运行时间 / 同次计时实际完成的唯一核心输入时长。重试和重放只增加运行成本，不重复增加分母；未完成输入另列，完成量为零时不填零 RTF。全批完成后再算全批 RTF。另列模型 RTF，不能用只含语音的片段速度推算全日处理时间。调度等待时间独立报告。

开发阶段先验证持续计算时端到端 RTF 小于 1，并确认真实日常运行机会能清空积压。更严格的延迟、CER 和内存发布门槛在第一轮测量后确定，避免把未经测量的数字写成承诺。

## 4. 覆盖与结果记录

每轮报告至少包含：设备与系统、构建和模型版本、请求录音时段、已保存音频时段、未保存时段及原因、已接收时长、已转写时长、剩余任务、失败与重试次数、实际字节数、性能数据和原始日志位置。

录音覆盖按区间并集计算，避免重叠片段被重复计时。静音保留、VAD 未发现语音、录音中断和数据尚未收到分别统计。测试结果只能填写通过、失败、部分通过或未执行，并附上证据。

项目中的测试音频需要明确授权。含私人对话的原始音频与逐字稿保存在受控本地目录，不提交到 Git 仓库。

## 5. 录音方案对照

候选定义与取舍见[技术方案第 11 节](v0.1-plan.md#11-录音方案讨论)。本节所有实验均为 **未执行**。第一组优先比较 R-A、R-B、R-D；R-C、R-E、R-F 保留为后续候选。

| ID | 比较条件 | 需要记录的结果 |
| --- | --- | --- |
| X01 | 相同音频与文件大小，比较约 15 分钟批次提交和封口后提交 | 实际到达延迟、任务数量、待传时长与失败重试；区分提交和到达 |
| X02 | R-A 比较 30 秒、1 分钟、5 分钟文件 | 采集边界缺口、封口开销、文件数及异常终止后的可恢复范围 |
| X03 | R-B 在双方前台、双方锁屏、切后台、手机进程终止等条件下传输 | 实际可达状态、持续吞吐、背压触发、未确认片段与本地缓存完整性 |
| X04 | R-B 即时传输后断连，再通过文件补传；插入重复、乱序和确认丢失 | 音频覆盖完整，重叠音频不产生重复文字；确认前不清理手表副本 |
| X05 | R-D 使用人工标注的语音集，并加入长时间连续人声 | 人声到达与文字生成延迟、未优先传输区间的补转写、完整文件是否长期积压、总传输量 |
| X06 | R-C 在保留独立测试原音的条件下执行人声筛选 | VAD 丢弃的真实语音、低声与短句漏检、缓存前后长度对边界的影响 |
| X07 | R-E 对同一录音生成两种音质，并测试真实双路编码 | 各自 CER、漏判后的文字恢复、两路合计大小、缓存与编码开销 |
| X08 | R-F 注入识别失败、低质量音频、断连和存储压力 | 补传命中与漏触发、请求重试、原音保留条件；预览确认不触发原音清理 |

R-A、R-B、R-D 沿用相同采集设置和 ASR 配置。先用固定文件比较传输，再用连续编号的受控声源检查实时边界，随后测试腕部收音和目标 18 小时采集。不同阶段的结果分别报告。

延迟从音频或语音区间结束起算，报告 P50 / P95 / 最大值。未收到和未完成的区间单列，不能从延迟报告中静默排除。音频到达、转写调度等待和实际计算分别记录。对同一区间的多个文件表示，以区间并集计算覆盖，以真实字节数计算传输开销。

跨设备测量先估计时钟差并记录误差范围；未校准时，跨端延迟标为估算，另列单设备内可可靠测量的耗时。

## 9. 持久化、分析恢复与后台收尾故障用例

以下项目补足 R / T / S 系列中的关键故障点，全部为 **未执行**。固定文件故障注入先在 Mac / iPhone 测试工具执行，系统回调与设备行为再用真机复核。

| ID | 故障点 / 输入 | 必须核对的结果 |
| --- | --- | --- |
| F01 | 清单已落盘、音频尚未搬移时退出 | 不确认成功；留下可识别的未完成收件，重传后恢复 |
| F02 | 音频与清单落盘、数据库提交前退出 | 根据清单恢复原 ID 与帧范围，不创建另一个逻辑文件 |
| F03 | chunk / 任务 / receipt outbox 已提交、确认尚未发出时退出 | 重启补发；确认丢失后可查询，不重复建档案 |
| F04 | Watch 已持久记录确认、尚未清理副本时退出 | 重启幂等清理，不重新上传；能重复报告确认已应用 |
| F05 | ASR 或收件校验运行中删除 session，再让旧任务返回 | 代次与 attempt 检查拒绝旧写入，文字、音频与缓存不复活 |
| F06 | 跨文件一句话右侧先到，左侧迟到 / 损坏 | 等待完整连续输入；不填零，不把缺失当静音；补齐后覆盖和文字无重复 |
| F07 | 预览或优先语音已确认，完整文件未送达 | 完整原音仍在 Watch；完整输入拥有独立任务与确认身份 |
| F08 | 接收库重建后到达旧确认、旧结果与已删除对象 | 拒绝旧库确认；拒绝旧 attempt；有效删除状态不被迟到内容覆盖；新库先完成重新配对与可用删除记录恢复 |
| F09 | 原生 ASR 尚未返回时用户取消 / 系统到期 | 停止领取、attempt 失效、句柄仍有效；记录实际计算停止时间，迟到结果不提交 |
| F10 | 一句跨物理文件、短于分析帧的尾音、连续讲话超过上限、连续重复短句 | 物理文件不重置 VAD；结束尾部被处理；真实重复说话保留；切词损失有单独记录 |
| F11 | 正好在登记窗口前后、保存锚点前后终止，再重放 | 与不中断的同配置结果比较：范围、窗口 ID、结果条数一致；没有未闭合段被跳过 |
| F12 | 长时间无静音，后台多次到期；以及恢复前模型包改变 | 流式重放不加载整日 PCM；有效结果不重复；模型不兼容时不复用旧锚点，重播成本和推进情况可测 |
| F13 | Watch 连接刷新任务在各种会话状态下完成；双端重启 | 每个后台任务恰好完成一次，无遗留等待；从主屏启动复测，调试器成绩不代替 |
| F14 | 本批次处理期间不断收到新录音；冻结时尾段仍有人声；随后取消再切前后台 | 批次只包含已准备好的闭合窗口；尾段留下一批；分母不增长；任何入口不能绕过暂停，用户继续后再领取 |
| F15 | ReceiptApplied 丢失、Watch 重启并清理副本后再次对账 | 控制记录仍在并可补发；未收到时手机不自动过期清理；Watch 不需要等它送达才清理 |
| F16 | 删除正在采集的 session，旧写入和系统传输随后完成 | 先持久删除，停止旧采集与写入，再发送 DeleteApplied；迟到文件被拒收；新 session 不受旧回调影响 |
| F17 | ASR 已完成，但文件仍位于 VAD 恢复重放范围，触发过期清理 | replay floor 阻止自动清理，重启后仍可重建分析状态 |
| F18 | 原音已正常过期后收到旧文件重传；另删除一份应仍存在的文件 | 过期文件不自动复活且不返回新的持久原音确认；意外缺失单独报损坏 |

删除记录丢失后，新库无法凭空知道旧用户删除意图。恢复测试应保留并核对可用删除记录；彻底无备份重建时进入重新配对与恢复流程，不能默认接纳旧队列并声称保留全部历史删除语义。
