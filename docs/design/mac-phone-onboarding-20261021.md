# Mac 与手机：首次连接和日常使用

2026-10-21 用户纠正后的实施契约。本轮在独立 Hermes 分支开发。

## 主线

新用户打开的是同一套 MoMo 欢迎体验，不先进入设置或设备管理后台。

- Mac：既有三段欢迎体验 → 准备此 Mac → 配置并验证模型 → App 内登录 Tailscale 与 HTTPS 检查，或填写自建服务器的固定 HTTPS 地址 → 展示二维码 → 已准备好 → 聊天。可以明确选择先在 Mac 使用，之后从设置补配手机。
- 手机：既有三段欢迎体验 → App 内登录同一个 Tailscale 网络（自建服务器可直接扫码）→ 扫描 Mac → 核对数字 / 等待 Mac 允许 → 验证 Agent 与同步能力 → 已连接 → 聊天。首次连接前不出现正式 Tab；可明确选择先看转录，之后从聊天继续未完成的连接。
- 复用同一个连接流程处理首次配对与后续重连。设置中的 Mac/设备管理只显示现状、重连、撤销和高级入口，不承担首次使用教学。
- 进入主界面后，Mac 默认打开聊天；录音原文与整理记忆保持独立，连接从设置管理。关闭 Mac 窗口继续后台运行；显式退出才停止自有进程。

## 状态和跳转

| 状态 | 来源 / 操作 | 成功 | 失败 / 中断 |
| --- | --- | --- | --- |
| welcome | 既有演示，可跳过 | 进入配置流程 | 不写入示例资料或任务 |
| preparing | 下载/准备本仓库固定运行组件 | 进入模型配置 | 原地错误、可重试，不自动继续 |
| model | 地址、模型、密钥；验证真实模型接口并启动 | Agent 真正在线后继续 | 保留非敏感输入，错误原地展示 |
| pairing | 配置固定入口并检查 → QR → 手机请求 → Mac 核对数字允许 | 手机凭据通过能力验证 | 扫码失败、过期、拒绝各有明确恢复操作 |
| ready | 可达、授权、Agent 与资料身份核对完成 | 用户点击进入聊天 | 不把仅有 URL 或扫码成功当成已连接 |
| connected | 聊天、转录、记忆 | 复用任务和资料身份 | 断线保留当前界面、草稿、run ID，不退回 onboarding |
| reconnect | 设置中的管理动作 | 同一 Mac 更新入口 | 不覆盖不同 Mac 的历史与身份 |

配对请求/手机生成的秘密先持久化，App 被终止后仍可核对同一请求；二维码不是授权凭据。更换入口不创建新任务、不清空记忆。1.28.1 移除临时通道，只保留 Tailscale 与自建服务器；[升级与连接边界](../implementation/stable-remote-access-20261023.md)。

1.29.0 双端内嵌 TailscaleKit：不要求独立客户端或 Serve 命令。登录状态以 SDK 的 Running 为准；Mac 必须经私网 HTTPS 读取本机身份成功才显示二维码。首次可能需要在官方管理页面开启 HTTPS。网页登录完成不代表可达，二维码也不代表授权。详见[内嵌网络实现](../implementation/embedded-tailscale-20261023.md)。

## 设计来源与真实复用

以远端 main `f0a251e7` 的实际 SwiftUI 页面为最新基线；HANDOFF、v8 Pen、LANDING 的 L01–L11 是设计来源，落后处以代码为准。

- 从原手机实现恢复欢迎叙事，移除其中旧 Pi 引用；两端使用同一个 WelcomeExperienceView。
- 将品牌图标、Pebble 字标、MoMo 程序化角色、字体、画布、输入框表面和消息渲染提升到 Apps/ClientUI，两个 target 编译同一份源码。
- 两端引用同一份颜色与图形资产、同一份 Avatar HTML/JS、同一份聊天 DOM/CSS 与事件到消息的映射。仅 WKWebView 的平台宿主和剪贴板使用条件编译。
- Mac 使用桌面宽度和键盘交互；不放大整张手机页面，不另画通用聊天气泡或另一组加载点。
- 录音详情显示完整原文与分页范围；记忆显示 Hermes 原生内容与删除操作，保留文本内已有来源。事实、同步状态和执行状态不混用；不为原生 Markdown 伪造结构化证据或日期。
- 欢迎页同步最新 main 的三段自动故事：单个 MoMo 连续移动、细进度线、前后台暂停恢复；移除旧分页圆点和重播，保留跳过与七次点击版本号预览。聊天 MoMo 尺寸同步为无会话 144pt / 有会话 84pt，名字 16pt / 12pt。
- 转录按用户最新要求直接适配手机：共用 ClientTranscriptRow、ClientRecordingStatusCard、WatchSignalArtwork；72pt 黑色卡固定于日期栏上方，列表保留圆点、连线、时间、摘要。桌面宽度足够时并排展示原文，窄窗口保留返回；不重新发明另一套卡片。Mac 没有实时手表状态和原音数据，因此明确显示同步信息，不伪造录音状态、波形或播放按钮。
- 记忆直接编译 Hermes Desktop 原始 StarMap 组件：时间圈、菱形记忆节点、缩放平移、悬停。按用户后续简化决定，数据直接来自 Hermes MEMORY.md / USER.md，右键查看内容和删除；没有日期就不编造时间，没有结构化证据就不显示假的证据按钮。列表是可访问性与加载失败时的真实后备界面，不增加第二套记忆权威。
- Pen 新增桌面转录、Hermes 记忆、main 手机转录基线与原生运行截图；侧栏 Chat / Transcripts / Memory / Settings 均有图标。结构稿英文，实际界面中文；展示数据均为合成样例。

比较过首次弹窗、设置配置、独立 onboarding 三种结构；采用独立 onboarding，原因是首个可用对话依赖 Mac 准备与授权，必须在进入工作区前连贯完成。

标准视觉强度；默认字号检查，不增加大字号测试。无障碍使用语义按钮、键盘焦点、单一错误提示；减少动态效果时保留信息顺序并取消空间移动。动态角色和三点动画在后台暂停。

## 验证门槛

编译不替代体验验证：检查首次打开、返回、重启续配、拒绝/过期重试、连接完成进入聊天、已有连接断网不重走欢迎、设置中重新配对。与临时公网主线测试分别记录。

本轮已验证：Mac Debug；手机 Release 与内嵌 Watch 静态审计（1.20.0 / 94）；20 项 Swift 客户端、18 项 Python、1 项 StarMap 数据适配测试；手机模拟器首次流程与重启续接、二维码图片识别 → Mac 核对允许 → 能力验证 → 进入聊天 → 重启不重走引导。扫码测试须使用正常签名的模拟器构建，禁用签名会导致 Keychain 写入失败。

原生 Mac 检查：时间线选择 → 完整原文；Hermes 节点右键 → 证据 → 对应原文。公网临时入口验证包含 SSE 首段先于结束、断开客户端后 Mac 继续、重复请求不重复执行、授权与撤销。模型为合成测试模型；没有使用真实手机或 Watch，不等同于蜂窝异地与真实模型质量验证。

最终 main 核对为 f0a251e7（1.19.2 自动故事）。共享欢迎页同步后，自动播放结束 → 首次连接 → 重启续接 → 暂缓进入转录 → 聊天继续连接的模拟器 UI 测试再次通过（67.96 秒）。
