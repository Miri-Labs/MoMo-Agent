## 真机证据

1.18.2 的进程从 13:12:14 开始运行。第一轮分析耗时 **249.81 秒**，其中 VAD 重读了 **792,547,840 个 16 kHz 采样帧，即约 13 小时 46 分钟的历史音频**。本次新输入仅 701,536 帧，约 43.85 秒。原有实现为恢复检测器状态，从同一连续录音范围的起点重读到检查点。

之后完成了 16 个识别窗口，累计 ASR 原生调用约 7.54 秒。13:16:45 的状态为 `failed`，错误码 `speech_processing_failed`。最后一次分析输入为 72,544 帧，约 4.53 秒；该操作约 30 微秒即失败，尚未读取音频。旧诊断没有保留具体的 SpeechError 分支，不能仅凭这一条确定是哪一处抛错。

系统 CPU 报告记录 13:12:37 至 13:14:19 平均约 88% 的单核 CPU 用量，`Action taken: none`。这是耗时和资源使用的证据，没有证据表明系统在这次报告中杀死了 App。

## 本地复现与修复

复现了与短范围恢复相关的确定错误：检测器已经读到第 16,384 帧，下一次处理范围只到第 16,200 帧。旧的缓存预判使用物理文件末尾判断可复用，实际分析使用处理范围末尾判断，两个结果不同。未准备恢复音频时，实际分析抛出 `incompatibleCheckpoint`。预判与执行还分属不同队列，缓存也可能在其间改变。

现在由归档层先保护恢复所需的音频文件，再由分析队列决定是否复用检测器。移除跨队列的缓存预判及对应快照。缓存适用时保持原有复用，缓存不适用时使用已经保护的原音恢复，不因临时缺少前缀而停止队列。

对手表的原生 16 kHz 录音，恢复输入限定为检查点前约 60 秒，并按 512 帧向前对齐。该热身长度沿用现有长录音原生时钟回绕的尺度。44.1/48 kHz 等需要重采样的输入继续从原连续范围起点读取，保持转换器相位。待处理范围、检查点、已提交转录和原始音频均保持不变；此次修改不重算已有转录。

有限热身不是对旧检测器隐藏状态的逐位恢复。真实模型测试核对了样本中的语音范围、完整覆盖、中文正文和恢复行为；不能据此保证任意音频的 VAD 边界逐帧相同。

诊断增加固定错误码，后续可以区分检查点、窗口、模型及音频问题，不保存原文、文件路径或原生错误载荷。
