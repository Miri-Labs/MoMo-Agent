# 后台进展覆盖与转录入口

在聊天持续后台授权的基础上补齐两条实际调用链。

## 用户发起的转录

转录页在尚有待处理音频时提供“后台继续整理”，沿用现有样式和最小 44pt 命中区域。只有用户点击会调用持续后台申请；自动收件、页面恢复和记忆整理继续使用各自的后台机制。

协调器复用当前前台批次，或取回已准备的批次；没有批次时冻结当前已注册且未领取的待识别窗口。交接先持久停止旧执行，不等待 native ASR 返回。停止屏障完成后，`PhoneBackgroundTasks.requestBatch` 为该批次申请持续后台任务，按冻结音频总时长和已处理时长向系统上报。未准备完成的原音及后续新片段仍交给自动整理，不扩充本轮已冻结的分母。

申请、等待交付和执行期间防止前台恢复逻辑抢走同一批次。系统拒绝申请时，保留批次并恢复普通前台处理。交付时系统条件改变而拒绝启动，也会清除本轮申请状态，避免按钮永久停在已申请。旧回调不能清除新批次。

## 工具运行中的实际进展

所有聊天工具类别通过 PiDurableKit 的 `ToolCallContext.details` 写入 `momoProgress`。只记录已到达的执行节点，不包含用户正文、工具输入、原音或系统事项字段，也不进入模型输出。读取、查询和显式记忆操作在校验、数据读取与提交后上报；系统写入另上报意图持久化、系统调用返回、结果核验和回执保存。

`AgentTranscriptProjection` 将结构化进展带到 `AgentToolExecution`。已有 SDK 工具运行状态同时计入真实启动事件。后台计数按每个工具调用保存最高已观测值，避免实时槽位转成持久结果、重放快照或某工具暂时消失后，丢失已记录的进展或阻止后续工具推进。合并最新 main 的邮件能力后，邮件状态、查询、读取、草稿和发送工具也接入实际执行节点；授权、回执去重和发送策略沿用邮件模块。

进展写入失败只记录固定日志，不改变实际执行或写入回执；操作错误仍按原有路径处理。带有 `momoProgress` 却违反数值类型的载荷会被拒绝，不猜测进度。总工作量未知时仍使用不定总量系统进度，等待网络时不会伪造心跳。

## 验证与范围

本地小型 Swift 包链接当前生产源码，55 项 XCTest 与 65 项 Swift Testing 通过，覆盖聊天、工具投影、系统操作、邮件权限与持久化。受控系统平台验证写入、核验与回执节点顺序，以及相同逻辑请求不重复写入。另有 9 项调度申请状态测试通过，覆盖重复交付、取消、拒绝和旧回调；这些测试不模拟 iOS 实际调度。邮件相关用例使用受控 HTTP 响应，不发送真实邮件。

代码提交 `9ff5ef0` 的[原生 CI](https://github.com/xilanhua12138/MoMoAgent/actions/runs/39200271328) 全部通过，包含最新 main 的邮件能力和心率字段。使用官方中文音频和真实引擎的 7 项流水线回归包含本轮交接用例：native 调用未返回时持久停止旧执行，交接同一批次，并在后台执行路径完成冻结范围。手机与内嵌手表的 Release 模拟器构建、版本及后台声明产物检查通过；该构建验证包含新增 UI 和平台后台代码。

系统实际接受持续后台申请、不定总量进度是否被视为持续推进、实际获准时长，仍需安装后真机验证。本轮不操作手机或手表。
