# Watch 录音空间预检与诊断

2026-10-14：已实现启动和分片轮换前的空间预检。`package-tests-13.log` 中 Recording 的 34 个用例通过，包括下列 6 个容量用例。验证在 Mac 上完成，Watch 真机尚未验收。

## 读取与预算

`CaptureCapacityReader.live` 使用 `FileManager.attributesOfFileSystem(forPath:)` 的 `.systemFreeSize`，读取录音目录所在卷的当前可用字节。读取失败或返回负值时拒绝采集，不能把未知容量当成足够。WatchRuntime 在激活麦克风前检查；编码器在实际创建首片和后续 AAC 容器前再次检查。

预算由 `RecordingStore.captureCapacityBudget` 按当前 SQLite `page_size`、`page_count` 计算，不遍历历史文件或日志。

| 分项 | 计算口径 |
| --- | --- |
| 下一片音频 | 目标帧数 × 单声道 Float32 的 4 字节。默认 60 秒、16 kHz，为 3,840,000 字节 |
| 尾段封口与落盘副本 | 再计一份同等音频空间，覆盖封口、复制与原文件同时存在的阶段 |
| 元数据与账本 | 清单大小上限的 2 倍 × 6 份，覆盖草稿、封口侧车文件、manifest/envelope 和原子替换临时文件；另计 SQLite 页面增长与 9 次写事务的保守 WAL 余量 |

SQLite 估算为每个已有页面预留一次页面分裂，再加新增元数据所需页面；每份 WAL 按 32 字节文件头、每页 24 字节帧头计算。9 次事务覆盖 intent、epoch、启动诊断、文件归属、分片账本、容量停止、epoch 结束、收件确认及确认后清理。这是允许继续录音的保守策略，不是 SQLite 每次写入的预测值，也不以实测 AAC 码率作为容量上限。

总预算是三项之和。检查不会预留磁盘块，其他进程仍可能在检查后消耗空间；后续写入错误继续走封口与恢复流程，不能靠预检保证写入必定成功。

## 停止与保留

空间不足时，编码器拒绝创建下一片。若同一次输入已经封好上一片，仍先将它写入收件账本并保留 hash。已获准创建的短尾段可以正常封口。未获接收方确认的原音不会因低空间而删除；草稿和不能确认完整的尾段仍按既有恢复规则保留。

Watch 停止采集、清零输入音量并显示结构化原因。容量不足和容量未知都将 intent 与诊断放在同一事务中写入：intent 变为 `paused`，已由用户设为 `stopped` 时保持不变。重启或系统中断结束不会自动续录，需要用户明确重试。若停止记录本身写入失败，界面报告失败，收尾仍继续，不声称账本已成功保存。

## 有界诊断与迁移

账本 schema 从 3 升到 4，新增 `capture_diagnostics`，不重写已有原音、分片或确认记录。旧版本逐级迁移，未知的新版本拒绝打开。

诊断只保留最近插入的 64 条，按事件 ID 去重。字段包括事件码、毫秒精度时间、会话/epoch ID、已观察帧数、输入采样率、最后采样 uptime，以及可选的容量快照与预算。事件覆盖启动、暂停、停止、空间不足、容量未知、系统中断、路由变化、媒体服务重置、输入溢出、不连续、停滞及启动/写入失败。

诊断不保存原音、转录正文、麦克风名称、文件路径或原始错误描述。容量快照只保存在 Watch 本机，不发送到手机或云端。Watch 隐私清单为该空间预检声明 `E174.1` 用途。

## 已通过的软件验证

测试位于 [CaptureCapacityTests.swift](../../Packages/MoMoAgentKit/Tests/MoMoRecordingTests/CaptureCapacityTests.swift)，使用真实文件、SQLite、AAC 编码与重开后的 hash 校验。

| 用例 | 验证边界 |
| --- | --- |
| 预算边界与未知容量 | 恰好达到预算允许；少 1 字节、读取失败、负值拒绝；不创建采集 intent 或分片 |
| 真实卷读取 | 直接读取本机卷容量，不填满磁盘，不创建磁盘压力 |
| 首片拒绝 | 注入 0 字节可用空间，不留下音频、草稿或分片账本 |
| 轮换拒绝 | 注入首片空间充足、第二片不足；同一输入块已封好的 16,000 帧仍落盘，重启后 hash 不变，未确认清理不能删掉它，intent 不自动恢复 |
| 短尾封口 | 8,000 帧尾段只执行首次准入，不因无需创建下一片而重复拒绝封口 |
| 诊断上限与迁移 | 旧 schema 迁移保留未确认原音；69 条事件仅保留最近 64 条，毫秒时间与字段持久一致，不含测试原音路径 |

低空间用例是明确的容量读取故障注入，不代表真实 Watch 满盘、锁屏或长时间录音已经通过。仍需在 Watch SE2 验证真实卷读取、连续采集期间的预算开销、低空间停止提示、后台封口与重启恢复；不通过填满用户现有磁盘来验收。
