# 音频收件的原子交接

## 问题与处理

旧版 `InboxCustodian` 先创建 UUID 目录，再写入 `manifest.json`、`manifest.sha256` 和原音。并发的收件扫描只检查目录名，因此可能在文件尚未写好时开始读取。进程中断也会留下缺少校验文件的目录，后续重试持续报告文件不存在。

接收回调现在先写入 `<UUID>.receiving`。清单、校验值与原音同步到磁盘后，在同一父目录内改名为 UUID 目录，供处理队列读取。回调返回前完成原音接管。写入和启动恢复共用同步锁，扫描不持有该锁；锁内没有数据库事务或异步等待。

启动恢复按实际文件区分：

- 暂存目录三项文件齐全：发布到处理队列，继续正常校验与提交。
- 暂存目录不全，或旧 UUID 目录缺少清单、校验文件：改名为 `.incomplete` 并保留原有字节，退出重复处理。后续完整重传按原有校验流程提交。
- UUID 目录的清单完整、原音不在收件目录：继续处理。原音可能已经移动到正式目录，不能据此隔离有效的崩溃恢复记录。

半成品不产生接收确认，也不自行补造哈希。手表仍须收到匹配的持久化确认后才能清理原音。已能校验所属会话的半成品随用户删除该会话而清理；缺少校验依据的旧条目继续保留。

分块补传或其他处理调用可能先消费队列快照中的条目。`commitReceivedChunk` 对已经不存在的条目返回 `noLongerPending`；手机跳过该条目，不误报接收失败、不触发资料库刷新，也不生成新确认。其他文件、校验和提交错误仍保留原有错误处理。

## 验证

- 新增回归覆盖写入期间扫描、旧版两种清单文件缺失、原音接管失败、完整暂存恢复、删除关联半成品和过期队列快照。
- 真实生产源码的 macOS 回归：MoMoArchive 202 项、MoMoLink 66 项、MoMoRecording 74 项通过，共 342 项。使用任务目录中的精简 Swift 包，连接真实文件系统与 SQLite，不加载无关语音模型依赖。
- `CrashRecoveryReplay` 的 J08-b、J08-c、J08-d 通过。父进程在实际持久化边界强杀子进程，再用新进程恢复，核对原音哈希、双方记录、任务和确认数量。
- iPhone 接收模块与实际 MoMoArchive、MoMoLink 依赖通过 arm64 iOS SDK 编译；该检查不包含签名安装或设备运行。
- 日志与回放证据位于本任务 worktree 的 `tmp_agent_output/inbox-atomic-checks/`、`tmp_agent_output/inbox-crash-replay/`。iPhone 接收模块编译日志位于 `tmp_agent_output/inbox-ios-checks/build.log`。

本次未安装手机或手表。实际 WatchConnectivity 投递与手机存量目录迁移仍需安装后验证。
