# 转录切换日期的重复计算修复

用户反馈查看转录、切换日期时，App 偶发失去响应。本次检查确认了重复计算和重复读取路径；尚未取得用户那次卡住时的真机线程栈，不能据此判定为死锁。

## 已确认的问题

- 每天的滚动位置保存在整个 `LibraryView` 的状态字典中。滚动更新会使上层视图重新求值，日期页在求值时又执行列表筛选和时间重叠比较。
- 时间重叠检查逐对比较当天所有记录。即使所有记录处于同一时区，也会执行平方数量级的比较。
- 每个已挂载的日期页监听 `snapshotRevision`。资料库刷新会同时触发当前页和屏幕外日期的读取；下拉刷新还会额外读取一次。
- 读取任务被多个调用者共享，但旧页面取消时没有释放自身请求。快速切走再返回同一天，还可能被 `loading` 判断直接跳过。
- 界面回归还发现首次进入标签页时，日期栏选中了今天，但今天的内容仍在屏幕右侧。启动日志中选中日期正确、横向偏移始终为零：初始定位发生在分页布局就绪之前。

## 改动

- 将单日列表拆成独立视图。每个日期持有自己的滚动状态，离屏后仍保留阅读位置。
- 仅选中日期触发加载。筛选、时间排序和时区重叠计算在后台读取任务中完成，视图直接使用结果。
- 同一时区直接跳过重叠检查；跨时区使用排序和两次扫描，将复杂度降到 `O(n log n)`。
- 使用资料库内容修订标识跳过未变化的重复刷新。新分片、转录修改、删除、标记和处理状态变化仍会使缓存失效。自动总结的请求入口保留。
- 共享读取按调用者登记。最后一个调用者取消时才取消底层任务；详情页仍需要的读取继续执行。资料库查询入口和分片处理循环检查取消状态。
- 读取完成后，只有内容变化才更新列表、预备回听。首次进入仍定位到最新记录，用户手动滚动后保持阅读位置。
- 日历跨多天跳转不再沿途播放分页动画。
- 日期范围变化后重新定位到选中日期；日期列表获得实际宽度后再次校准。宽度观察不随每帧滚动触发。首次纵向定位使用内容底部，包含列表的底部留白。
- 尚未读取的日期显示加载状态，读取完成且确实没有内容时才显示空状态。

SQLite 正在执行的单条查询仍需返回后才能检查取消。

## 验证

- `xcodebuild build-for-testing` 通过。
- iPhone 18 Pro / iOS 27 模拟器：`TimelineDateNavigationTests` 12 项通过，`TimelineReadingIntegrationTests` 7 项通过。另有 1 项显示帧间隔测试要求专用性能环境和 `MOMO_RUN_TIMELINE_PERFORMANCE=1`，本轮未启用，按原测试条件跳过。
- 新增用例覆盖：取消后立即返回同一天；取消列表读取后详情页继续共用请求；8 次未变化刷新不重建日期、新片段到达后重建；混合时区重叠与逐对比较结果一致；12,000 条同一时区记录快速返回。
- 异步读取和预先缓存两种情况下，首次打开今天的记录均定位到底部；测试数据同时包含昨天，覆盖历史日期插入带来的分页变化。
- `PhoneTimelineJourneyTests` 4 项界面回归通过：首次打开与刷新、切换标签后保留位置、今天与昨天往返、日历选择、左右手势切换。最终合计 23 项通过、1 项按原条件跳过、0 项失败。
- 使用 `verify-release-bundle.py` 的版本配置校验，确认构建出的模拟器手机包和内嵌手表包均为 `1.17.8`，内部构建号均为 `86`。这不是完整 Release 包审计。

初次测试执行器在启动阶段返回 `Invalid connectionUUID specified`。关闭本轮模拟器并重新启动后，分开运行集成测试和界面测试；初次运行不计为通过。构建和测试证据保存在本 worktree 的 `tmp_agent_output/date-freeze/`。

最终通过的结果包为 `integration-complete.xcresult`、`pager-layout.xcresult` 和 `ui-navigation-complete.xcresult`。早期失败运行用于定位分页错位，未计入最终通过结果。

本次没有安装真机。用户现场的卡住问题仍需用新版本实测；当前证据证明上述重复工作已被移除，相关回归通过的范围如上。
