# VAD 召回与计算量复核

日期：2026-10-22。复核代码：`d80ff464`。本轮只做隔离副本实验和方案复核，没有改动手机资料库，也没有安装应用。

后续代码已加入[选择性语音复核](selective-speech-review-20261022.md)。下文保留此次复核时的行为与结论，现行策略和新对照结果以该实施记录为准。

用户指出：使用 VAD 的目的包括跳过无语音音频，不能用全量 ASR 掩盖 VAD 漏检。这个判断成立。上一版增加了识别覆盖，但没有同时解决语音召回与计算效率，不能作为这两个要求都已完成的证明。

## 当前代码的实际行为

`PhoneComposition` 开启 `verifyVADRejections`。`CompleteCoverageWindows` 会给 VAD 检出范围和剩余间隙都生成 ASR 窗口。识别前只跳过精确为零的数字静音，持续的环境噪声仍进入 ASR。因此 VAD 在这条路径中主要负责切句，已经失去了跳过大部分非语音的作用。

上一轮一小时用例的静音是人工填零，不能代表佩戴手表时的环境声。原有文档已说明这个限制，但这类测试不足以验收新的计算策略。

本轮尚未修改生产策略。只把 `verifyVADRejections` 关掉也不构成完整修复：它同时控制上下文拼接、完成历史的继承和分析窗口身份。尤其不能因切换指纹而重新识别用户已经完成的历史录音。

## 隔离实验

继续使用已有的 11 段一分钟副本，共 660 秒；不从手机重新导入或重跑历史。这批数据是定位样本，不代表全天分布，也没有人工逐词标注。

推理用 sherpa-onnx 1.13.8。Silero v6.2.3 原权重不变，单线程 CPU。表中时长是 VAD 选中的原音范围，尚未加入 ASR 上下文，不能换算成等比例的耗电或处理速度。

| 方法 | 选中音频时长 | 观察 |
| --- | ---: | --- |
| Silero v6，阈值 0.25，起声 250 毫秒 | 180.34 秒 | 两段此前 ASR 能输出正文的样本仍零检出 |
| Silero v6，阈值 0.10，起声 64 毫秒 | 212.13 秒 | 这两段仍零检出 |
| Silero v6，阈值 0.05，起声 64 毫秒 | 219.98 秒 | 两段中一段仍零检出，另一段只检出约 0.41 秒 |
| sherpa TEN-VAD，阈值 0.50，起声 100 毫秒 | 108.64 秒 | 未稳定补回上述候选语音 |
| sherpa TEN-VAD，阈值 0.25，起声 100 毫秒 | 549.05 秒 | 大量噪声对照也被选入，不能作为省计算的替代方案 |

全量间隙核验覆盖 660 秒，而当前阈值的 v6 只选中 180.34 秒，前者覆盖的音频约为后者的 3.66 倍。这说明新增 ASR 工作量很大，不说明 v6 跳过的其余范围全部没有语音。

检查还发现：

- sherpa 的 `min_speech_duration` 要求起声前连续若干帧超过阈值。Silero 官方离线切段先触发，再按段长过滤。两个参数同名，但行为不同。缩短起声要求可以减少一部分短促、断续语音的排除；本组实验说明它不能解释全部问题。
- v6 的 16 kHz 输入、64 点上下文、循环状态及逐帧接口与既有验证一致。C API 未暴露的负阈值采用 C++ 配置默认值，未发现此前猜测的“零初始化导致负阈值错误”。
- 增益、高通滤波、8 kHz 模型分支和传统频谱降噪均未稳定补齐这两段候选语音。本轮不据此新增产品参数。
- sherpa 已有 GTCRN 降噪后再运行 v6，确实能在两段中得到更多候选区间，但降噪处理 660 秒音频耗时约 19.23 秒，且会增加一些噪声候选。这个额外成本不能忽略，也没有证明识别准确率提高，因此未接入产品。
- sherpa 的 TEN-VAD 实现将 pitch 特征置零，官方提示可能影响效果；本实验不能代表 TEN 原实现的全部能力。

“ASR 出字”与“正确识别真实语音”必须分开。尤其是低信噪比样本，不能用输出字数充当召回率，也不能把模型没有输出文字直接标成确定静音。

## 修正后的实施要求

后续实现仍应让 VAD 承担过滤工作。明确的非语音不进入 ASR；检测到的语音连同必要的边缘上下文进入批量识别。复核只能针对经过验证的不确定范围，不能把全部 VAD 拒绝范围都视为不确定。

不确定范围的判定目前尚未验证。此次低分样本说明，简单增加一个较低阈值不能可靠区分弱语音与噪声。不能先写成三档状态机，再宣称已经解决分类问题。

切换新策略时，应保留已经验证的连续 VAD 状态、最长 20 秒核心、跨文件和处理批次的上下文、取消恢复与持久检查点。历史继承必须覆盖旧 v4 指纹和上一版全量核验指纹，避免模型或策略更新触发历史重算。

验收需要同时检查：

1. 有原文或人工标注的语音，包含轻声、远场、背景噪声、短句、连续长句和文件边界。检查语句是否完整及文字是否正确。
2. 真实环境声中的 ASR 输入时长、调用次数和重复识别时长；不能只测人工补零。
3. 同一台 iPhone 上每小时录音的总处理时间、峰值内存、发热与耗电，继续以五分钟内处理一小时为目标。

当前结论是：全量核验方案不满足效率要求；本轮参数和备选处理实验尚不足以交付一个同时通过召回与效率验收的替代策略。没有将任何实验组合合并成生产修复，也不把本次复核称作“漏检已解决”。
