# 生活事件上下文实现与代码验证

初始基线：`8b811cc`。合并时同时保留远端 `55dcf0a` 的总结与附件实现。范围按本轮确认：到访地点 → 日历安排 → 录音实况，暂不加入待办、文件或照片。

## 已接入

- `LifeTimelineController` 汇集三种来源，按发生时间排列。事件保留独立来源、原时区或报告时区、读取/收到时间。日历始终标为计划；地点和录音不会自动合并为出席或人物身份结论。
- 新增只读 `query_life_timeline`，支持最多 7 天的时间区间、来源筛选、正反序、游标分页。限制条数和实际编码字节数，后续页从最后一条继续。权限或筛选改变后旧游标失效。
- 每轮默认提供过去 6 小时及未来 18 小时的概况。地点最多 4 条、日历最多 6 条、录音最多 8 条；显式选中的原文仍优先提供。日历上下文和地点均默认关闭，用户在「系统与健康 → 生活信息」独立开启。
- 录音查询使用采样时间映射，支持持续多日的同一录制会话。现有引用校验仍负责修订、删除及资料失效。
- 手机使用 Core Location Visits，到访报告先原子保存，再串行解析大致地址；地址请求只保留一个待处理报告。没有持续 GPS、位置轮询或依赖录音任务的等待。
- 到达和离开报告合并为同一次到访；保留未知边界、精度和延迟报告时间。不将未知离开解释为仍在原地。最多保留 10,000 条到访，并返回实际保留范围。
- 首次初始化即可按已保存的开关恢复监测，兼容没有 SwiftUI 场景的系统唤醒。权限提示只从用户设置操作发起。后台权限需用户另行选择「始终允许」。
- 可停用及单独清空地点。清空、断开和权限撤销会阻止旧资料进入后续模型输入；保留本地历史展示，并保留隐私边界之后的新对话连续性。处理中失去访问权则取消该轮，避免发送旧快照。
- 地点记录或上下文偏好损坏会单独呈现失败，保留原文件并关闭相关来源；不阻止录音库和 Agent 启动。定位、日历读取失败也分别报告。

- 其中 Agent 集成测试运行实际 Pi harness 和工具调度，使用本地确定性模型及系统来源夹具，确认自动上下文、查询工具、撤销后的历史隔离，以及后续多轮连续性。这不代表外部模型回答质量或真实系统数据已验收。

与附件合并后，隐私边界只根据消息时间和文字生成标识，不重复散列图片数据。
