# 转录页手表状态小卡片

用户反馈原卡片占用了过多阅读空间，并要求保留有设计感的小卡片。每日卡片只作为留白、图形层次和信息轻重的参考，状态卡使用独立的配色与图形。

## 界面

- 常规状态使用 72 pt 高的横向小卡片。左侧放状态标题和上次报告时间，右侧放声波图形及详情箭头。红黄绿状态点继续表达真实状态。
- 按用户要求以黑色为主色，使用白色标题、灰色次要信息和细边缘。浅色和深色模式都保留黑卡。
- 右侧使用用户选定的五层倾斜环形图案，转为灰白像素风格。保留各层的大小与位置关系，以 2 pt 方格和四档灰度绘制，关闭边缘抗锯齿。图形是静态装饰，不代表采样振幅或同步进度。
- 首页每日卡片保持原样；状态卡没有复用它的点阵图形、紫绿配色或卡片代码。
- 点击卡片打开浮层，显示状态说明以及待确认片段数量和大小。
- 新鲜报告中的录音中断或失败保留一行恢复提示。过期报告显示“手表状态待更新”，历史状态在浮层里说明。
- 按 1.17.7 的用户反馈，卡片固定在日期栏上方；转录内容在下方独立滚动。长时间线仍默认定位到最新记录。
- 移除原来大块波形的持续动画；像素图形只生成一次，按四档灰度合并成四个绘制路径，不新增动画计时器。状态请求仍由页面统一持有，分页不会各自启动请求循环。
- 聊天页和转录页共用详情浮层；聊天页保留“查看录音与同步”入口。

## 1.17.7 固定卡片与阅读位置

用户要求卡片常驻，并报告滑到顶部后又回到底部。卡片移出每日滚动区域，保留 72 pt 高度、黑色像素图案和点击详情；每日列表恢复直接使用 `LazyVStack`。

旧位置绑定只保存 ID，并用底部锚点选择和恢复阅读目标，忽略空 ID 更新。现在按日期保存 SwiftUI 的完整 `ScrollPosition`，常规阅读按可见顶部追踪；首次载入才向最新一条发起底部定位。用户开始滚动后即结束首次定位资格，避免延迟载入抢回控制。归组替换 ID 时仍沿用已有映射。

API 依据：[Apple ScrollPosition](https://developer.apple.com/documentation/swiftui/scrollposition) 与 [scrollPosition(id:anchor:)](https://developer.apple.com/documentation/swiftui/view/scrollposition(id:anchor:))。绑定中的旧目标可能在内容或视口变化时触发位置恢复；目前未在手机上完整复现用户这次回弹的触发顺序，不能将该机制认定为唯一原因。

本地 macOS 原生 SwiftUI 检查覆盖首次到底部、滚轮上翻到顶部、连续四次刷新与追加以及重新挂载。固定卡片布局下，顶部偏移保持在 4 pt 内。该检查验证滚动 API 的行为，不替代 iPhone 整页手势验收。现有 iPhone UI 回归已同步检查卡片固定、上翻停留及下拉刷新后继续停留。
