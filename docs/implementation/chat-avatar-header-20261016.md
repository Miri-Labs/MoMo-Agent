**后续复核更正：** 用户指出头像消失。重新检查本轮的 `header-ui-attachments/832CDE22-5D05-44DC-ACEC-E611C994AC7F.png`，绿色状态页确实只画了手表小标，头像没有出现；原首页和键盘页画出了头像。旧像素断言只在部分场景使用，且包含小标重叠区域，未拦住这张缺失截图。因此下文通过记录只表示原断言通过，不能作为所有状态下头像可见的结论。修复与更强的验证见 [MoMo 修复记录](momo-header-visibility-20261016.md)。

用户提供 [IMG_8077.jpg 参考图](../design/iphone-review-20261015/avatar-header-reference.jpg)，要求将 Avatar 固定在聊天顶部，手表状态缩为右下角的小标，思考时使用 MoMoAgent 品牌图标动效。本轮从 `origin/main` 的 `c3937a1` 建立 `codex/chat-avatar-header`，保留主目录和其他 worktree 的改动。

## 实现

- 聊天首页与会话共用导航栏中央的 Avatar，移除首页中央重复角色和顶部手表长文案。输入框与会话状态的所有权保持原样。
- Avatar 右下角显示手表小标与状态点，保留独立点击区域、具体状态的读屏说明和完整录音状态入口。
- 绿色表示状态新鲜且采样正常、确认正在录音；黄色表示等待、未录音、静音、准备或过期；红色表示新鲜状态下的中断或失败。过期、恢复缓存和采样断续继续由既有新鲜度规则判断。
- 等待、思考和工具步骤共用原品牌图片节点，以轻微抬起、倾斜与缩放表示活动；保留文字 shimmer。正文开始且无工具运行时停止，后台和减少动态效果时静止。
- 图片与 `PhoneBrandIcon` 原始资产逐字节一致，不重画或修改颜色。消息网页只允许打包的本地图片，模型生成的图片与 HTML 仍经原有转义和清理。
- 首次体验保留原品牌图标和角色；本次位置变化不改变首次体验流程。

## 验证

证据放在本 worktree 的 `tmp_agent_output/20261016-avatar-header/`。仅使用一台专用 iPhone 17 Pro / iOS 27 模拟器，按系统默认字号检查。

- 17 项前端规则检查通过。
- 32 份固定渲染资源、24 份 Avatar 源码与品牌图片一致性检查通过。
- `native-final.xcresult` 的 18 项检查通过：17 项原生 WebKit 渲染及 1 项包含 12 种输入的手表状态检查，覆盖颜色、新鲜度、品牌动效、深色、减少动态效果与图片/脚本清理。
- `header-ui.xcresult` 的 2 项真实 UI 检查通过：首次点按弹出软件键盘、顶部角色实际像素，以及右下角绿色小标点击打开完整状态。首页、键盘弹出和手表录音状态的截图已人工复核。
- `built-resource-verification.json` 确认测试安装包中的五个消息渲染资源与本工作区源码一致。
- `journeys.xcresult` 的 5 项 UI 检查通过：停止/重新生成/503 重试/来源回听/重启，底部标签与草稿保留，失败横幅可关闭，静音状态，过期状态。流式期间和键盘打开后，顶部只保留一个 Avatar 且纵向位置不变。本轮两次 UI 运行合计 7 项，均为同一最终代码版本。
- `ledger-verification.json` 独立核对受控流式场景的 4 次请求，重新生成与重试的操作 ID、attempt、持久化完成状态，以及重启后无重发。
