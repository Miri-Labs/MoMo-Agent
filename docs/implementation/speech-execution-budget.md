# 本地转写的重放与取消计量

2026-10-14 在 Mac M4 上运行生产 SpeechEngine，固定 SenseVoiceSmall INT8、Silero 与默认 CPU 配置。新增诊断逐次记录音频校验、解码、重采样、前缀丢弃、原生推理和取消时间。计量回调不含音频、正文或文件路径，默认不落盘。

工具把公开中文样本的指定片段循环拼成 60 秒、180 秒压力输入，按 60 秒保存 WAV。它验证高语音负载下的执行成本，不属于自然对话质量集，也没有增加已报告的 60 分钟 CER 样本量。工具与字段说明见 [SpeechQuality 诊断入口](../../Tools/SpeechQuality/DIAGNOSTICS.md)。

最终报告为本机证据目录中的 `speech-diagnostics-02/summary.json`。这轮在本任务的编译、包测试和 UI 测试之间单独执行；第一轮与 Xcode 构建重叠，保留原始报告但不用它作为以下耗时基线。

表中帧数使用 16 kHz 模型采样率。

| 项目 | 60 秒输入 | 180 秒输入 |
| --- | ---: | ---: |
| 闭合 ASR 窗口 | 3 | 9 |
| 不重复的有效核心帧 | 955,808 | 2,875,808 |
| 实际转换帧（含前缀与预读） | 1,934,848 | 14,451,200 |
| 实际转换量 / 有效核心量 | 2.0243 倍 | 5.0251 倍 |
| 丢弃的前缀帧 | 968,384 | 11,553,536 |
| 热 VAD 准备耗时 | 0.151841 秒 | 0.427147 秒 |

两组分析锚点均为 0，从头重复准备得到相同窗口。输入时长增加 3 倍，重复前缀增长更多，确认当前单窗口接口会重复解码前缀。180 秒场景的 ASR 调用共耗时 3.117052 秒，其中 native decode 为 3.006913 秒，音频读取和转换为 0.032888 秒，音频哈希为 0.017528 秒。此次保留已有重采样输入和窗口身份，没有直接跳过前缀或加入跨 attempt 缓存。

另一次真实 20 秒核心窗口在 C 推理调用期间收到取消。该次 native decode 为 0.346165 秒；从首次取消到 C 返回为 0.333844 秒，到整次操作收尾为 0.333935 秒。结果被丢弃，随后同一执行者的新 attempt 可以完成识别。这是单次本机测量，不能用作 iPhone 最坏取消上限。

后续需要在 iPhone 17 Pro 测量热状态、内存、最慢取消时间和系统后台到期。若优化连续语音的重复读取，需要比较连续与恢复后的实际模型 PCM、窗口身份、帧范围和哈希，并覆盖取消、来源修订和文件损坏。后台系统入口仍未接入，当前 App 继续只在前台转写。
