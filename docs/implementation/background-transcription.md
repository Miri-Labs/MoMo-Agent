# 转写批次与后台任务

`1.2.0` 默认启用 CPU 后台处理。离开 App 后先保存前台进度，再提交允许使用电池运行的 `BGProcessingTask`，不要求接电。iOS 决定实际启动时间；这不保证锁屏后立即处理。低电量模式、serious 或 critical 热状态不接纳后台执行，运行中的系统任务遇到这些条件会建立持久停止屏障，并保留后续申请。真机锁屏、峰值内存与用电仍需测量。

## 执行归属

`PhoneRuntime` 持有唯一 `TranscriptionCoordinator`，所有入口复用同一个 `SpeechEngine`。协调器分别管理前台许可、用户暂停和一个受管理的执行。系统授予的后台执行不会因 scene 进入后台而被前台许可误取消。

资料页的“处理已准备好的音频”冻结当前已闭合窗口与已知无语音区间。进度分母随后固定，新收件进入后续处理。删除原音单列时长，不计作已转写。活动批次查询不受历史列表分页数量限制。

在用户点击继续时，协调器恢复该批次。后台提交失败会保留批次；再次点击可在前台运行。普通自动队列不能绕过暂停批次领取其窗口。

## 系统接口

| 入口 | 提交条件 | 结束行为 |
| --- | --- | --- |
| 前台 | App 活跃、用户未暂停 | 进入后台时使当前 attempt 失效，批次记为 interrupted |
| `BGProcessingTask` | 离开 App 或后台收件时申请；允许电池供电、无网络要求，低电量或明显发热时不执行 | 到期记为 backgroundExpired，资源限制中断记为 interrupted，允许再次申请 |
| `BGContinuedProcessingTask` | iOS 26 起、用户主动操作且资源条件允许；使用 fail 策略 | 到期记为 systemEndedUnknown，保留暂停，等待用户继续 |

`PhoneAppDelegate` 在 didFinishLaunching 内注册任务。UI 和后台冷启动共用 `PhoneBootstrap` 与同一个 Runtime，避免分别打开两套执行者。iOS 27 使用异步 submitTaskRequest，旧系统使用兼容入口；请求创建和提交都离开主线程。首版仅申请 CPU，不申请后台 GPU 权限。

`TranscriptionTaskGrant` 在异步恢复前安装到期处理。准备期间到期会立即结束平台 grant，准备函数随后返回也不能启动执行。进入短 admission 后才会创建执行记录；若此时到期，grant 记住原因，拿到 handle 后执行持久停止屏障。屏障完成后系统 completion 只调用一次。它不等待 C 原生识别结束；识别返回后由协调器丢弃迟到结果并释放音频租约。屏障失败也结束系统 grant，但报告明确失败，不记成成功。

系统完成回调可能先于 admission 返回，到期回调也可能与 App 内暂停并发。协调器与 grant 分别处理这两层顺序，不依靠回调的预期先后。

停止入口在第一次异步等待前捕获原执行的任务或领取请求。后续只使这份任务失效，不重新读取并停止当时的“当前任务”。多个停止调用等待同一个持久屏障，第一个原因决定结束状态。前后台和用户操作分别使用版本号，避免旧操作在状态经过一轮切换后覆盖新状态；新后台 grant 已进入时，旧前台停止也不能发布挂起状态。

批次进入执行也记录期间是否发生过暂停或前台许可中断。即使返回时用户已经恢复，旧批次仍需显式继续；它在任何后续异步读取前标为 stopping，不能被普通队列接管。scene 切换只中断前台批次，系统已授予的后台批次继续遵守自己的期限。

普通后台任务使用固定 identifier，因此提交按顺序执行。用户取消会使正在提交的请求代次失效；迟到提交成功后立即撤销，再处理用户恢复后的新请求，避免撤销旧请求时误取消新请求。

## 验证边界

协调器集成测试使用真实 SQLite、Silero VAD 与 SenseVoice，以及明确的同步门制造执行交错。grant 生命周期测试控制 admission、expiration 与 completion 事件，验证持久屏障和一次性收尾。这些测试不代表 iOS 系统实际调度已经通过。

设备验收要从正常入口启动 App 并脱离调试器。记录系统授予时间、最后成功持久化位置、停止回调时间、原生返回时间，以及用户取消和 App 被杀后恢复状态。当前只启用已有 CPU 系统入口；没有新增主动批处理按钮，也没有将自动启动冒充用户操作申请 continued processing。

## 有界流水线

语音检测和识别各使用一条 utility 串行队列。两者共享一次完整的模型哈希与运行时版本校验。VAD 复用实例，在每次分析入口重置内部流状态；纯静音不初始化 SenseVoice。识别仍只有一个实例和两个内部线程，VAD 使用一个线程。

普通自动队列识别当前页时，最多提前领取并分析下一页。预取只保留有界输入页的租约、窗口描述和范围，不预存整天 PCM，也不提前提交。协调器完成前一组识别后才提交预取结果。明确批次与指定范围重试沿用串行路径。低电量或明显发热时不再启动额外预取，已领取的一页按原生命周期收尾。

暂停、删除或系统到期同时取消两个阶段，并对已领取的两个 attempt 建立持久屏障。停止回调不等待原生推理，租约则保留到对应原生读取返回后再释放；迟到结果仍受 attempt 和 generation 校验约束。
