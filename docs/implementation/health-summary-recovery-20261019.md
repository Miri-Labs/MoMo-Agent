# 健康摘要读取恢复

基线为 `c5145ac`，修复版本为 1.10.9。本次只修改、验证和合并代码，不安装设备。

## 已确认的问题

1. 六类 HealthKit 查询串行执行，任意一类报错都会丢弃本轮已读到的其他结果。`HKErrorNoData` 也按整份摘要失败处理。
2. 旧版健康开关只保存用户的启用选择。新增心率和静息心率后，打开摘要没有检查是否需要补充授权。
3. 查询使用 continuation，但没有超时、取消和 `HKHealthStore.stop`。退出页面不能停止查询。
4. 页面丢弃具体错误，只显示“健康摘要暂时无法读取”。设备不支持或连接关闭时也缺少明确状态。
5. Agent 将首次读取失败缓存在整轮对话中，后续无法通过再次获取初始摘要恢复。

原用户报错没有保留 HealthKit 错误码，因此目前不能确认是哪一项触发。以上问题均由源码确认，不能据此倒推那次设备错误。

## 修复

- 六项查询并发，各项独立返回数据或问题，每份摘要最多六个查询。保留成功项目；缺少数据保持未知，不填零、不推断用户拒绝了权限。
- 单项查询最多 10 秒；成功、失败、超时和取消均停止底层查询，并只完成一次 continuation。迟到或重复回调不会覆盖结果。
- 明确处理 HealthKit 的无数据、尚未请求授权、锁屏保护、设备限制和设备不支持错误。未知错误保留项目、错误域和错误码。日志不包含健康数值、查询日期或原始错误描述。
- 在用户进入健康摘要页时检查需要补充的授权；后台和 Agent 读取不弹授权页。授权返回后再次检查启用代次，避免断开连接后重新启用或返回旧数据。
- 页面显示已读到的数据和未完成项目，提供重试。返回前台时刷新；页面请求使用标识校验，迟到结果不能覆盖新请求。
- 页面展示实际已读到的活动能量和训练统计，补齐此前只读取、不展示的内容。无数据时提示检查健康 App 的权限或同步状态。
- `issues` 为可选字段，旧健康快照继续可读。Agent 工具和初始上下文保留各项失败信息，失败或部分失败的初始摘要不作整轮缓存。

健康设置中的开关表示允许使用健康上下文，不代表已获得全部类型的读取权限。`getRequestStatusForAuthorization` 只用来判断是否需要请求授权，不用来推断用户授予或拒绝读取。依据：[Apple HealthKit 授权说明](https://developer.apple.com/documentation/healthkit/authorizing-access-to-health-data)。
