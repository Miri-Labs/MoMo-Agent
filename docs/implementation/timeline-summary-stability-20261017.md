# 录音时段总结稳定性

基线 `58b1669`，修复版本 `1.3.1`。保持现有原生界面，只调整总结的状态与校验。

## 行为与原因

列表之前在缓存未命中时直接回退到原文，缓存刷新返回空值还会删除已经显示的总结。异步结果也可能通过旧详情快照被接纳，覆盖日期列表的新内容。模型生成期间，原音到期或处理元数据变化又可能使结果被误判过期。

- 同一时段的全部语音窗口完成转录、时段可以总结后，才生成及展示总结；全天录音的其他时段可以继续整理。
- 总结尚未就绪时，列表显示整理状态或“转录已完成，点开查看原文”，不拿原文充当总结。详情中的原文仍可随转录进度阅读。
- 同一正文版本的缓存暂时未命中不清空已有总结。正文修订、删除、窗口合并与来源变化仍按内容版本拒绝旧结果。
- 读取缓存、等待在途请求和写入结果统一校验完整正文版本，播放可用性与无关进度变化不触发重新总结。详情新读取的内容同步到日期快照，迟到的旧详情结果不能覆盖它。

- `package-all.log`：归档层 150 项回归通过。Agent 扩大检查有 3 个既有用例、15 条断言失败；`package-baseline.log` 在未经本次修改的基线源码上复现同样失败，涉及日期上下文、选中来源和时间提示失败注入。
- `swiftui-audit.log`：无高风险项；4 条中风险为既有时间线装饰与活动条尺寸。
- `native-build-arm64.log`：Xcode 27 的 iPhone、内嵌 Watch、Widget 及测试宿主编译通过。
- `native-summary-tests.xcresult`：4 项原生回归全部通过，覆盖空缓存刷新保留总结、未转录完成不显示旧总结、详情新正文替换旧日期快照、刷新与直接打开详情。首次扩大原生运行遇到无签名测试宿主的钥匙串写入失败，随后磁盘耗尽，结果包损坏；该运行不计通过。
