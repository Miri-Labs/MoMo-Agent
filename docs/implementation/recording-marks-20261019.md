# 手表标记接入手机转录时间线

手表录音页的标记已经持久保存并通过控制队列同步。此前手机的独立录音管理入口移除后，转录时间线没有接入标记入口。本次恢复完整的查看和回听流程。

## 用户操作

- 时间线在对应时段下显示小旗标和标记时间。同一时段有多个标记时可横向查看。
- 点击旗标进入详情，定位并突出标记附近的文字。此操作不播放声音，也不恢复到之前保存的其他阅读位置。
- 点击“从标记处回听”才开始播放。播放位置使用手表记录的采样帧，不使用附近段落的开头。
- 详情顶部可切换标记。没有可读文字时仍保留标记和原音回听入口；原音缺失时保留文字定位，禁用回听。
- 后台刷新不会重复执行进入页面时的标记定位。普通详情入口继续恢复既有阅读位置。

## 实现与边界

`TimelineWindow.marks` 提供标记身份、录音身份和 generation、epoch、采样帧、时间、原音可用性及附近段落 ID。沿用 `CaptureMark` 的持久化和同步协议，不新增传输消息。

附近文字只在同一时段、同一录音和 epoch 内查找。先命中包含标记采样帧的段落；标记处没有文字时，取距离最近的可读段落。多个录音合并展示时，不会定位到其他录音的文字。

回听将采样帧映射到现有播放器连接后的音频时间轴。播放器在启动原生音频前设置位置。若目标位置在缺失区间内，播放失败，不跳到下一个可用片段。位于已知录音末尾的标记仍可查看附近文字，不制造额外音频。

午夜内部边界的标记归入下一录音日，结束边界的标记保留在此前时段。标记使用原录音时区，不随手机当前时区改变。重复同步沿用 markID 去重。标记变化更新时段 revision，单纯增加标记不会使已有总结失效。

## 验证

- 本机执行现有 Contracts、Archive 和 Link 源码组成的轻量 SwiftPM 测试包，运行 `ActivityTimelineTests|TimelineTests|ArchiveCoverageTests`：39 项通过。使用真实临时 SQLite 资料库和音频文件。
- 新增归档测试覆盖精确帧位置、静音处附近文字、多个标记与重复投递、总结缓存保持、缺失原音、录音结束边界、午夜边界和不同录音隔离。
- 新增 iPhone 集成回归：原生播放器启动前已设置标记位置；缺失位置不能跳过；标记定位覆盖旧阅读位置且刷新不重复跳转。
- 合入最新 main 后，iPhone 集成测试包的 generic iOS `build-for-testing` 通过，包含新增回归的编译检查。
- iPhone、内嵌 Watch 和 Widget 的 Release 编译及 29 项包检查通过，版本均与共享配置一致。本次构建未签名，仅用于代码和资源验证。
- 本次不安装设备，也不启动模拟器。iPhone 集成回归的设备执行尚未完成。

新增功能版本为 `1.11.0`；已安装设备版本保持独立记录。
