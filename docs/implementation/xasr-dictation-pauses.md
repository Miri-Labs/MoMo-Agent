# X-ASR 听写保留短停顿两侧的语境

iPhone 聊天听写使用 `SpeechEngine.dictate`。Silero 可以把同一句话里一次短停顿的两侧交给两次 X-ASR 推理，后一段解码时就听不到前半句。现在先生成原有的无重叠、有长度上限的窗口，再将间隔至多一秒、合并后仍在长度上限内的两个短语交给一次解码。计算原始停顿时包含两侧已经保留的 padding。默认配置是每侧 0.3 秒，最大解码长度 20 秒。

该策略应用于 X-ASR 听写，以及复用听写入口的测速。手表时间线归档使用 `WindowPlanner.continuousWindows`。此次改动不需要新的模型文件。

## 带参考原文的对照

取 ASCEND 测试集两组各 48 条原始音频，每组中文、英文、中英混说各 16 条。组间没有相同音频，两组来自同两位测试说话人。每 6 条依次连接成一段，把原始人工转录按同一顺序拼接作为参考。用项目现有 X-ASR Core ML 及 `Tools/ASRCodeSwitchEval/score.py` 的 `momo-cs-mer-v1` 计算混合错误率。中文按字、英文按词，全组累计替换、删除和插入。 [ASCEND 官方数据集](https://huggingface.co/datasets/CAiRE/ASCEND)

| 组别 | 参考词元 | 原解码次数 → 改后 | 原错误数 → 改后 | 原 MER → 改后 |
| --- | ---: | ---: | ---: | ---: |
| 探索组，8 段 | 753 | 46 → 28 | 75 → 68 | 9.96% → 9.03% |
| 复核组，8 段 | 602 | 46 → 37 | 81 → 79 | 13.46% → 13.12% |
| 合计，16 段 | 1,355 | 92 → 65 | 156 → 147 | 11.51% → 10.85% |

分段前后使用相同 PCM 和 Silero 参数，仅改变交给识别器的窗口。16 段中，7 段错误减少、2 段增加、7 段持平。两位说话人和人工插入的停顿限制了结果的外推。探索组的 SenseVoice 也试过相同的合并方式，错误从 79 个变为 81 个，因此只对 X-ASR 启用。

### 复现输入

每行是一个合成录音的 ASCEND test 原始 ID。将 16 kHz 单声道 PCM 前置 0.30 秒静音，在每条音频后依次加入下方给出的间隔，包括最后的尾部静音。使用阈值 0.25、最短语音 0.25 秒、最短静音 0.50 秒和每 16 秒一次的原有 VAD flush。用 `SpeechEngine.dictate` 获取每行的转录，与该行的人工参考逐段评分。
