# 存储重复数据与回收

2026-10-22，版本 1.19.7。

## 真机核查

手机文件清单中的「索引与其他资料」约 8.51 GB。其中 Core ML 系统缓存约 4.97 GB，正式资料库约 2.08 GB，FunASR Nano 下载中的文件约 711 MB，应用模型缓存约 260 MB，临时文件约 383 MB。临时文件中约 340 MB 属于旧测速。真正的记忆索引约 15 MB。

这些数值是文件长度总和，不是 APFS 独占磁盘空间。资料库取自运行中的主数据库文件，未附加 WAL；副本通过 `quick_check`。它代表当时已经写入主文件的数据，不是手机全部最新事务的原子快照。个人资料和原始文件清单仅保存在忽略的本地证据目录。

## 转录历史

原实现每次提交新文字都会保存整轮转录。核查副本有 8 轮录音、7,132 个版本，版本正文共 1,994,298,511 字节。每轮最新版合计 2,208,323 字节。

历史版本现在按 16 个片段组成不可变数据块。块以内容哈希去重，用系统 LZFSE 无损压缩；各版本保存时间、代次、版本号和有序块引用。修改、重排和删除片段会产生新的块，旧引用继续读取原来的内容。当前版本保留完整 JSON，供现有时间线 SQL 读取。文件恢复、投影和历史引用统一通过兼容两种格式的读取函数。

旧版本按小批事务迁移。每次替换前重建并核对规范化编码；取消、进程退出或写入失败后可从已提交的批次继续。新的转录提交会在同一事务里转换前一版本，防止继续累积全文副本。删除一轮录音时同时删除该轮的共享块。

历史整理让出正在进行的转录和模型预热，在现有资源条件允许时运行。后台是否继续获得执行时间仍由系统决定。迁移完成后，空页达到 32 MB 且超过数据库页数的五分之一，并有足够临时空间时，执行数据库收缩。

SQLite 的 `VACUUM` [可能改变隐式行号](https://www.sqlite.org/lang_vacuum.html)。因此 schema 12 先为录音、片段和回执保存稳定序号，迁移初值沿用原行号，新插入自动递增。分页、波形准备、保留范围和同步回执改用稳定序号。收缩后使依赖物理行位置的内存索引失效并重建。
