# 空闲时重复工作与运行时释放

交付版本：1.12.2。保留后台转录、自动记忆和总结，只消除已确认的重复计算与资源残留。

## 原因与改动

- 真机调用栈命中记忆向量计算。原先一个文件变化就重算其中全部条目。现在从索引读取相同正文的向量，按当前模型版本和维度验证后复用；同批相同正文也复用。数据库查询先结束，再执行本地模型。NaturalLanguage 模型在串行锁内复用，最多保存 4 种语言模型，每次计算结束释放临时 Objective-C 对象。
- 历史波形准备的完成状态原先只在内存中。现在持久化每个片段的完成记录，关联 manifest、资料代际和缓存代际。新进程只准备缺项；缓存目录被清除后会重建。实际播放仍校验原音，准备失败或取消不会写完成记录。新增表仅保存派生状态，不改变原音与转录格式。
- 自动总结在没有已激活 provider 时重复创建 Pi Runtime。现在同一配置修订的请求共享一个初始化任务和运行时，切换配置会使旧任务失效。
- 生命周期回归测试证明：HTTP 流完成、任务和计时器都已清空后，Engine 仍被保留。原因是 JS 文件操作回调捕获了 actor 内部的局部函数。将该辅助函数改为不隔离到 actor 的静态函数后，引擎释放测试通过。Engine 结束时也会关闭 URLSession，延迟回调使用弱引用。
- 1.12.1 真机复测又发现：自动总结在摘要缓存不存在时，也会先重新构造整天时间线。1.12.2 先检查缓存是否存在、格式和 revision 是否匹配，命中后才校验资料；返回摘要前仍检查资料和 provider 配置，删除或修改的资料不能返回旧摘要。

## 验证

- 新增向量复用测试：文件间重复、元数据变更、正文变化、模型版本与维度校验。
- 新增波形准备测试：重启恢复、新片段、缓存代际变化和中断后保留待处理状态。
- 新增自动 provider 测试：并发请求复用，配置修订变化重新创建。
- 新增真实 Pi/JavaScriptCore 生命周期测试：成功与 HTTP 失败后 Runtime、Engine 均释放。现有流式请求和取消用例继续运行。
- iPhone 播放集成用例增加断言：新建控制器后补齐已完成的历史波形，不再次读取原音文件属性。

本机已通过 203 项归档回归、44 项记忆整理回归、7 项 Pi 网络与生命周期回归，以及向量、记忆归档和 provider 定向测试。摘要缓存调整后 23 项自动总结与 provider 回归通过。两项使用相对当前时间的跨日记忆测试在午夜失败，已固定为本地中午，使两个证据时间始终处于不同日期。

1.12.1 已在手机和手表覆盖安装并启动，原资料库身份一致，安装前 2,870 个录音片段均保留。三段 20 秒原生进程采样的内存约 85–92 MB，没有此前每段增长约 100 MB 的表现；CPU 仍约 73–79%。这不是严格的静止 A/B：真实后台任务仍在运行，3 秒 Time Profiler 的 4,854 个进程样本中，2,689 个含 SpeechEngine，1,178 个含 AutomaticInsights，689 个含波形准备，未命中记忆向量计算；这些调用栈计数不可相加当成互斥 CPU 百分比。首次更新需要为已有波形补齐完成记录。不能据此宣称机身温度已下降。

GitHub 的 xcode-27 CI 等待 runner，仓库 runner 列表为空；本机验证和 Release 构建不能写成远端 CI 通过。新增 iPhone 播放集成断言未运行。原始真机数据只保留在忽略目录。

2026-10-20，源码 `cfd060b` 的 1.12.2 Release 构建、包检查、两端签名校验均通过，独立 Watch 包与手机内嵌包一致。手机和手表覆盖安装成功，两端实际版本均为 1.12.2。手机启动成功；手表安装后锁屏，启动命令被系统以 `FBSOpenApplicationErrorDomain/7 Locked` 拒绝，因此最终手表启动验收尚未完成。上一轮 1.12.1 手表启动后同一进程仍存活 8 分钟。

## 1.12.3：正文准备去重与释放回归

继续核对代码发现：1.12.2 已复用向量，但同批重复正文仍分别调用 `MemoryEmbedding.vector`，重复执行语言识别和模型校验。没有可用向量时，同批也会反复尝试。现在每批按正文只准备一次，包含无向量的结果；下一批重新验证和尝试，避免暂时不可用的模型永久失去重试机会。条目 ID、状态和来源继续分别保存，数据库连接仍在模型计算前关闭。

修复前的新增回归确认：119 条相同且无法生成向量的正文调用 119 次，两批共 238 次。修复后分别为 1 次、2 次。已有向量的重复正文也只校验一次；正文改变、跨文件复用、模型版本和维度变化继续验证。记忆索引、记忆归档与自动 provider 共 25 项测试通过。

Pi 生命周期回归加强为连续 8 次成功请求、8 次失败请求，每次确认 Runtime 与 Engine 的弱引用清空；另验证正在流式输出时取消请求、关闭 Harness 后两者释放。使用真实 Pi/JavaScriptCore 与 URLProtocol 测试 HTTP 响应，连同网络回归共 8 项通过。这些是本机代码回归，不是新增真机温度或功耗测量。

1.12.3 安装后复测又定位到 UIKit 后台执行权到期未及时释放，系统以 `0x2182BAD2` 终止进程。四条路径的修正、原始现象与后续验证边界见 [1.12.4 后台到期释放](background-expiration-release-20261020.md)。
