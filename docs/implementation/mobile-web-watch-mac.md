# MoMo Agent 手机网页版试用

手机用 Safari 聊天、回看转录、回听手表原音和查看记忆。手表负责录音和保管待传分片。Mac 接收原音，在本机识别语音，再把有时间信息的文字接入现有 Agent。网页沿用原生应用的 MoMo Avatar、Pebble 字标、手表状态浮层和三个底部入口。

## 在 Mac 上试用

1. 启动并配置现有的 MoMo Agent Mac 版。网页复用它的会话、记忆和资料。
2. 从仓库根目录执行下面的命令。转写器使用本机的 Swift 工具链、项目固定的 sherpa 运行库和 `Models/Speech` 下的模型。首次准备这些文件时，按[构建说明](../../install.md#需要重新构建)操作。

   ```sh
   swift build --package-path Apps/MobileWeb/Speech -c release --product momo-web-speech
   ./Scripts/start-mobile-web.sh
   ```

3. 用 Mac 浏览器打开[设备配对](http://127.0.0.1:18790/)，点击「生成网页配对码」。进入[网页版](http://127.0.0.1:8789/)，输入八位数字。配对码十分钟内可用一次。可以从设备配对页随时解除单个设备的授权。

服务默认使用已安装 Mac 版的 Python 环境。使用其他安装位置时，设置 `MOMO_WEB_PYTHON`，该环境需包含 `aiohttp`。另行存放转写器和模型时可以设置 `MOMO_WEB_SPEECH_BINARY` 和 `MOMO_SPEECH_MODELS`。缺少模型时，Mac 仍可接收原音供回听，转写任务留在队列。退出后，重新运行启动脚本即可使用已有配对和录音。

自行签名构建手表时，可按[安装说明](../../install.md#检查实际安装包)验证手机与内嵌手表包。已有个人签名标识的构建应向检查器传入 `--variant self-hosted --expected-phone-id`，其值使用签名配置中独立指定的 `MOMO_PHONE_BUNDLE_ID`。发布包继续使用默认的正式版检查。

## 在 iPhone 和手表上连接

两台设备需要能访问同一个有效的 HTTPS 地址。上一步的 `127.0.0.1` 只通向打开浏览器的设备自身。在已有用户授权的 HTTPS 反向代理中，保留请求的 Host，只转发到 Mac 的 `127.0.0.1:8789`。启动时用 `--public-url https://你的域名` 指定对应地址。生成配对码的管理页在 Mac 自己的 `127.0.0.1:18790`。启动脚本只监听回环地址。

1. 在 iPhone Safari 打开上述 HTTPS 地址，输入 Mac 生成的**网页配对码**。网页菜单中可以打开「添加到主屏幕」，对应路径为 `/install`。按 Safari 的「共享 → 添加到主屏幕」操作。若从主屏幕首次打开时出现配对页，重新生成一个网页配对码即可。
2. 在 Mac 配对页点击「生成手表配对码」。在使用此版本的手表打开「更多 → 连接 Mac」，输入同一个 HTTPS 地址和**手表配对码**。以后手表可以在 Safari 关闭时传送已封口的原音。手表上仍可选回原有的 iPhone 接收方式。
3. 在聊天页轻点 MoMo 右下的手表，看最近一次报告和待传数量。到「转录 → 手表录音」查看 Mac 已收的原音和识别进度。「Mac 已有转录」可回顾此前已同步给 Agent 的文字。

## 断线与恢复

| 情况 | 手表 | 网页 |
| --- | --- | --- |
| 手表可访问 Mac | 分片封口后交给系统后台上传，校验 Mac 回执后清理本地副本 | Mac 收到即可回听，识别完成后显示文字 |
| 手表暂时无网，或 Mac 关机、睡眠 | 继续录音，保留未确认分片，占用手表储存空间。具备网络与执行机会后重试 | 只有 Mac 可达时才能读取个人资料。手表状态带上次报告时间 |
| Mac 已收到，回执途中断开 | 再传同一分片可取回原回执 | 同一分片只显示一次 |
| 仅 Mac Agent 暂停，网页服务仍运行 | 网页服务仍可归档，已转写的资料等待投递 | 已归档原音可回听，聊天等待 Agent 恢复 |

手机浏览器不需要常开，离线缓存只包含公开引导资源。Mac 的试用资料位于当前用户的 `~/Library/Application Support/MoMoAgent/MobileWeb`。原音、采集时间、校验信息、识别窗口与模型结果一起保留。当前网页提供语音转写。环境音与情绪分析可使用这些原音后续开发。

## 验证范围

- watchOS 27.2 模拟器通过一次性码与隔离的 Mac 服务配对，使用系统后台 URLSession 上传一秒测试音频。确认 Mac 原音内容与回执摘要相符，手表仅在正确回执后清理，待传计数归零。共四项 Watch 测试，另覆盖旧接收方、重启和原有 iPhone 路径。
- 使用仓库内 13.06 秒人声样本及一秒静音，在 Mac 实际完成音频解码、Silero/SenseVoice 识别与现有 ContextStore 入库。七项归档测试覆盖重复或损坏的上传、分页、写入失败与重启恢复。
- 手机尺寸浏览器测试覆盖配对、聊天回执、重试、分页、音频解码播放、离线和主屏幕引导。已用正在运行的 Mac 服务读取真实会话和资料接口，带内容的录音与记忆详情使用隔离数据验证。
- 三项网页网关测试覆盖设备授权、解除配对和网页回听。分片到 Mac 后，浏览器可用 HTTP Range 读取指定范围的原音，即便该片尚在排队转写。在当前个人签名配置下，手机与内嵌手表的 29 项包检查通过，独立手表和内嵌副本逐文件一致，版本均为 0.7.0。
- 真实 Apple Watch 出门借用配对 iPhone 网络时的后台上传延迟、全天续航，以及 iPhone Safari 系统「添加」的最后一步，仍需真机验证。
