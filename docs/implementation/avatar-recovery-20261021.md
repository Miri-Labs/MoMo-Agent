# Avatar 加载失败后的恢复

用户在 1.19.2 看到“助手暂不可见”。旧实现将网页加载、脚本调用和内容进程退出统一设为 `failed = true`，后续成功没有清除该状态，也没有重载逻辑。这会让一次临时错误持续隐藏 Avatar。

本轮未取得手机触发错误时的具体原因：旧实现没有保存错误详情，系统日志采集需要本机管理员授权。安装包内的 HTML 与脚本在本机 WebKit 中加载成功，能绘制 6 个 SVG path 并接收外观设置。这确认资源可执行，不能据此判断手机当时为何失败。

共享 Avatar 组件现在按下列规则恢复，聊天首页和引导页一起生效：

- 内容进程退出或脚本失败后，清除旧调用状态，在前台最多重载两次，分别等待 300 毫秒和 1 秒。后台不重试；再次进入前台可以重新尝试。
- 重载完成后应用最新表情与主题，并恢复显示。旧加载周期、已拆除视图的回调和正常导航取消不会再把新页面标成失败。
- 加载或恢复期间显示 MoMo 的静态矢量图，恢复后切回动画。图形从同一渲染器的静止姿态导出，提供明暗两套颜色，没有改角色轮廓。
- 只有失败时写入错误阶段、域、代码和时间，保存在 `Library/Caches/MoMoAgent/avatar-latest-failure.json`，并写入系统日志。没有新增周期扫描或无限重试。

WebKit 的内容进程终止回调与页面加载是独立事件，接口说明见 [Apple 文档](https://developer.apple.com/documentation/webkit/wknavigationdelegate/webviewwebcontentprocessdidterminate(_:))。

从实际 Coordinator 源码提取的本机 WebKit 检查已通过：初次绘制、脚本异常后恢复、后台故障延迟至前台恢复、恢复最新状态、重试次数上限、再次进入前台恢复，以及拆除后忽略回调。探针第一次使用相对路径被导航白名单拒绝，改为与 App 一致的绝对资源 URL 后通过。这里测试的是 WebKit 回调和脚本异常处理，没有在手机上主动终止系统网页进程。

新增对应 iPhone 集成用例；按用户要求未运行模拟器回归。版本为 `1.19.3`，源码提交 `16a7a138`。Release 构建、包与签名检查通过，编译后的资源目录包含静态 Avatar 的明暗矢量资源。手机已覆盖安装、启动并读回 `1.19.3`；检查时缓存目录没有产生新的 Avatar 失败记录。尚未在真机操作引导页来逐帧检查动效。
