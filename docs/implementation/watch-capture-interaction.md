# 手表录音入口调整（2026-10-15）

按用户反馈，将开始录音与静音职责分开。未开始或已结束时，波点正中央显示“轻触开始录音”，整个波点区域可点击，下方不显示操作按钮。开始后显示麦克风与标记；麦克风仅暂停/恢复当前会话的声音采集，分别显示“静音”“解除静音”，静音图标为带斜线麦克风。静音仍保留当前录音会话和原音，重开应用后也保留。

左上角原电脑图标打开的是传输状态/录音信息，与更多菜单已有入口重复。本次移除左上角按钮，统一从右上角“更多 → 录音信息”查看时长与传输队列。“更多 → 结束录音”保留既有确认步骤，结束后返回中央开始入口。

改动仅涉及 CaptureView 与既有 Watch UI 旅程，不调整采集运行时、原音存储或传输协议。UI 自动化同时验证开始前和结束后底部按钮不存在，以及静音、重启恢复、标记、结束确认和待确认原音保留。

用户进一步确认不需要在首页显示录音时长，而是将系统时间放在顶部正中央。通过不可交互且不参与辅助功能的透明 leading toolbar 占位，让 watchOS 自行将原生系统时间居中，右侧仍为更多按钮，不绘制或维护第二套时钟。Xcode 27 Watch build-for-testing 通过，已在 40 mm Watch 模拟器启动并查看截图确认：时间顶部居中，左上无可见按钮，中央开始提示和右侧更多保留。截图为 `tmp_agent_output/20261015-watch-tap-start/centered-system-clock.png`。本次布局微调未重跑上一节完整交互旅程。

## 真机反馈：大字号横排与音量响应

用户在 SE 2 44 mm 发现底部两个按钮纵向排列。原实现于 Dynamic Type xxxLarge 起主动切到 VStack；现始终使用横向两列，圆形按钮按当前可用宽度约束尺寸，文字可换行。大字号时整体仍可滚动，不再改成纵排按钮。

波点仍由实际麦克风 RMS 驱动，改为 -55 至 -20 dB 的显示映射，保留每 100ms 窗口内的峰值，并缓慢回落；移除压缩音量差异的四次方根。参考收到的真机音频，100ms RMS 的中位数约 0.00257、90 分位约 0.00855、峰值约 0.120；仅调整显示，不改变录音增益或原音。真实信号与模拟器界面截图需分别判断。

`tmp_agent_output/20261015-device-sync/` 中，watch-responsive-01 验证 40 mm 大字号录音/静音横排、完整录音旅程及音量映射，3 项通过；watch-responsive-44mm 在 44 mm 再验证大字号横排，1 项通过。已查看 40 mm 大字号的录音、静音截图。按真机 RMS 收窄显示范围后的映射测试在 watch-meter-02 复跑通过。大字号测试 override 仅在 DEBUG simulator 且提供合法测试 UUID 时生效，不进入真机编译。

## 后续真机反馈：单屏首页与首次连接

用户确认录音首页应始终只有一屏。取消大字号、容量提示和错误触发的 ScrollView；可用高度优先留给状态与横排按钮，波点使用剩余空间。同步提示放在更多/录音信息，用户主动操作失败使用可关闭的系统提示，均不增加首页高度。

真机第三次录音已到手机，但回执仍未返回；RecordingError.receiverNotBound 的 NSError code 为 7。未绑定时先保留回执，等待身份消息后重试；不能把资料库身份等待当作永久错误，也不能直接按回执绑定手机。为两端前台连接增加可达时的即时控制消息，后台持久传输仍保留，同一指令仍经原收件箱和身份校验处理。
