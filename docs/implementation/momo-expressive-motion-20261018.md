# MoMo 眼型与动作加强

2026-10-18，源码版本 1.7.2。用户指出 1.7.1 的变化太少，并明确要求眼睛本身有明显变化。

## 表现调整

保留原创眼部参数和 MoMo 身体，把验收尺寸从放大的角色图切回真实聊天顶部的 84pt。表情使用睁开程度、长宽比、左右不对称、弧度、倾斜和目光变化；每个工作阶段也有独立姿态。

| 场景 | 眼型 | 动作 |
| --- | --- | --- |
| 日常 | 熟悉的竖眼；首页循环含明显单眼眨 | 首页继续好奇转头，顶部保持安静待机 |
| 聆听 | 25×42 与 23×36 的大眼 | 朝向用户、略歪头 |
| 思考 | 一只 28×10 眯眼、一只 22×30 睁眼，视线抬高 | 明显歪头和左右找线索的视线 |
| 执行 | 两只 32×11 宽扁专注眼 | 俯头，身体压缩伸展，保持专注 |
| 回应 | 26×30 与 29×25 圆润眼睛 | 点头、轻提身体，独立于 token 到达节奏 |
| 完成 | 两只 38×9 大弯眼，弯曲量 -10 | 一次小跳和舒展，随后回到日常 |
| 遇阻 | 28×32 与 26×15 高低眼 | 约 12° 的关切侧头，保持目光 |
| 招呼 | 一只 36×8 弯眼、一只 27×37 睁眼 | 单眼眨；首页更大弹跳，顶部稍小 |

上表为原创眼部设计坐标，不是屏幕点数；还会经过实际朝向、眼睑与曲面投影。完成状态 1.7 秒后开始收回。首页招呼跳高由 22 增为 44，顶部由 8 增为 25；忙碌招呼使用 7 的小点头，结束后继续真实状态。

轮廓生成同时采样圆角和直线段，再施加中心线弯曲。此前只充分采样圆角，宽眼的中段缺少顶点，导致弯眼看起来接近横条；本次修正后形成真实弧线。

身体动作在原有 SVG 层内进行，和眼型共用既有 30/15 fps 几何时钟；切换时从当前变换继续，减少动态效果、隐藏和停止时归零。原生 WebView 仍固定，不增加外部动画库或参考仓库数据。正文里的原品牌思考动效、手表状态小标、同一 MoMo 的首页到顶部移动保持原职责。

## 预览与验证

- [顶部尺寸动作与眼型动图](evidence/2026-10-18-momo-expressive/header-motion.gif)：从实际打包的 `agent-avatar.html` 与运行时采样，八个 126px 透明视口对应 84pt 原生角色；60 帧、3 秒，循环仅用于查看。
- [首页动作动图](evidence/2026-10-18-momo-expressive/home-motion.gif)：216px 视口对应 144pt 首页角色，120 帧、6 秒，包含待机眼神、单眼眨与一次点击。
- [放大眼型预览](evidence/2026-10-18-momo-expressive/expressions.png)与[顶部尺寸静帧](evidence/2026-10-18-momo-expressive/header-preview.png)。以上为实际 SVG 输出经 CairoSVG 绘制，不是浏览器或 iOS 截图。

19 项头像测试通过，包含顶部尺寸眼型差异、真正的弯眼中段、明显的单眼眨、动作的连续中断与限帧、640 份过渡轮廓无自相交、完成收回与历史会话隔离。19 项聊天核心测试、品牌动画及离线资源校验通过。共 600 份视口采样中，透明内容均未接触视口边缘，见[捕获记录](evidence/2026-10-18-momo-expressive/capture-checks.json)。

本轮环境仍是 Linux，未进行 iOS 编译、模拟器或设备验证，没有生成可安装 App。动图证明实际资源的几何和调度表现；原生显示与耗电仍需在设备上验证。
