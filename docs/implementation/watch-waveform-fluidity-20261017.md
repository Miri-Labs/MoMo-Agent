# 手表波形刷新卡顿

用户反馈近期波形比旧版卡顿。本轮从 `origin/main` 的 `1366c30` 建立独立分支，不修改另一任务正在处理的传输、回执和启动恢复代码。

旧版 `CaptureDots` 每 100ms 独立推进一列。`4b0b719` 将历史移到 `CaptureMeter` 后，绘制改为跟随编码进度更新；`CaptureEncoder` 通常每 200ms 才发布进度，因此 100ms 的显示桶会累积到两列后一次公布。封口和落盘等待还会拉长显示更新间隔。

本轮保留运行时的 29 列采集包络，在活跃录音页面中使用目标 20 帧/秒的独立显示时钟。`displayHistory(at:)` 根据单调时间进行列间线性插值，两个编码回调之间也能推进。缺少新回调时，已有显示能量继续衰减；显示插值不写回采集历史或录音账本。

熄屏、停止录音、开启减少动态效果或没有可见声音能量时，视图使用静态 Canvas，不创建显示时钟。恢复活跃时从保留的历史开始，重复前台通知不重置显示时间。点阵尺寸、横向铺满、音频采样、编码、分片和传输保持原有职责。

验证使用系统默认字号。原生宿主用例覆盖无新编码回调时的半列推进、回调边界连续性、隐藏与抬腕、重复前台、异常时间、历史不被绘制修改，以及正式 Canvas 连续四帧像素不同。已有点阵宽度与包络测试一并回归。

`tmp_agent_output/20261017-waveform-fluidity/` 保存本轮证据：`build-final.log` 构建成功，`waveform-tests.xcresult` 中 9 项宿主测试和 1 项整屏 UI 测试全部通过，0 失败/跳过。四帧截图分别对应 0、50、100、150ms，期间没有新增音频回调；已导出并目视复核连续帧及整屏截图，文件名见 `attachments/manifest.json`。

提交前同步主线传输修复 `4b766c0`，两处重叠文件自动合并成功。最终组合版本重新构建并复跑同一组 10 项检查，全部通过；结果为 `build-integrated.log`、`tests-integrated.log` 和 `waveform-integrated.xcresult`，不重复计算为新增测试项。

验证设备为本任务专用 Apple Watch SE3 44mm / watchOS 27 模拟器，测试不启动麦克风、不运行真实传输。此结果验证刷新逻辑和原生绘制；物理手表的实际帧率、抬腕效果与耗电仍需安装后检查。
