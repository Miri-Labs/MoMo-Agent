# Core ML 输入配置与长录音本地修复

本地候选已通过两次完整一小时转写，以及真实模型的取消、重试和 PCM 复用回归。采用 `bounded512-v1`：保留 128、256、512 帧输入，移除本应用不会使用的 1024、1800 帧配置。没有合并 main、推送或安装设备。

## 修改与原因

上游模型提供五个输入档位，默认 1800；本应用保留原有 20 秒核心及两侧 padding，最长 20.6 秒上下文约需 344 帧特征。模型加载与切换形状时曾进入 ANE 编译等待，详见[修复前记录](sensevoice-coreml-benchmark-20261018.md)。运行时允许范围与模型声明一并缩小，默认改为 512，短片段继续使用 128、256，避免无效 padding。

识别串行队列按每个 work item 释放 autorelease 临时对象。VAD、分析队列、音频窗口、检查点、顺序读取、结果提交及取消屏障沿用原实现。识别指纹更新为 `fluid-sensevoice-lfr6-query4-ctc-bounded512-v3`；分析指纹不变，已保存的旧识别结果仍可解码。

模型准备时先校验上游文件 SHA256，再修改两个编译文件的形状声明；运算图正文、INT8 权重、预处理器和词表保持原样。原始 pin 单独保存在 `Native/SpeechVendor/coreml-upstream-manifest.json`，生成文件使用新的固定哈希。ModelDescription 使用 coremltools 官方 protobuf 定义编码；外层容器按本次固定产物的布局检查。布局、声明或输出哈希不匹配就停止准备，不能用于任意模型或其他上游版本。生成工具仅在构建机使用。

## 实测与口径

Apple M4、10 核 CPU、16 GiB 内存、macOS 27.0 / 26A428，Release `-O`。仍使用固定的 20 条 FLEURS 中文录音及原始参考文本；长录音为这些句子加句间静音后重复拼接的压力输入。复用此前校验过的 71 个 WAV 和 manifest，旧、新实现使用相同长输入身份。Mac 数据不能替代 iPhone 的速度、温度、能耗及后台验收。

磁盘恢复充足后，先用旧实现再跑完整对照。这次旧实现也跑完了一小时，故此前 ANE 编译失败不能全部归因于代码；磁盘和缓存压力是混杂因素，早期失败记录保留。本轮没有清空全局 Core ML / ANE 缓存，也没有占用独立空闲主机，首次加载数字不是严格冷启动分布。

两次修复运行的全部 14 次长任务成功，逐个转写窗口 ID、完成窗口数和最终文本 SHA256 均与旧实现对照一致。两个进程各自的 20 条自然句子也均完成，逐句文本与旧 Core ML 一致；CER 都为 63 / 841，即 7.49%。自然句子的 fixture 每轮生成新的源 UUID，因此不跨进程比较其窗口 ID。该小样本检查回归，不代表全天环境的完整识别质量。

新构建本轮第一次模型加载为 44.911 秒，第二个进程为 0.156 秒；旧实现本轮第一次为 160.795 秒。另一个三档原型第一次加载为 84.853 秒，说明系统首次准备仍可能花数十秒，不能承诺安装后首次立即可用。长任务表排除了此前自然句子阶段已发生的模型加载，不能将 27 秒解读为任意冷启动的一小时端到端总耗时。

曾试过所有片段固定补齐到 512：一小时完整执行需 48.720 秒，10 分钟约 6.4 秒，比旧实现本轮补测更慢。最终实现保留短片段的小档位，未采用该候选。

本轮旧对照先运行 Sherpa，再运行 Core ML；最终两个进程仅运行 Core ML。记录的整进程内存峰值因此不用于计算模型内存降幅。当前也没有真机能耗结论。

## 验证与复现

- 最终 Release 基准工具构建通过；两次相同可执行文件、相同模型 manifest 的长任务通过。工具 metadata 保存可执行文件 SHA256、源码摘要和模型 manifest SHA256。
- Debug 定向回归 10 项通过，包含真实模型：窗口与旧分析一致、PCM 复用、token 时间坐标、重复转写、原生返回后取消丢弃、取消后重试，以及旧结果解码兼容。
- 模型准备离线测试 3 项通过：上游 pin 与权重保留、固定 protobuf 形状与输出哈希、已有模型升级、重复准备复用、未知元数据拒绝。
- 静态发布包检查器自身的 21 项回归通过。这不是本轮手机发布包编译或安装验收。
- 运算图正文与固定上游逐字节一致，权重等其他七个模型文件哈希不变。两次长任务全部窗口与文本比较结果保存在 `comparisons.json`。

证据目录为 `tmp_agent_output/20261018-coreml-fix/`：`control-roomy-01/` 为旧实现补测，`fixed-profile-01/` 为未采用的固定 512，`bounded-01/` 和 `bounded-02/` 为最终两个进程；各目录保留自然句子、逐调用诊断和长任务记录。测量时源码摘要为 `sha256:274552cbf82059aa31b506301060ea92315fb35d9cfc29712d2251183d5eb824`，模型 manifest SHA256 为 `880995250bc5c29f91dbed85df90bb9f968fa2fa08119498863f8f7c1ff0434c`。测量完成后只删除一条过时注释并整理文档，识别实现与模型未再变化。

准备模型使用 `uv run Native/SpeechVendor/prepare-models.py Models/Speech --scratch-directory tmp_agent_output/<任务>/prepare`。基准命令见 [BACKEND_BENCHMARK](../../Tools/SpeechQuality/BACKEND_BENCHMARK.md)；使用 `pipeline-coreml` 和已有共享输入目录，可以在新进程中重跑模型加载及完整长任务，不复制音频，也不加载第二个识别后端。
