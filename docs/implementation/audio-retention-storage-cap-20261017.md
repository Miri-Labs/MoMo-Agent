# 永久原音保留与存储上限

原音保留新增“永久”，不再按天数到期。储存空间新增原音存储上限，默认 20 GB，界面支持设置 1–1000 GB，按十进制 GB 计量。上限与保留期限分别保存；永久保留继续受上限约束。转录、索引、转写模型和临时导出副本分别统计，上限只管理原音。

原有默认保留期仍为 7 天，已保存的 1–365 天设置不变。保留策略用明确的 `AudioRetentionPolicy.days` / `.forever` 表达；沿用 metadata 的 `retention_days` 键，数值兼容既有记录，新增 `forever` 值。上限使用 `audio_storage_limit_bytes` 键，首次缺省为 20,000,000,000 字节。无效设置读取时报告错误，写入时拒绝，保留已确认的设置。

## 清理与保护

- 按原音封存时间从早到晚清理，同一时间按入库顺序处理。永久取消按天到期，超限清理仍然生效。
- 只处理已确认同步且转写完成的原音。每个 epoch 必须提供足够的分析重放边界，仍被待处理窗口使用的原音继续保留。
- 录音详情的“原音不自动清理”同时保护到期与超限清理。播放、转写输入或导出持有原音租约时，整次录音都受保护，避免分页播放器尚未获取的后续片段或回退位置被删除。显式删除仍使用原有租约屏障。
- 清理只删除原音文件并更新原音状态，转录版本、正文和来源引用继续保留。已有的 `expiry_pending → expired` 恢复流程复用。
- 配额根据已入库原音 manifest 中、接收时已核对的文件长度统计，不读取或哈希整个音频库。接收中的临时原音、保留中或使用中的录音可能暂时使实际占用超过上限。容量页显示真实文件统计及超限说明，接收流程不拒收新录音。

## 调度

PhoneRuntime 在资料变化触发刷新后请求低优先级清理，常规请求间隔至少 60 秒；设置保存后立即发起后台请求。同一时间只运行一个清理任务，保存期间的新请求合并到后续检查。

每次最多清理 128 个片段，批次之间让出执行机会。资料读取与会话恢复不等待清理结束。数据库查询先物化结果并关闭 statement，删除标记分别提交，不跨异步等待保留数据库事务或文件句柄。清理失败独立展示具体阶段，下一次重试先恢复待完成的删除。

## 验证

证据位于本 worktree 的 `tmp_agent_output/20261017-audio-retention-storage-cap/`。

- 141 项档案检查通过，见 `archive-tests-01.log`。新增用例验证旧天数兼容、永久与上限持久化、无效值不覆盖已保存设置、按封存时间先后清理、单次清理数量限制、正文不变，以及 6 种保护条件下仍可接收新录音。
- 手机回归覆盖 44 项不同用例，包括真实本地转写、回听与单条原音保留，保存后重启，默认 20 GB、拒绝 0、改为 35 GB 后重启恢复，以及导出、播放与收件状态生命周期。第二轮 43/44 通过；播放用例改为核对新规则下的租约与目录删除屏障后，最终针对性补测 4/4 通过，无跳过、无 xcresult 运行时警告。见 `phone-regression-02.xcresult` 与 `phone-regression-03.xcresult`。
- 首轮的容量输入测试把光标落在原数值前方，实际填成 3520，保存按钮正确保持禁用；测试已明确定位末尾并分别确认 0 和 35。旧播放断言借到期删除检查租约释放，与新增的整次播放保护冲突；现在直接读取实际租约并检查停止后的完整删除。前两轮容量页出现的尺寸警告，在移除键盘工具栏的占位布局、改用导航栏“完成”后不再复现。原始失败记录保留。
