# 持续整理的局部失败隔离

基线 `f876628`，交付版本 `1.1.2`。按 Ponytail full，复用既有归档、分析检查点与单模型队列，只补齐坏范围隔离、持久重试和等待状态。

## 行为

自动整理在领取、解码或识别阶段遇到确定的音频错误，会记录范围和结构化错误码，再继续处理其他独立录音。失败记录包含 session、epoch、版本、模型配置、阶段、任务身份、次数与重试期限。可读取原音的处理失败从 5 秒开始退避，间隔指数增加至最多 5 分钟；原音不可用则等待校验通过的补传，不用计时器反复检查。重新打开 App 后可以恢复记录和期限；后台失去执行资格时停止唤醒，获得资格后继续。

领取失败只隔离无法校验的本地原音；识别失败只隔离对应核心，分析失败隔离当前有界输入页。依赖同一坏文件的其他核心也会分别记录失败。隔离不代表修复文件，也不跨过同一 epoch 中尚未收到的帧。模型初始化、配置与数据库错误仍报告全局失败。用户指定范围重试或明确运行冻结批次保留原有失败语义，不扩大选择范围；明确批次可立即重试处于自动退避期的窗口。

无可运行任务时，归档分别返回等待原音、最新尾段等待上下文、原音不可用、排队、等待重试和空闲。仅缺少录制结束事件不会让已处理完的接收范围继续显示等待原音。时间线从归档读取失败，冷启动也保留具体范围与原因。

SQLite 新增第 9 版迁移，事务只登记失败或完成状态。原生音频读取、模型执行和退避等待均在事务之外。成功或失败后沿用既有取消、lease 释放与删除清理；完成范围清除对应失败，旧 generation 和旧模型配置不影响当前范围。没有新增依赖或并行模型执行器。
