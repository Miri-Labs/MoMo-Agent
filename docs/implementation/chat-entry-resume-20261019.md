# 聊天启动与恢复

2026-10-19，版本 1.8.2。

用户反馈每次打开都恢复旧聊天，首屏等待较久。现在按实际离开时长决定入口：不足 30 分钟恢复当前会话，达到 30 分钟打开聊天首页。冷启动和留在后台后返回使用同一规则。系统时间倒退时也回到首页。

## 加载与状态

- `AssistantConversations` 保存前后台活动时间，后台资料同步不刷新该时间。旧索引首次升级以文件修改时间迁移。
- 到期后切到未绑定会话的首页，不创建 Agent 会话，不读取旧会话内容。未发送的首页草稿仍保留。
- 当前聊天可用状态独立于录音资料库的初始化。恢复聊天不再等待整库维护，空首页不扫描聊天目录。
- 短时间返回只读取选中的会话及其未完成发送记录，不读取其他会话的元数据。
- 打开侧栏才刷新聊天列表。首次加载显示列表占位，已有列表刷新时继续展示。
- 到期后保留旧模型、草稿、阅读位置和进行中的回复；用户仍可从历史返回。返回首页同时退出设置或转录详情的导航层级。
- 回到首页后忽略旧历史读取任务的页面切换结果，避免迟到的异步结果再次打开旧会话。

`AssistantDraftIntegrationTests` 本地 46 项通过，覆盖到期冷启动、短时间恢复、无关历史损坏、30 分钟边界、后台唤醒后延迟打开、时间倒退、草稿保留及到期后后台回复继续完成。测试使用隔离目录中的真实 SQLite 和 Pi 运行时；可控回复由测试 provider 提供。
