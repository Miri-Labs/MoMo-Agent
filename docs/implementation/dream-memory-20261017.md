# 分类 Markdown 记忆与后台整理

2026-10-17。基于远端 main `afa1142` 合入记忆整理，应用版本为 1.6.0。

## 最终行为

已核对[Hermes 的提示词及工具链](hermes-memory-editing-review-20261017.md)。后台现在通过实际 memory 工具的 add / patch / remove / operations 参数编辑，不再解析助手正文中的 JSON 提案。工具校验失败会把未应用回执交给模型修正。

记忆正文保存在 Markdown 文件中。保留 USER、人物、项目、目标、近期经历和其他事实几个分类，拆开旧的大 MEMORY；不要求用户填写字段。正文允许自由写段落、标题、列表和链接，沿用 Hermes 的 `§` 条目边界及按条目修改方式。程序不再给新条目添加固定的方括号状态前缀。类型、来源、游标、到期时间与完成状态保存在旁置状态中。

自动整理使用已有空闲队列。无新内容跳过，开始聊天、修改配置或系统取消时终止旧任务。稳定偏好须有跨日原话；明确项目与承诺当次可记录。未确认说话人的录音只进入事件背景，不成为用户偏好、个人资料或承诺，也不能据此关闭用户承诺。明确完成后保留原文及完成证据。相对日期根据来源时间解释，无法确定日期时保留不确定性。

「个性与记忆 → 整理模型与推理」允许选择连接、填写独立模型 ID、设置推理强度和输出预算。默认跟随聊天连接、保留服务商推理设置；默认输出 16,384 tokens，可选最高 65,536，另受所配上下文一半的限制。推理与正文共用 API 的输出预算。截断不提交半份记忆，配置修改后旧结果无法落盘。一轮共用 120 秒截止点；通常只请求一次模型，工具校验失败时最多再请求一次修正，系统可能提前取消后台执行。

## 真实 DeepSeek 提取

使用本机已有凭据，实际入口是 **OpenRouter** `openrouter.ai/api/v1`，模型 `deepseek/deepseek-v4.1-flash`，并非 DeepSeek 直连接口。最终验证明确选择高强度推理和 32,768 tokens，不改变应用的「服务商默认」。通过生产 `MemoryDream.generate` 和 `AgentPromptStore.applyDream` 执行，保存到本机隔离 Persona。

最终验证日志位于本工作树 `tmp_agent_output/20261017-dream-memory-live/live-08-tools-high/`：

| 场景 | 实际结果 | 请求与落盘耗时 |
| --- | --- | --- |
| 已知答案的个人背景 | 原样迁移 2 条旧记忆，新增 5 条；绿茶偏好有跨日证据，未把一次拿铁经历或第三方发言归为用户偏好；相对项目时间带具体年份与日期 | 5.49 秒 |
| 明确完成承诺 | 对既有原文标记 1 条完成，保留原事实与来源 | 9.36 秒 |
| 手机诊断副本中的真实录音 | 3 段、362 字，提取 3 条近期事件；USER 和 GOALS 仍为空，每条引文均逐字匹配来源 | 2.65 秒 |

最终 opt-in 测试通过，退出码 0，实际编辑协议为 `memory-tool-calls`。早期强制 JSON 提案的结果只保留作过程记录，不作为这次工具链验收依据。源档案 SHA-256 前后一致，临时凭据文件已删除。私人转写、提案及来源标识只保留在忽略目录，不提交 Git。没有修改手机原库或安装手机、手表。

真实调用发现并修复两处问题：小输出预算会被默认推理耗尽；同段录音的多处有效引文曾被误认为重复来源。现在预算可配置；同一来源可提供不同引文，但只计算为一个来源，不会冒充跨日佐证。失败尝试保留在本机对应输出目录，不计作通过。
