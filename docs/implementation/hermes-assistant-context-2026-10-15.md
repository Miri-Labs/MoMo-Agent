# Hermes 风格的助理上下文

本次从 main 的 `832c9dc` 新建任务分支实施。研究固定 Hermes 提交、源码入口、许可证和对齐差异见 [研究记录](../research/hermes-prompt-architecture.md)；设计取舍见 [ADR](../adr/file-backed-assistant-context.md)。这是手机场景的架构适配，不是完整移植 Hermes 的 CLI、插件、人设市场或审批系统。

## 实现

- `MoMoAgent/Prompts` 独立拥有人格和长期资料。默认人格来自包内 `SOUL.md`，按用户最终要求采用 Hermes 默认 SOUL 的简短中文适配，保留直接回答、篇幅相称、无客套/复述/过程播报和独立判断的主要内容，不堆叠逐项话风禁令。用户的 `SOUL.md / USER.md / MEMORY.md` 在现有 Agent 私有根目录的 `Persona/`，不会覆盖定制人格。产品规则仍由程序管理。
- Pi 注入顺序是人格 → 产品规则 → 用户资料/长期记忆 → 本轮录音上下文。人格无额外标签，仅出现一次。私人资料用 JSON 编码，不能改工具权限。
- 每条新逻辑请求捕获并持久保存文件快照。工具循环、同一 request ID 的重试和进程重启沿用它；下一条新消息读取新内容。原来的录音版本、删除屏障、选定来源、请求时钟和有限重试继续生效。
- 单一 `memory` 工具管理 user/memory 两个目标，支持 `read / add / patch / remove / operations`。新增去重，局部修改保留其他事实，删除返回被删除条目；原子批次只看最终预算。SOUL 和产品规则不开放给模型写。写入带版本检查，三次连续失败后本轮停止记忆写入，中断工具不自动重放。
- 文件有严格 UTF-8、字节上限、文件锁、原子写、同步及并发冲突检查。恢复同样文字也不会使旧版本 token 重新有效。损坏/超限明确失败，不继续发送旧 Pi 缓存。
- 设置增加“个性与记忆”，可编辑助理性格、关于你和长期记忆。前端仅调用 Agent 文档 API；不组装 prompt、不直接读写文件、不接触 Pi。聊天渲染只给真实 memory 工具步骤加展示文字，未过滤或改写模型回答。计划功能保持移除。

## 验证

最终结果和证据哈希保存在本目录的 `evidence/2026-10-15-hermes-context/`。本机原始日志/xcresult 在主检出的 `tmp_agent_output/hermes-prompt-20261015/`，不同轮次分别保留。

- 共享 Agent 测试：文件初始化、空人格回退、UTF-8/容量/符号链接、并发与 ABA、JSON 边界、真实 Pi 的冻结/刷新/重启、记忆批次、唯一匹配、局部修改、最终容量、失败回滚与失败上限。
- iPhone 原生集成：设置 API 持久化/冲突、实际 Pi 工具写入、真实 URLSession 编码后的 system prompt 顺序、人格不重复，以及更新/清空后新的 system prompt 不再含旧人格/用户资料。

- 渲染器与付费 runner 自检继续运行；默认普通测试不会发付费请求。

## 真实模型验证过程

用户另行明确允许付费验证；先使用 OpenRouter `anthropic/claude-sonnet-4.6`，随后按用户要求改为 `deepseek/deepseek-v4.1-flash`，仅发送合成资料。测试自然问候/明确记忆的保存与删除、近期录音事实回答、不可信原文指令。凭据只经私有临时文件传给隔离测试，运行后停止宿主并清理临时凭据和测试工作区，不提交凭据或原始数据库。模型参数只用于本次测试，未改 OpenClaw 或产品的百炼预设。

`live-agent-01` 三项直连均返回 HTTP 403，没有回答，不能作为质量验证。`live-agent-02` 经系统现有代理自动断言 3/3，但人工阅读发现写入前提前报“已经记住”且重复确认，以及事实回答缺引用，因此不接受该轮。随后加强“先执行、后一次确认”和简短回答仍保留来源链接。

`live-agent-03` 的记忆完成顺序和来源链接已正确，唯一自动失败来自测试漏掉正确同义表达“负责人还没确定”；已补入等价表达。人工还发现切换话题后重复追问上一条疲劳问题，默认人格因此明确跟随当前话题，不反复追问。原始失败保留；后续验证使用新结果目录。

`live-agent-04` 自动通过但追问仍在；`live-agent-05` 再次提前确认，人工均不接受。工具描述明确要求调用阶段文本留空、成功后一次确认后，`live-agent-06` 三项通过、`live-agent-07` 新工作区的一项记忆复测通过，人工核对事实、来源和真实工具顺序后接受这些具体用例。它们早于最终 SOUL 简化，不外推到其他模型。

`live-deepseek-01` 三项自动通过，人工仍发现额外邀约和过滤过程说明。`live-deepseek-02` 使用两个独立新工作区复测，共 6/6 自动通过；记忆保存/读回/删除与执行顺序正确，也没有执行原文夹带的写记忆、播放或计划指令。但人工发现无关建议、合成资料提醒，以及把“负责人未确定”增强为“没人认领”的一次无依据推断，质量保持 `needs_work`，不把自动绿色当作自然度和语义全通过。

用户随后明确要求不要继续堆叠话风规则，因此最终人格回到上游 SOUL 的主要内容，移除这轮针对结尾和过滤过程追加的规则。最终构建与 DeepSeek 验证单列记录；上面的失败与中间结果继续保留，不用新结果覆盖。

`live-deepseek-03` 使用 Hermes 简化人格，3/3 自动检查通过。事实回答精简且引用正确；一次写入漏传 revision 被拒绝，模型在成功的原子批次后才确认，保存和删除状态正确。工具说明和错误信息随后明确“每次写入都需要 read 返回的 revision”，没有新增话风规则。该轮不可信资料的回复仍附带过滤过程说明，因此只接受功能结果，未把自然度标为完全通过。

`live-deepseek-04` 在最终构建、新工作区复测记忆完整流程，1/1 自动检查及人工复核通过；四次 memory 调用均成功，每次写入均携带正确 revision，保存/删除后只给出一次最终确认。该轮只验证记忆用例，不与上一轮合并冒充一次完整回归。测试宿主已停止，临时凭据及隔离工作区已清理，只关闭本任务的 iPhone17e 模拟器。

本次结果仅覆盖这些具体题目与模型，不代表完整 v0.1、真机、长时录音或所有对话质量已经验收。
