# 首页卡片与 MoMo 布局

用户的真机截图暴露了两个问题。自适应网格在只有一条建议时仍保留第二列，40 字主题与 80 字背景又没有预览行数限制，因此卡片窄而高。MoMo 使用屏幕固定坐标，欢迎标题和卡片使用独立滚动坐标，内容滚动后会互相覆盖。

1.10.8 按实际建议数量排布：单张使用通栏横向卡片，两张使用等宽双列。卡片标题与背景各预览最多两行；完整内容保留在建议对象、读屏标签与发给助理的请求中。点阵保持静止，沿用既有雾紫和鼠尾草绿。

首页为 MoMo 保留真实布局空间，并用 SwiftUI 布局锚点定位同一个角色。角色、名字、欢迎标题和卡片共同参与首页布局，滚动时保持相对位置；角色经过页头时裁切到内容区域。进入对话后，原角色移动到页头位置，输入框持续挂载。首页内容整体居中，空间不足时可以滚动。

实际参考：用户的 `IMG_8137.PNG`、`docs/design/home-suggestions-20261016/screens/GiJ7x.png`、对应 `DESIGN-REVIEW.md` 和 iPhone `HANDOFF.md`。保留双卡的局部配色、原创点阵、16pt 圆角及系统字体。单卡通栏、预览行数限制和角色布局锚点是针对本次问题的调整；旧稿的顶部品牌和输入框位置沿用后续已确认的 App 结构。

## 验证

三项首页 UI 回归通过：双卡发送与草稿、单张长建议、双张长建议及收起后扩展。测试同时检查 MoMo 的实际像素、与标题和卡片不重叠、发送后移到页头及输入框可继续编辑。最终一轮三项耗时分别为 29.596、17.062、16.479 秒。

键盘首点用例在本次改动和原 main 的 AssistantView 对照构建中均失败，系统键盘坐标位于屏幕外。该用例未通过，不据此声称真机键盘已验收。用户随后要求停止模拟器、直接安装，已停止后续模拟器测试。
