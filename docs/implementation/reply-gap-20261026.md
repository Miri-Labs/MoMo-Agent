# Beta 1.34.7：等待气泡与回复衔接

用户反馈三点消失后仍需等待才出现文字。代码中，任务完成状态与共享聊天正文由不同请求抵达：共享用户回声已让 renderer 隐藏本地任务行，而完成状态又提前关闭等待提示，正文尚未进入共享消息列表时便出现空档。

## 修改

- 本地发送的任务已进入共享聊天后，三点持续到对应 assistant 正文进入同一渲染 snapshot；任务完成但回复仍在同步时不提前收起。
- 工具开始和流结束事件不再单独关闭三点。失败、取消、等待用户确认及确实没有输出的完成任务仍结束等待。
- 保留整条消息展示、共享消息去重和执行状态；不通过延时动画掩盖状态问题，也不调整模型或网络重试。

## 验证与交付

- 69 项客户端测试通过，覆盖完成先于共享正文、失败、取消和空输出。
- 2 项真实 WKWebView 模拟器测试通过：发送未联网时即有三点；完成状态先到仍有三点，同一 snapshot 中正文出现且三点收起。使用合成消息与默认字号。
- 手机和 Mac Beta 构建通过，29 项安装包检查通过。两端已安装并启动 1.34.7；设备读取确认正式手机端仍为 1.19.8。Mac 网关健康检查 HTTP 200，无需重启 Agent。
- 证据保存在任务输出 `outputs/reply-gap-20261026/`。本轮未重新采样真实模型的首正文延迟，不将模拟器时序验证或安装成功算作真机完整时序验收。
