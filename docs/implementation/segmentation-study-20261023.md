# 切段长度与边界对照

历史研究记录：后续 1.19.12 曾实现能量低谷候选，1.19.13 已移除其优先规则。当前切段见[移除短停顿优先切段](bounded-speech-segmentation-20261023.md)。

建议先保持 20 秒上限，优先评估沿短停顿选择切点。短句的首尾边缘需要单独校准。本轮没有修改应用的窗口长度、VAD 阈值或边缘保留参数。

后续已在 1.19.12 实现自动切点，具体取舍与验证见[沿短停顿切分长语音](pause-aligned-segmentation-20261023.md)。下文保留本轮研究时的结论和候选方案。

当前基线为 `e6b686df`，版本 1.19.11。Silero v6 通过 sherpa-onnx 连续检测语音，归档路径等待 2 秒停顿后结束语句。窗口规划器对超过 20 秒的范围按固定长度切开，语句两端保留 300 毫秒，内部窗口最多向两侧各取 1 秒上下文。原生 VAD 每 16 秒 Flush 用于限制缓冲区，随后合并连续范围；这个 Flush 位置不等于自然停顿。

上轮“开放／开饭”的样本只有 5.592 秒，没有触发 20 秒上限。因此，提高上限不能改变这条样本的识别输入。

## 对照结果

使用 sherpa 官方公开中文样本“开放时间早上9点至下午5点”。短句实验在固定的非零背景噪声中放入两次正常音量语句。长句实验重复 24 次，另有一组在语句之间加入 300 毫秒停顿。三个场景均使用手机默认 VAD 阈值 0.25。

30 秒方案只在忽略目录中的源码副本放宽配置校验，其他处理路径与生产基线相同。识别在 Mac 上使用 sherpa CPU，逐窗口运行；未测手机 Core ML、批量识别或峰值内存。每轮先预热，表中的输入秒数包含实际重叠上下文。

| 场景 | 方案 | 字符差异 / 参考字符数 | 窗口数 | 实际 ASR 输入 |
| --- | --- | ---: | ---: | ---: |
| 短句加背景噪声 | 20 秒，边缘 300 毫秒 | 2 / 26 | 2 | 10.132 秒 |
| 同上 | 30 秒，边缘 300 毫秒 | 2 / 26 | 2 | 10.132 秒 |
| 同上 | 20 秒，边缘 100 毫秒 | 0 / 26 | 2 | 9.332 秒 |
| 同上 | 20 秒，无额外边缘 | 2 / 26 | 2 | 8.932 秒 |
| 连续长语音 | 固定 20 秒 | 0 / 312 | 7 | 145.774 秒 |
| 同上 | 固定 30 秒 | 0 / 312 | 5 | 141.774 秒 |
| 长语音加短停顿 | 固定 20 秒 | 0 / 312 | 8 | 154.348 秒 |
| 同上 | 固定 30 秒 | 1 / 312 | 5 | 148.647 秒 |
| 同上 | 20 秒内沿已知停顿切开 | 0 / 312 | 8 | 154.674 秒 |

短句对照又分别只缩短左边缘、只缩短右边缘，均仍出现两处“开放／开饭”差异。直接使用原始语句范围则没有差异。这支持“模型对完整输入边缘敏感”的判断，不能据此断定只删左侧或右侧噪声就能解决，也不能将 100 毫秒设为通用最佳值。

字符差异使用去除标点后的 Levenshtein 距离，包含跨窗口正文拼接的影响。表中沿停顿切开的方案使用构造音频时已知的停顿中心，是可行性对照，尚未实现自动寻找停顿。这是结构测试，素材仍只有同一句公开语音，不能当作日常对话准确率。它表明：更长窗口减少了窗口数量和重复上下文，但没有在这组场景中稳定改善正文。

完整指标、区间和公开样本文字见 [results.json](evidence/segmentation-20261023/results.json)。实验代码见 [SegmentationStudyTests.swift](evidence/segmentation-20261023/SegmentationStudyTests.swift)。

## 下一步实现方向

1. 保持现有 VAD 对语音范围的判断。复用同一次 Silero 推理的逐帧概率，额外记录短停顿候选，不增加第二次 VAD 或 ASR 补检。
2. 对超过 20 秒的已选中范围，先在第 15～20 秒寻找候选停顿。100～200 毫秒可作为首轮评估范围；这些参数需要用正常佩戴的标注录音校准。
3. 找到合适停顿时，在停顿内切开。没有停顿时，保留 20 秒有界切分和现有重叠上下文。切点只改变识别窗口，不丢弃两侧语音。
4. 原生缓冲区 Flush、文件边界和两分钟调度任务边界分别处理。保留连续 VAD 状态、检查点与正文归属规则，避免将内部边界误当成说话结束。
5. 单独比较短句的 100、200、300 毫秒边缘，以及较完整语句范围，统计句首、句尾漏字。取得更广泛证据前，保留生产的 300 毫秒。

当前固定版本的 sherpa C API 只向应用提供带滞后的说话状态和结束范围，不能直接读出同一次推理的逐帧概率。实现自动停顿切点需要补充这一只读接口，不能通过再调用模型一遍来取概率。仍使用 sherpa-onnx，不增加模型或推理框架。

验收应同时覆盖正常音量的中文对话、短回应、快速连续讲话、多人轮流说话、正常环境噪声和跨文件边界。先固定人工参考文字，再比较漏字、重复字、字符错误、实际 ASR 输入量、手机耗时与峰值内存。此前专门挑出的 11 分钟问题片段不承担这项总体评估。

## 上游依据与复现

[SenseVoice 官方示例](https://github.com/QwenAudio/SenseVoice/blob/main/README.md)同时设置 30 秒最大 VAD 片段和 15 秒短片段合并参数；这是长度上限与片段合并的组合，不代表每段都固定为 30 秒。[Silero 官方参考实现](https://github.com/snakers4/silero-vad/blob/master/src/silero_vad/utils_vad.py)在达到最长语音限制时寻找短停顿，找不到时才强制切分。这些是方案依据，不是 MoMoAgent 已经实现的能力。

复现时使用基线提交的模型清单和源码，在独立 Swift 包中链接 `MoMoContracts`、`MoMoRecording` 与 `MoMoSpeech`。仅复制 `MoMoSpeech` 并将 `SpeechTypes.swift` 中 `maximumCoreFrames` 校验上限从 `320_000` 改成 `480_000`，生产源码保持原样。把本页附带的 Swift 文件加入实验测试目标，设置 `MOMO_SPEECH_MODEL_DIRECTORY` 指向含 `test_wavs/zh.wav` 的校验模型目录，设置 `MOMO_SEGMENTATION_OUTPUT` 指向新的输出目录，然后运行 `swift test --filter SegmentationStudyTests`。设置 `MOMO_SEGMENTATION_SHORT_ONLY=1` 可只复核短句边缘。

本机实验已完成，普通测试包已恢复到生产源码。没有安装应用，没有重跑手机历史，也没有将 30 秒实验配置带入 App。
