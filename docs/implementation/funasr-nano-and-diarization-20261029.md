# FunASR-Nano root-cause runtime and overlapping speaker segmentation

Version 0.0.1, internal build 7. This replaces post-decode repetition workarounds with a spec-faithful ONNX Runtime CPU pipeline for FunASR-Nano and upgrades speaker diarization and turn boundary alignment.

## FunASR-Nano root causes and fixes

- **Official `n_aud` low-frame-rate query slicing**: Upstream `sherpa-onnx` passed all `T_lfr` frames from `encoder_adaptor` into Qwen3, whereas `Fun-ASR-Nano-2512` trains and supervises only the leading `n_aud` low-frame-rate queries (`ol = 1 + (T - 1) / 2; ol = 1 + (ol - 1) / 2; n_aud = (ol - 1) / 2 + 1`, ~12.5% of `T_lfr`). Feeding the remaining ~87.5% unsupervised padding positions diluted attention, dropped words, caused hallucinations on silence/noise, and prematurely filled the 512-token KV cache on 20–24 s windows. `MoMoFunASRNanoRuntime` (`FunASRNano.cpp`) slices `[0 ..< n_aud]` prior to LLM prefill, shrinking a 24 s context from 423 tokens to 73 tokens and speeding up decode by 1.6x–2.3x.
- **Centered LFR padding**: Matches FunASR's `apply_lfr` (`(m - 1) / 2 = 3` left-replicated fbank frames, `ceil(T / 6)` output frames) instead of unpadded `(T - 7) / 6 + 1`, preserving initial syllable onsets.
- **Direct ORT CPU execution**: `encoder_adaptor.int8.onnx` and `llm.int8.onnx` rely on `DynamicQuantizeLinear` + `MatMulInteger`, which Core ML EP cannot fuse (fracturing the adaptor into 362 partitions with 36 s ANE compile stalls and FP16 overflow). `FunASRNano` runs directly on ORT `CPUExecutionProvider` with pre-allocated KV-cache and `IoBinding` decode buffers; `SenseVoice` retains Core ML acceleration and its `sherpa-1.13.8-coreml-v1` fingerprint.
- **Token-level repetition control and special-token cleanup**: Applies bounded `repeat_penalty = 1.12` (128-token window, exempting digits and clause punctuation) and `no_repeat_ngram = 5` during autoregressive logit selection, strips trained `/sil` / `endofbreak` / `FFFF` markers before emission, and checks `SpeechAttempt` cancellation on every decode step. Post-hoc string regex collapsing in `SherpaRuntime` has been removed.

## Speaker diarization and sentence-boundary alignment

- **50%-overlapping PyAnnote windows with powerset permutation stitching**: `Speakers.cpp` slides 10 s windows at frame-exact `step_frames * receptive_field_shift` (`79,920` samples) across blocks up to 40 s (`640,000` samples), aligns adjacent windows over all `3! = 6` speaker permutations in 7-class powerset log-probability space, blends overlaps with a raised-cosine window, and bridges `<= 85 ms` same-speaker micro-gaps.
- **Multi-span clean speech pooling**: Pools exclusive speech frames across fragments of the same local speaker (with 64-sample cosine crossfades) to extract a 3 s WeSpeaker embedding when total clean speech reaches `>= 1.5 s` while keeping `clean_seconds` tied to contiguous clean speech so Voiceprint anchor learning (`cleanSeconds >= 3`) remains conservative.
- **Acoustic turn collars and punctuation snapping**: `SpeakerTurn` adds up to `160 ms` acoustic collars into quiet margins (bounded by neighboring speaker speech) for fallback turn re-decoding, and both `SpeakerTurns.swift` and `SpeakerAlignment.swift` apply a `280 ms` nearest-turn collar, 1-token same-voice gap bridging, and `<= 300 ms` sentence-ending punctuation (`。！？!?；;`) boundary snapping.
