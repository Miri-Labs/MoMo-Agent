# 拍照附件的像素尺寸与编码

用户反馈 AI 称收到的照片被严重拉伸。本次检查拍照导入和模型请求编码，修复了可以在代码中复现的像素尺寸错误与重复 JPEG 编码。尚未取得该次实际请求的图片，不能认定这两处问题解释了原反馈中的全部失真。版本为 `1.17.1`。

## 改动

- `UIImage.size` 已包含图片方向，但单位是点。拍照导入现在用 `size × scale` 计算像素尺寸，再等比缩至最长边 1536 像素。保留系统绘制时的方向归正，避免再次手动交换宽高。
- 拍照大图只编码一次，保留原有最终 JPEG 质量 0.72 与 1 MiB 上限。已准备好的 JPEG 直接作为 `AgentAttachment.data`，单独生成 160 像素缩略图。图库与文件入口继续使用 ImageIO 等比缩放。
- 新增圆形、方格及非对称位置标记的测试，检查图形宽高、位置与图片尺寸。覆盖八种旋转或镜像方向，以及 `scale=1` 和 `scale=3`。旧的纯色测试无法检查内容变形。
- 三种模型接口的测试改用实际生成的 JPEG，在传输边界解析请求体，确认解码出的图片字节与准备好的附件一致。测试同时保留文件文字的检查。

## 验证

隔离目录：`tmp_agent_output/camera-geometry/`。没有操作正在运行的手机、手表或主线程构建目录。

- 在 Mac Catalyst 的 UIKit 与 XCTest 中运行实际导入代码和新增图像测试。旧实现出现 8 项尺寸断言失败：2048×1024 像素、`scale=3` 的输入变成 683×341，旋转后为 341×683。预期分别为 1536×768 与 768×1536。
- 修复后 2 项图像测试通过，包含 16 组拍照输入以及图库导入的大图、缩略图检查。圆形与方格保持等宽高，方向标记的位置符合预期。此次合成样本没有复现严重的非等比拉伸。
- 将上述 UIKit 路径生成的 JPEG 交给 macOS 原生测试程序。程序编译仓库中的 PiDurableKit、ProviderAccess 和配置代码，使用 URLProtocol 拦截请求。OpenAI Chat Completions、OpenAI Responses、Anthropic Messages 三种生产编码器均通过字节一致性检查，没有外部网络请求。
- 上述是聚焦测试，不是完整 iPhone App 集成测试或真机相机验收。新增用例已加入 Xcode 测试目标；本轮没有重新安装应用。

日志：`baseline.log`、`fixed.log`、`transport.log`。临时测试程序仅用于隔离执行图像处理和请求编码，没有加载用户的模型配置或照片。
