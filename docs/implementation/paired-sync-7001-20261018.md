# 配对真机同步与 7001 恢复

同步修复的开发基线 `165703b`，交付前纳入最新 `main` 的 `bb9cad1`，版本 `1.7.4`。同版记忆修复采用来源池与受限巩固，见 [Dream 机制核对](dream-memory-adaptation-20261018.md)，未采用按天队列。

## 真机发现

两端独立回读确认安装 `1.7.1` 后，用户再次遇到 `WCErrorDomain 7001`。手机日志明确记录 `receiverIdentity` 的后台传输失败，当时 `reachable=false`、系统队列尚有 20 条控制消息；同期系统日志仍有传输结果文件缺失和 `failed to load user info result`。这些证据不能确定系统文件缺失的最初原因。

22:19 手机快照有 1,669 个片段、1,412 条未完成回执。22:26 手表快照有 1,188 个待确认片段、519 条已应用回执。两端接收身份和资料库一致；519 条回执的标识均能匹配手机，其中 310 条尚未在手机标记应用。两个快照采集时间不同，不能作为同一时刻的总量守恒检查。

## 改动

后台 `transferUserInfo` 的容量限制或通道退避，原先会提前返回，阻止后续 `sendMessage` 尝试。现在两条通道独立准入：后台队列满额或退避时，只要对端可即时连接，仍可尝试保存到同一个持久收件箱。

发送即时消息本身不推进持久发送账本。后台通道仍返回原有准入结果；收到对端持久保存回复后，下次调度才可跨过该消息。即时失败采用独立通道退避，纳入自动恢复待办。控制消息数量、字节预算、接收身份核对与 `ReceiptApplied` 条件保留；原音清理仍要求业务回执。

还确认手机档案中保留两个不同手表源。手表控制收件箱有 736 条历史指令，已复制的 430 条全部是当前手表没有对应本地 manifest 的回执。手机现在依据当前所选手表的已验证状态筛选回执与待确认计数；其他设备的回执保留在手机，未标记应用。切换设备会重置分页游标；退休的异设备错误不再持续重试，也不释放尚未结束的系统传输预算。当前手表没有本地 manifest 的回执从控制收件箱清除，不产生 `ReceiptApplied`。

录音状态在读取最小账本后即激活连接并上报，不等待历史音频校验。重新打开 App、仍需轻触开始的历史录音意图上报为当前未录音；真实中断与失败保留原语义。Widget 的当前开始操作仍可恢复同一录音会话。手机明确请求刷新时，未变化的手机状态也会生成新观察时间。

## 验证

最终 iPhone 原生模拟器 22 项通过：回执与通道 18 项、所选手表切换和恢复 3 项、状态展示 1 项。异设备错误不会替换当前错误，清除展示状态仍保留所选手表来源；未收到业务回执时原音待办保持未确认。

最终 Watch 原生模拟器 10 项通过：7 项历史收件箱、冷启动和 Widget 状态用例；3 项真实麦克风用例验证历史校验未结束仍可开始采样、恢复意图等待轻触、当前 Widget 开始可恢复同一会话。配对模拟器均在测试后关闭。

共享同步模块另有 56 项通过：录音对账 9 项、Link 36 项、档案回执及状态 11 项。记忆最终回归实际执行 55 项通过，1 项真实外部模型用例未启用。交付代码 `4e7a3e8` 的 [远端回归](https://github.com/xilanhua12138/MoMoAgent/actions/runs/39143857316)通过。

最终签名 Release 构建成功，27 项安装包核验及严格签名核验通过。手机与手表已安装，并分别从设备回读确认 `1.7.4`，内部构建均为 `33`，未卸载应用或清空资料。

真机完整同步尚未通过。先前 `1.7.3` 的手机应用回执从 257 增加到 502，手表采样状态到达手机，但新音频接收数量未增长。升级前最新快照仍有手机 1,669 个片段、502 条已应用回执，手表有 1,268 个待确认片段。升级 `1.7.4` 后两端均已锁屏，公开启动接口分别返回 `Locked`，手机指定后台启动也被拒绝；因此不能把安装及模拟器通过视为配对真机验证完成，也尚未确认真实模型成功整理记忆。升级后旧录音意图仍按设计等待明确开始操作，本轮未在锁屏状态尝试启动麦克风。
