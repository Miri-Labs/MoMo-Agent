# 后台任务到期时及时释放执行权

交付版本：1.12.4，包含 1.12.3 的记忆正文准备去重。

## 真机证据

2026-10-20 的 1.12.3 安装后复测中，手机启动成功，但稍后进程退出。设备日志在 10:15:50 明确记录 `runningboard / 0x2182BAD2`：等待应用释放 `Shared Background Assertion` 超时，系统以信号 9 终止进程，`isUserKill=0`。因此不能把此前启动命令成功作为持续运行验收，也不能将退出归因于用户关闭应用。后台任务名称被系统隐去，日志不能单独确定具体业务任务。

1.12.3 手机与手表均覆盖安装并启动成功；手机版本回读为 1.12.3。手表启动后两次版本查询遇到开发隧道 `RemotePairingError/1001`。手机资料库身份不变，安装前 2,893 个录音片段全部保留，后续快照为 2,904 个。两次资源采样因进程已结束而没有有效样本，不作为性能改善证据。

## 代码修正

核对 UIKit 后台任务后发现，录音接收、自动记忆、聊天回复和前台转录延续这四条路径都把到期释放放进异步 `Task`；转录还会先等待持久取消完成。系统允许到期回调同步清理，但回调返回后不保证继续执行异步清理。[Apple 的接口约定](https://developer.apple.com/documentation/uikit/uiapplication/beginbackgroundtask(expirationhandler:))要求在到期时明确结束任务，否则应用会被终止。

- 四条 UIKit 到期路径现在在回调返回前调用 `endBackgroundTask`，且先清除本地标识，避免重复释放。
- 转录的持久取消继续异步完成。取消完成前仍禁止重新取得转录延续任务；旧回调通过代际校验不能影响新任务。
- 聊天在释放有限执行权后，再检查是否已进入前台或取得独立的持续后台任务，避免迟到取消停止已经获得新执行权的请求。
- 自动记忆先释放执行权，再取消当前工作；原队列仍保留未完成任务。

本次不调整正常后台处理频率、不增加固定的后台时长，也不修改原音或转录清理策略。
