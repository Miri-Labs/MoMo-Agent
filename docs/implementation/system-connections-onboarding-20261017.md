# 系统与健康：层级和首次连接

基线 `8ec2e18`，任务分支 `codex/system-connections-onboarding`。用户指出设置页面将按钮与文案混在一起，并要求首次连接时完成默认位置设置。

## 页面与交互

- 功能名使用主文字；能力范围、连接状态和保存位置使用次级文字。未连接显示实底“连接”，已连接显示次级“管理”。
- 日历与提醒事项首次连接先申请系统权限，然后在同一流程中选择可写入的日历或列表。点击“完成连接”时，一次保存启用状态与默认位置。
- 系统授权在打开 App 的连接弹层之前申请，避免两层呈现相互竞争。返回后显示候选位置或权限恢复入口。
- 仅有一个可写入位置时预选该位置，用户仍需确认。多个位置不擅自选第一项；只有只读位置时解释如何在系统 App 中准备可写入位置。
- 取消流程不会打开 Agent 的能力开关。系统授权与 App 内启用分别处理；关闭流程不会撤回用户刚授予的系统权限。
- 管理页可修改保存位置或断开连接。断开停止 App 内访问，保留系统中已经创建的事项。
- 旧连接缺少默认位置，或原位置被删除时，显示“完成设置”。完成前不展示虚假的有效保存位置。
- 闹钟明确只管理 MoMo 创建的闹钟，无默认保存位置选择。
- 健康使用开关，并保留首次启用时的数据范围和 AI 用途说明。设置页只读启用状态，打开“查看近 7 天健康摘要”才查询明细。
- 行动记录从独立入口查看，不再在设置首页展开 50 条结果。

复用现有系统字体、中性配色和原生列表、导航、开关。视觉依据为用户截图、项目 HANDOFF 与已有设置组件；本次新增的连接流程不冒称旧 Pen 中已经包含。

## 状态与边界

`connectionTargets` 只取得系统授权和可写入候选位置，不启用 Agent 的访问。`connect` 重新读取候选位置后校验选择，在一次偏好写入中提交启用状态和默认位置。

| 条件 | 行为 |
|---|---|
| 进入设置页 | 不请求系统授权，不主动拉健康明细 |
| 授权被拒绝 | 提示在 iPhone 设置中允许访问，保留重新读取入口 |
| 用户在授权或位置选择期间取消 | 不启用连接，不保存新的默认位置 |
| 多个可写入位置 | 必须明确选择后才能完成 |
| 只有只读位置或没有位置 | 禁止完成，说明准备可写入位置的方法 |
| 选中的位置已删除或属于另一种能力 | 保存失败，不改动已有连接设置 |
| 授权返回前连接状态已变化 | 按连接版本拒绝迟到结果 |
| 改位置过程中失去权限 | 不覆盖之前保存的位置 |
| App 重启 | 从持久偏好恢复连接与默认位置 |

协议继续使用现有 opaque ref，原生标识不进入模型输出。工具创建日程／待办时继续明确携带位置 ref，列表中的 `userDefault` 标识反映已保存的选择。

## 验证

- `SystemActionTests` 的 15 项回归全部通过，覆盖启用与默认值一起持久化、多位置明确选择、只读过滤、失效或跨能力位置、取消与断开时的迟到授权，以及原有幂等、冲突和失败核对逻辑。日志：`tmp_agent_output/20261017-system-connections/package-tests-final.log`。
- iPhone 模拟器构建通过。最终 `settings-final.xcresult`：UI 3 项通过、闹钟成功授权路径 1 项跳过；原生日历与提醒事项 2 项通过、闹钟原生调度 1 项跳过，没有失败。
- 日历、提醒事项 UI 均验证取消后未连接，再次选择位置并完成连接、显示管理入口、进入管理并断开。健康 UI 验证初始关闭、先显示数据用途说明、取消后仍关闭。截图位于同目录的 `final-attachments/`。
- UI 使用系统默认字号、深色模式和专用 iPhone 17 Pro 模拟器。仅测试该模拟器中的权限和测试自建事项，不改动已连接手机或手表。
- 模拟器的原生 AlarmKit 授权持续返回拒绝。界面验证禁用完成连接、显示前往设置入口、取消后仍未连接；成功授权后的闹钟连接与调度不能记为通过，需要在可授权的设备上验收。相关用例明确跳过该成功路径。
- 最终原生 EventKit 回归使用专用模拟器上预先授予的日历、提醒事项权限，以单独验证默认位置与真实读写。授权弹窗交互和 App 内连接开关分别验证。
- 合入远端 main `25fbbf3` 的抽屉手势改动后，重新构建并运行日历完整连接流程、健康首次说明两项 UI 验证，均通过。结果：`merged-main-settings.xcresult`。本轮未安装到实体手机或手表。
