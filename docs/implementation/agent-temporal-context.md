# Agent 请求时间与近期上下文

2026-10-14。本轮冻结并实现以下软件契约，新增固定时钟测试；Xcode 27 / Swift 6.4 下完整共享包回归已通过。本文不代表 J09 的真实模型时间语义或设备验收通过。

## 时间基准

- 新逻辑请求首次准入时，将绝对时刻和设备 IANA 时区写入 `SessionMetadata.contextClock`。同一请求的工具循环、显式重试和重启恢复沿用该快照；新请求重新取值。
- 正式 `PiAgentHost.submit` 在调用入口捕获时钟。内部 provider 构造入口支持 `contextClock` 依赖注入，让固定时钟穿过正式 Pi/AssistantModel 路径；普通 App 构造使用 `Date` 与设备当前时区，不增加环境变量或 UI 测试工具。
- `generatedAt` 表示这份请求的上下文时间基准，不是每次提示渲染的墙钟时间。`timeScope.before` 与其相同，所有自动时间窗口使用半开区间。
- “今天截至请求时”为请求时区公历自然日零点 `todayFrom` 到 `before`。`tomorrowFrom` 为下一自然日零点，通过 `Calendar` 计算，不加固定 86,400 秒；夏令时日可能是 23 或 25 小时。
- 旧版本待重试任务没有原请求时间/时区时，首次恢复只记录检索时间，并设置 `originalRequestTimeKnown=false`。正式提示要求保留旧请求中相对日期的歧义，不能把恢复当天冒充原请求当天。
- 用户当前请求的相对日期与录音原文的相对日期分开解释。录音里的“明天”不随用户今天重听而移动。逐段 `recordedAt` 来自原音清单的 epoch anchor 加源帧偏移，不能使用转录修订时间替代。
- 模型可见的上下文与工具 JSON 使用 `AgentJSON`，按冻结的请求时区输出带偏移的 ISO 8601 日期。例如 `09:58Z` 在上海请求中输出 `17:58+08:00`，夏令时偏移按各日期计算。绝对时刻、毫秒精度、来源和持久 `WireJSON` 都不变；这是当前请求下的表示，不补出录音发生时未知的时区。

## 自动范围、排序与预算

| 项目 | 规则 |
| --- | --- |
| 自动近期窗口 | `[请求时刻 - 2 小时, 请求时刻)`；两小时是自动提供资料的技术窗口，不把用户的模糊“刚才”强行定义为两小时 |
| 目录 | 最多 8 个开始时间早于请求的会话；按既有稳定录音目录顺序。未来起点会话不能挤掉过去会话 |
| 逐段筛选 | 在目录内按逐段实际录音时间过滤；会话开始于前一天或更早不自动排除，因此可覆盖跨午夜与长会话的近期尾部 |
| 自动资料数 | 按各会话最新合格段落时间降序取 3 份；同刻按 session UUID 稳定排序 |
| 自动段落顺序 | 每份最多最新 12 段，最新优先；同刻先按 span UUID 稳定排序。预算耗尽时不以较旧段落挤掉最新段落 |
| 显式选定录音 | 优先提供精确选定 span，其后为该录音正文顺序中的其他段落，总计最多 12 段；不扩大总预算。标记 `contextRole=selected`，保留旧日期或异常未来日期 |
| 全局正文预算 | 最多 20 段、10,000 UTF-8 字节；单段最多 1,200 UTF-8 字节，不切断字符 |
| 角色与遗漏 | 自动段落为 `automatic_recent`，工具结果为 `requested_tool`。目录有下一页、超过 3 份/12 段或全局预算时标记 `omittedRecentPassages`；不能据此声称已读完全天 |

三份自动资料之外，仍允许一份用户显式选定资料先占预算，保持既有选定来源语义。来源准入、版本检查、删除屏障和最多 128 个已暴露来源的限制保持有效。新增时间元数据不授权更多工具、原音上传或读取整库。

文本与时间通过 Archive 的 `transcriptSnapshot` 在同一次 actor 执行中读取，避免两次等待之间的 ASR 追加造成版本不一致。搜索结果的来源则通过 `transcriptLocations(sources:)` 复用已有 `validateSources` 契约：允许新版本仅追加文字且所引用 span 完全未变，仍拒绝修订代次变化、删除或引用正文变动；随后 `policy.expose` 在出站前再次校验并登记来源。

Pi 在提示片段渲染失败时会保留上一次显示的片段。本 App 对近期上下文渲染错误明确将请求置为失败，让正式 `beforeRequest` 校验拒绝模型调用。首轮真实 Pi 回归进一步发现 scheduler 会吞掉 hook 异常，因此固定 vendor 的 generation 补丁还必须在 hook 回调外检查准备失败，以安全固定文案结算并在 provider 调用前返回；源码及重建方式见 `Vendor/PiDurableKit/UPSTREAM.md`。不能在新请求中继续发送上次的日期或上下文。文件恢复后由用户显式重试，保留原逻辑请求时钟。

## 日期工具的实际边界

`list_recordings` 和 `search_transcripts` 的 `from` / `before` 过滤的是 **录音会话开始时间**。跨午夜会话中今天的段落，可能被 `from=今天零点` 排除。这次没有将 Archive 分页协议偷偷改成逐段过滤。

工具说明、系统提示和 `timeScope.archiveDateFilters` 明确这一区别。按需查询今天内容时，需要放宽会话起点范围、分页定位相关会话，再用 `read_transcript` / `search_transcripts` 返回的逐段 `recordedAt` 判断是否属于今天。二者现在都会返回真实逐段时间，既有来源版本检查继续在结果出站前执行。目录未覆盖更老的长会话时，自动上下文仍可能遗漏；该限制明确保留，不能把空摘录当成“没有发生”。

`TranscriptSpanLocation` 当前只导出绝对时间，不导出录音发生时的 IANA 时区。底层清单中的 epoch UTC offset 也不能单独证明旅行或夏令时变更后的完整时区规则。因此当前实现要求在缺少原说话时区、未来锚点或日期语义不明时保留待确认；不能仅用用户现时区为旧录音补出确定日程。是否进一步向 Agent 提供原采集 offset/时区，是后续接口扩展，不能视为本轮已实现。

## 验证范围

新增 `Packages/MoMoAgentKit/Tests/MoMoAgentTests/TemporalContextTests.swift`，共 10 个命名用例，其中追加/修订/删除用例含 3 个参数场景：

- 固定时钟的两小时上下边界、未来段落排除与未来会话不挤占目录。
- 上海 00:10 的跨午夜录音，同一会话昨天和今天段落保留真实日期；同时锁定 Archive 日期过滤确实按会话起点的事实。
- 同一绝对时刻在上海/洛杉矶的不同本地日期、23/25 小时夏令时日、非法时区/非有限日期拒绝。
- 旧选定录音的精确 span 优先、原日期、原预算和修订后拒绝。
- 长会话的近期尾部排序、3 份与 8 份目录限制及遗漏标识。
- 跨午夜/换时区/重启的同请求时间不漂移，新请求刷新；旧版缺少时钟时明确未知。
- 正式 Pi + Archive 工具链的逐段时间输出；模型响应受控，不计作真实 OpenRouter 语义质量成绩。
- 模型侧日期编码覆盖上海跨午夜、尼泊尔 45 分钟偏移、洛杉矶回拨时重复的 01:30、UTC 和毫秒；解码仍是同一时刻，持久 UTC 文档字节不变。正式 Pi 的提示与读稿、搜索结果均检查本地日期和偏移。
- 检索完成后发生 ASR 正常追加，旧引用仍能携原时间暴露；相同边界的修订、删除分别拒绝。
- 正式 Pi 先成功渲染旧日期，新请求发生无关新文档文件冲突时，不能以旧片段调用 provider；恢复文件并重启后重试，provider 看到原请求日期而不是重试当天。

既有 `SelectedSourceTests` 的两项前置用例也改为固定时钟，显式断言近期资料非空并与旧选定来源共存，避免“recent fixture 已过两小时”时空上下文仍能通过测试。

固定日期夹具审查还覆盖既有 Agent/宿主测试及 Tools。`AgentTests` 的日期等价/分页用例冻结请求在两条录音后 60 秒，逐轮检查正式 Pi 提示中的两条自动来源。`LifeContextReplay` 保留原 ASR 夹具日期，显式将请求时钟冻结在最后一个实际段落起点后 60 秒，确认跨文件来源进入自动上下文并保存请求时钟/来源证据；这份预发送证据不冒充实际 HTTP 截获。`LiveAgentScenario` 的固定合成质量集由其测试入口统一提供时钟，真实 ASR 案例则显式生成近期回放清单并在证据中标识回放时间，不更改通用固定夹具默认值或已存在档案；必须断言来源进入自动上下文，不能依赖模型自行补搜索掩盖空摘录。其余空档案的草稿/鉴权/HTTP 故障宿主测试有意测试无录音场景；当前时钟构造的普通夹具、仅 Archive/录音/状态协议的固定日期用例无需修改时间窗口。
