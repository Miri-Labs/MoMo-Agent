# 波形游标偶发停顿修复

用户反馈：波形卡顿已经减少，但仍会偶发停一下。此修复保持现有点阵波形和原音格式，不新增波形生成进度条。

播放进度原来每 250 毫秒会在同一循环等待 ArchiveStore 的资料有效性检查。资料库处理其他录音时，原生播放器继续播放，游标刷新却会等待。现在原生进度按原来的 40 毫秒间隔读取，资料检查由一个独立任务串行执行，每次检查完成后等待 250 毫秒再继续。暂停、停止、切段和替换目标时取消旧检查；已取消检查的迟到错误不能停止新播放。播放、定位、恢复及切段前的完整校验保持不变；后台检查发现删除或失效仍会停止原音。

冷缓存波形还有一处重复工作：每解码一个分片，都会重新核对整轮录音的全部文件。32 个分片实际产生 1,088 次文件检查，基线用时约 7.26 秒；缓存命中时为 64 次、约 0.40 秒。修复后每个解码分片只核对自身，仍保留开始和结束时的完整校验。同一模拟器回归中，32 个分片的冷缓存检查降至 96 次，用时约 0.38 秒；已有缓存为 64 次、约 0.15 秒。操作量下降约 91%，计时会受系统负载和文件缓存影响，不视作手机耗时保证。

完整文件信息扫描在每个文件检查完成后让出 ArchiveStore。SQLite 查询已返回普通数据，文件句柄已关闭，不跨让出点持有 SQL statement、事务或音频租约。解码仍一次租用一个原音文件，缓存仍限于 64 × 256 个 RMS 值；不提高后台并发，不压缩或改写原音。

回归使用真实 SQLite、AVAudioFile 和 AVAudioPlayer，以及公开语音夹具。长录音回归约束冷缓存检查量并比对冷热缓存结果；资料库争用回归在测试扩展内占用真实 ArchiveStore 0.9 秒，检查 650 毫秒内游标持续推进，然后删除原音并确认播放停止。另覆盖单分片归属校验、文件时间变化、损坏 manifest、原音缺失、删除和取消扫描。

最终代码的 5 项原生波形回归通过，覆盖长录音、持久缓存、准确引用范围、取消后租约释放及损坏原音；最终计时为冷缓存约 0.32 秒、已有缓存约 0.17 秒。资料库相关 31 项 SwiftPM 测试通过，包含新增两项原音身份与取消回归；Release 包验证器自身的 20 项测试通过。

原生播放争用回归被模拟器音频输出阻塞：AudioQueue 两次报告 15 秒初始化超时，播放器未能启动，测试在进入资料库占用之前失败。重启本轮专用模拟器后仍未通过；未把这项失败计入通过数。游标与检查任务的拆分已编译，资料库繁忙时的真实音频播放、删除后停止及手机上的偶发卡顿仍需真机验证。

签名 Release 构建通过，27 项实际包检查全部通过，包含新调试计数器未进入发布包、手机与内嵌 Watch/Widget 版本一致及模型资源校验。深度严格签名检查通过。版本为 **1.6.2**，内部构建序号为 26，唯一版本入口仍为 `Config/App.xcconfig`。

本轮证据目录为 `tmp_agent_output/20261018-waveform-hitch/`：`baseline.log` 保存原始 1,088 次检查的失败回归，`waveform-final.log` 与对应 xcresult 保存最终代码 5 项波形回归，`archive-tests-02.log` 保存资料库测试结果，`clock-final.log` 保存音频输出超时失败。两台本轮专用模拟器均在验证后删除。模拟器回归不等于用户手机上偶发卡顿已经完成实测验收。
