# 手表点阵全屏宽度与唤醒连续性

用户在真机更新后再次指出两侧波形没有铺开，且每次唤醒都从右侧重新累积。此修复接续 `3d70be3` 的手机响应修复，不把“手机 Watch App 显示已安装”视为腕上视觉验收。

## 原因与修改

- [前一轮](watch-waveform-wake.md)修复了 Canvas 内部的横向点距，但其离屏测试没有覆盖实际 `NavigationStack` 安全区及整页 8pt 内距。现在绘图区忽略水平安全区，状态文字和底部按钮各自保留内距，点阵不再跟随这些控件缩窄。顶部时钟、更多按钮和垂直安全区保留。
- 旧 `CaptureMeter` 在回调间隔达到整个 29 列窗口时会抹除所有历史；旧 View 在 inactive 时还会直接绘制空数组。这两层都可能让真实唤醒体验仍像从右边重新进入。现在 meter 在 inactive 时冻结对外发布的画面、继续维护有界样本；恢复 active 时一次公布现有历史。跨长回调间隔只追加本次真实观测，不清空左侧、不补造期间音频。此点阵表达最近观测的声音包络，没有带时间轴，不宣称这段时间采样连续。
- 开始一段新录音仍重置历史；暂停、结束、失败仍显示静态非采集状态。录音代次检查、采样编码、断点恢复、WatchConnectivity 和录音账本不改。
- 两端构建号升到 **2**；Info.plist 改为读取 `CURRENT_PROJECT_VERSION`，不再无论何次构建都写死为 1。手表“更多”显示 `版本 1.0 (2)`，用于直接核对腕上运行版本。

## 验证

证据保存在 `tmp_agent_output/watch-waveform-20261016/`。新增 UI 用例启动实际 Watch App、截取包含导航安全区的整个屏幕，检查中央绘图区左右边缘；不是只渲染一个指定宽度的 Canvas。宿主测试覆盖隐藏期间不发布、长回调间隔后历史不清空、重复前台、100ms 桶、重置及原来的 Canvas 宽度。

`full-width-and-wake.xcresult`：6 项宿主测试与 1 项完整屏幕 UI 测试全部通过，0 跳过、无 xcresult runtime warning。截图已人工查看，左右点阵到屏幕边缘均小于 4pt；测试结束后关闭并删除本轮专用模拟器。

全部使用系统默认字号与独立未配对 Watch 模拟器；本轮定向测试不打开麦克风，不录制或转发用户声音。模拟器与控制时钟能验证代码契约，物理手表放腕/抬腕、后台音频连续性和功耗仍需分别判断，不能由这组显示测试代替。
