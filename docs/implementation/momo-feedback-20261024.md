# MoMo 聊天反馈修复 · 1.30.1

用户要求直接完成此前在 MoMo 中提出的修改。以 Beta 私有 Hermes 的用户消息为依据，确认三项：输入时跟随到底部、手机消息桌面不可见、发送后长时间无回复。未采用 MoMo 对“已派给 Codex”的描述作为完成证据。

## 实现

- 两端共用 `ClientComposer`，获得焦点或编辑时发出滚到底部请求。WebKit 独立处理滚动命令，不因每个字符重建消息 DOM；视口因多行输入或键盘改变时继续跟随。未编辑时保留历史阅读位置，纯原生降级界面也接入该请求。
- 旧版手机、桌面各用独立 `momo-UUID` 会话，新版共用 Mac 持久消息流。Mac 现在从同一认证范围的原生 API admissions 回填旧会话，并读取后续到达的旧版手机消息。排除转录、其他认证范围、非 API 会话和隐藏消息。以原生消息 ID 去重；保留递增同步游标，展示时将旧记录放在共享会话之前。本地 journal 按 run ID 去重。历史读取不重新提交任务、不产生通知、不自动接管旧会话的执行。
- 慢响应源于请求路径差异：登录探测原先使用 SDK 默认系统代理，Hermes 正式请求只读取代理环境变量；Finder 启动的桌面进程未传入这些变量，导致正式请求直连超时。MoMo 启动器现在在没有显式代理环境时读取 macOS 已配置的 HTTP/HTTPS 代理与例外，始终绕过 localhost。显式代理及 `NO_PROXY` 优先。登录探测也复用 Hermes 的 HTTP 客户端，避免“测试通、正式请求不通”。未更换模型或缩短超时掩盖问题。

## 验收

- Python 31 项通过：包含真实 SessionDB 的旧会话回填、后续消息、稳定游标、不重复执行与认证范围隔离；环境变量优先级和本机绕过；模型探测协议。
- Swift 客户端 50 项通过：双设备读取、分页和重开恢复；迟到的历史回填不倒退游标、不重新提交。
- 渲染 core 20 项及多语言检查通过。真实 WebKit 验证历史位置保留、开始输入回到底部、多次编辑不替换 DOM、视口缩小继续跟随。
- 真实 Beta 数据副本回填 34 条旧消息，两端会话都包含在内；三条反馈均可见，无重复。安装后在桌面界面再次确认。
