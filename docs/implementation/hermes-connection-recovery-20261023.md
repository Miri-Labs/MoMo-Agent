# 1.29.5：连接恢复与回复读取失败

## 现场证据

2026-10-23 19:02 手机 Beta 的新消息没有进入 Mac。手机任务日志中，16:45–16:46 的三条已接收任务仍显示 running / queued，并保留“无法连接服务器”或“错误的URL”；Mac 的同一 run ID 已于 16:47–16:48 完成。手机内置 Tailscale 日志同时出现 socket is not connected / broken pipe。重启手机 Beta 后，这三条原 run 的完整结果自动取回，未重新提交任务。

Mac 本机 Agent、访问服务和 Tailscale 入口在线；从 Mac Beta 聊天界面发出的独立诊断收到了“连接正常”。手机和 Mac 的本地任务日志使用不同 session ID，因此桌面当前会话看不到手机消息是另一个已有的会话同步缺口，本次不以连接恢复冒充聊天同步已经完成。

现场记录未保留每次 URLSession 请求的底层错误链，不能精确断言首次断线由哪一个系统事件触发。代码中已确认的恢复缺口包括：返回前台继续使用可能失效的 SOCKS listener；badURL / timeout 不触发重建；并发创建会话和关闭节点没有完整隔离；已接收任务读取失败不会在聊天界面显式提示。

## 修改

- 手机回到前台，下一次私网请求重建内嵌节点及 URLSession，沿用持久登录和配对身份。
- 关闭完成后再启动下一节点；并发读取共享一个 URLSession，创建期间身份变化则取消旧请求。旧会话的迟到错误不影响新会话。
- 已通过私网地址校验的请求出现 badURL、timeout、连接断开等错误时，下一次请求重建连接。继续禁止普通网络回退和重定向。
- 两端聊天在已接收任务读取失败时显示重连/重试入口，停止把该任务呈现为持续工作。重试只 GET 原 run；无回执的失败消息仍由用户显式重试，继续使用原幂等键和保留期限。
- 本次不更改 Mac 服务、用户任务、账号、授权或任务执行语义。
