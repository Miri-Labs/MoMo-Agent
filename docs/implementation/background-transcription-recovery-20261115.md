# 手机后台转录持续执行与自动恢复（0.6.23）

用户要求锁屏、离开转录页面后仍自动处理积压，失败后自行接续。保持 App 在前台不是交付条件。本次手机开发连接不可用，尚未取得用户这次失败的真机日志；以下是源码确认的问题，不能据此断定这次现场失败的唯一原因。

## 已确认问题与修改

- 持续后台任务原来在正常温度下 105–130 秒、较高温度下 70–90 秒主动结束。移除这一固定时间上限；保留系统到期回调、低电量/严重热压力限制、CPU 节流、增量落盘与取消屏障。获得的执行权有效时继续处理，不能为了避免系统显示失败而提前宣告一小段完成。
- 原进度按约 120 秒的切片计算，并以定时心跳增加进度；多小时任务会过早逼近满格。改为整批真实已分析/已完成覆盖率，移除时间驱动的虚假进度与轮询，只有批次真正结束才报告完成。
- 自动任务原来最多执行一个后续阶段，即使仍有执行时间也会结束。现在在同一系统授权内持续领取后续批次，全部完成后才归还；阶段代次隔离迟到的入场返回和重复回调，防止取消到错误的任务。
- 持续任务也在开始时预约后续自动处理机会；结束回调在报错时同样补排，用户暂停除外。后台申请失败按 5、10、20 秒递增重试，最多间隔 5 分钟；取消会撤销重试。此计时器只能使用系统已有执行时间，不能唤醒被挂起的进程。
- 新系统授权到达时重新读取资源条件；电量/热状态恢复且仍有后台执行时间时，检查已有积压并尝试接续，无需等待新录音。错误文案不再要求用户返回转录页。

平台依据：[Apple WWDC25：Finish tasks in the background](https://developer.apple.com/videos/play/wwdc2025/227/)。`BGContinuedProcessingTask` 用于用户明确发起的任务；自动积压处理仍使用 `BGProcessingTask` 和收件时有限的执行时间，不自动伪造新的用户发起任务。iOS 仍决定调度时间，不能承诺持续常驻或固定时间清空积压。

## 验证

- Mac 回放：16 项定向检查通过，覆盖整批真实进度、多批次接续、迟到回调隔离、后台申请退避/取消及原有收件执行权回归。
- iPhone 模拟器宿主集成：39 项通过，包括真实 SQLite / VAD / ASR 在中断恢复后不进入前台也能完成原批次。首轮新增共享测试遇到宿主与测试模块同名类型冲突，显式限定类型后通过；未更改生产类型或放宽断言。
- Release 构建通过；本地覆盖升级身份的 29 项包检查通过，手机、内嵌手表与 Widget 均为 0.6.23，手机/手表严格签名校验通过，独立与内嵌手表包一致。默认公开 Bundle ID 检查不适用于本地沿用的旧身份，按仓库既有 `local-upgrade` 规则核验，未修改身份或清理用户资料。
- 真机锁屏、实际 8 小时录音吞吐和本次现场积压：尚未验收，设备开发连接当前不可用。8 小时进度用例是覆盖率模型测试，不是 8 小时真实录音性能测试。
