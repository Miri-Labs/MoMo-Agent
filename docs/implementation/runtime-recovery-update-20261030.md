# 已送达后无回复与 Mac 统一更新入口

现场消息已持久保存，但旧 gateway 在数小时前收到 SIGTERM 后一直处于 `runtime_draining`。关闭日志报 `ModuleNotFoundError: gateway.session_llm_oneshot`；旧后台跨越了 App 替换过程。源码和当前安装包都有该模块，不能解释为未打包 Python。旧进程仍响应 capabilities，因此界面误以为可以正常处理输入。

恢复时只终止已核对命令行、数据路径和孤儿身份的旧 gateway。Mac 自动恢复服务，原 pending 输入随后被原生执行队列接纳，真实模型生成回复；没有重发用户消息或修改其记录。

修复包括：

- Hermes 关闭失败或被取消时保留线程 watchdog，防止永久停在拒绝新输入的关闭状态；正常完成关闭才撤销 watchdog。
- Mac 启动回收前次后台时，异步等待 35 秒，仍存活则重新核对进程身份并终止；确认退出才删除 PID 文件，避免失去旧服务所有权记录。
- 通用设置增加唯一的「应用更新 · 获取更新」入口，打开 GitHub 最新安装包。Python、Hermes 与连接依赖随完整 App 更新，不做独立组件下载器。
- 更新操作先确认旧 App 和后台全部退出，再替换完整已签名 App；保留原 Bundle ID、签名要求、用户身份、模型配置及配对数据。

公开版本 0.0.1，内部构建 17。Apple Silicon 包包含 Python 3.14.7 和 SQLite 3.53.1。当前本地 Apple Development 签名，未做 Developer ID 公证。

验证：18 项运行环境测试通过；关闭与 watchdog 定向测试 6 项通过、1 项跳过。Mac Release 构建通过；真实安装包禁网、隔离开发工具的初始化与重复初始化、原生依赖及关闭路径模块导入、严格签名检查通过。恢复前滞留消息的回复已在 Mac 界面出现。更新后身份/密钥/模型配置哈希一致，8 条配对保留，Agent 在线、隧道连接。新版实际通过 Mac 输入框发送自检消息，收到模型的「连接正常」并显示「回复已完成」；通用设置的「已内置」和「获取更新」在实际界面可见。手机端实际显示和跨网消息未在本次验证。
