## 实现

- 新 `GET /momo/v1/conversation/snapshot` 原子读取对话状态与事件游标；初始最近 100 条之外的历史保留明确分页并独立补齐，不阻塞发消息。
- 新 `GET /momo/v1/conversation/subscribe?after=N` 是整段对话的 SSE。任务完成后继续保持；新消息、公共文字增量、完整正文、任务/授权和后台完成状态复用它。
- 发送使用原 JSON POST 和原 operation ID。回执丢失不导致重跑；先到的推送结果不能被晚到的排队回执覆盖。旧版客户端的 POST SSE 仅保留过渡兼容，新版优先使用 `conversation_events` 契约。
- SQLite 是事件事实来源，消息和事件同事务提交。进程内通知只唤醒查询；订阅先登记再查询，避免快照/建联窗口漏事件。已完成任务清理临时文字增量，持久正文和递增游标保留。
- 客户端先应用状态并原子写盘，再确认游标；重放按事件游标和消息 ID 去重。一个 RemoteTaskStore 拥有一个前台订阅，切后台取消订阅但不停止 Mac 任务。账号、实例及订阅代次约束旧回调。
- 心跳 15 秒，45 秒无数据后重连；250ms–5s 退避并尊重 Retry-After，401 停止并要求恢复配对。缓存游标无效时获取一致快照；缓冲溢出从已应用位置恢复。旧 run GET 仅用于旧服务端兼容。
- 两端继续使用内嵌 Tailscale 和原配对鉴权；交互池与同步池隔离。Hermes 的执行、记忆与结果归属不变。

## 1.34.16：短暂发送失败与迟到回执

真实手机记录：2026-10-27 11:40:35 的消息 POST 在约 2.38ms 结束，没有 HTTP 响应；3.79s 后自动重投原 operation，648ms 收到 200。Mac 已执行并完成，手机最终保存了正文。1.34.15 未记录该失败的 NSError code，不能断言就是 badURL。启动时另有一组 401，之后请求恢复 200；鉴权拒绝不作为普通网络重试处理。

修复：可重试发送保持持久待确认状态，不显示确定未送达的红色标记。网络错误在幂等保证有效时立即重试同一 operation 一次；仍失败再退避，遵守 Retry-After 和保存期限。推送先确认接收后，迟到的 POST 错误不能改写该任务；新响应之后到达的旧请求错误不再把整体连接降为离线。badURL 只淘汰对应连接池，保留节点、配对和其他活跃请求。保存有界的错误码和持续订阅指标，便于继续核对真机问题。没有新增聊天连接提示或重配流程。

回归覆盖一次立即重试、连续两次失败后重开恢复、回执丢失但推送已确认、503 退避、过期禁止重投、401 停止、健康代理下坏连接池重建、旧错误不破坏新连接。新手机版本的实际连接仍需安装后单独验收。
