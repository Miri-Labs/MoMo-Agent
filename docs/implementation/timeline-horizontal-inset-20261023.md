# 转录时间线偶发向左偏移

后续：10 月 27 日在录音重新分组后的阅读位置恢复路径复现了同样的 24pt 偏移，见[后续修复与回归](timeline-reading-inset-20261027.md)。以下保留当时验证范围，不代表所有触发路径均已解决。

用户截图中，手表状态卡片保持正常边距，下面的时间线圆点却贴近屏幕左边。基线为 `068666b0`。短列表的缓存加载测试读到纵向 `UIScrollView.contentOffset.x = 24`，其左侧 inset 为 0；横向偏移正好抵消了时间线的 24pt 留白。

日期分页原来同时使用 `scrollPosition(id:)` 和包住嵌套滚动视图的 `ScrollViewReader`。布局尺寸或日期范围变化时，后者用 `.leading` 主动定位。Apple 的 [ScrollViewProxy 文档](https://developer.apple.com/documentation/swiftui/scrollviewproxy/scrollto(_:anchor:)) 说明它会扫描范围内的滚动视图；这条定位路径与每一天独立的纵向阅读位置共存。此前仅调整日期页宽度，仍保留了这条路径。

本次将日期定位统一为直接绑定外层横向分页的 `ScrollPosition`，移除外层 `ScrollViewReader`。日期按钮、左右滑动、首次进入、视口变化和发现更早日期都使用同一份分页位置。每一天继续保留自己的纵向阅读位置、24pt 留白和首次定位到最新转录的行为。

## 验证

- 增加三条转录的首次加载、缓存加载及历史日期场景，同时检查纵向容器没有横向偏移、时间文字的实际显示位置，以及短列表顶部和长列表底部位置。
- 扩展界面用例：左右滑动日期、日期按钮切换，以及在历史日期切换聊天/转录标签后，检查可见转录行两侧仍有 24pt 留白。
- iOS 模拟器上 5 项原生布局测试通过，覆盖短列表异步加载、缓存加载、历史日期及长列表的首次底部定位。修复后纵向容器的横向偏移为 0，时间文字距左侧约 50pt。
- 2 项界面测试通过，覆盖首次进入、刷新、聊天/转录标签切换、左右滑动日期及日期按钮导航；转录行两侧保留 24pt 留白，返回日期后保留阅读位置。阅读位置断言直接检查元素坐标，避免反复查询可点击状态时的自动化工具错误。
- 版本更新为 `1.19.14`。本轮未安装真机，手机上的画面尚未验收。
