# Beta 1.34.6：发送延迟、立即等待与聊天排版恢复

## 现场证据

用户 14:04 的“嗨”已到达 Mac，模型请求持续出现 `APIConnectionError / ConnectError`，约 5 分钟后失败，输入/输出 token 均为 0。Mac Agent 与 Tailscale 入口仍在线，因此不能把这次失败解释为手机和 Mac 断联。现场随后模型连接恢复，真实 Hermes 请求已回复“连接正常”。

手机初始记录停在共享序号 64、最后任务 running；激活 Beta 后补到 67、该任务 failed，并收到自检回复。没有重放原任务。手机当次 WebKit 错误日志未能还原具体触发原因；现有实现确实将普通导航取消、JavaScript 错误和 WebKit 进程终止都永久切换成排版不可用。

## 修改

- WebKit 进程终止或 JS 执行异常后自动重载本地资源，重放最新 snapshot；保留消息与阅读位置数据。重载期间原文继续可见。
- 后台仅接收并保留最新 snapshot，回前台再恢复显示；忽略正常导航取消，丢弃旧文档异步回调，拆除视图时同步移除 bridge/delegate，避免销毁回调误伤新页面。
- 同一次持续失败只自动重载一次，仍失败保留原文和手动重载入口；回前台可重新尝试。
- 保留 Hermes 正常 API 重试，MoMo 默认不再增加五轮分钟级自动恢复。用户显式设置的 `agent.auto_recovery_cycles` 保留。
- 从 Hermes 持久结果提取失败类别，在现有 run error 中提供中文原因；不转发原始错误、URL 或凭据，不改变任务幂等与执行结果。
- 消息本地持久化后立即显示三点，不等 Mac 回执；排队状态仍显示。发送失败、权限等待、任务结束或完整回复到达时收起。SSE 不可用不取消游标拉取期间的等待提示。保留整条消息展示，本次未改成逐 token 展示。
- 新共享消息先投递，旧会话导入不再排在发送前；旧 outbox 的幂等迁移顺序不变。同一导入只保留一个在途请求。
- 已读上报按最大实际可见序号合并，同一时刻仅一个请求；成功后清理通知使用实际确认的序号。失败结果的可见回执按连接身份去重，不再每次渲染都发送。
- 前台预取能力契约，成功结果缓存 60 秒；发送仍检查幂等保证及原回执有效期。新增本地提交阶段时间和 Mac 首个公开正文 delta 的计时，日志不含消息内容、推理或凭据。

## TTFT 真机分段

2026-10-26，用户在同一台 iPhone 的 Beta 中发送“你好”；Mac 日志使用公开正文回调，协议首包、reasoning 事件和完整回复均不当作首 token。跨设备绝对时钟的差值为近似值，Mac 内部阶段使用单调时钟。

| 样本 | 手机创建 → Mac 回执 | Mac 接受 → 首个正文 | 手机创建 → 首个正文 |
| --- | ---: | ---: | ---: |
| 1.34.5，16:03 | 16.50 秒 | 3.60 秒 | 约 19.44 秒 |
| 1.34.6，刚进入后 16:12 | 7.34 秒 | 3.86 秒 | 约 11.00 秒 |
| 1.34.6，保持前台第一条 16:16 | 1.51 秒 | 4.38 秒 | 约 5.45 秒 |
| 1.34.6，保持前台第二条 16:17 | 0.80 秒 | 21.88 秒 | 约 22.16 秒 |

第一条现场样本在旧会话导入前后出现二十多次重复 `/read`，发送等待显著；1.34.6 的重复回执消失，连续发送进入提交只需约 30 毫秒。进入 App 后的样本仍有约 5.6 秒提交前等待，现有时间字段不能单独区分恢复、重试与主线程调度，不把它宣称为已消除。

最后一个慢样本在 Mac 侧明确发生了模型连接重试：16:17:07.879 建立请求；收到协议首事件后连续 12 秒没有 SSE；16:17:22.140 watchdog 断开，等待 2.79 秒重试；16:17:29.700 出现正文。此次延迟不是手机上传或消息排版。证据只能定位到 Mac 与模型之间的连接，不能进一步断言是代理、外网还是服务端原因。没有擅自切换模型、降低推理配置或关闭 Hermes 正常重试。
