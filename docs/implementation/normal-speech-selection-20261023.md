# 常规语音选择策略

日期：2026-10-23。代码版本：1.19.11。本轮修改代码，在 Mac 验证真实模型和生产转录协调器；未安装到设备，也未重跑手机历史。

## 目标与取舍

用户要求保留正常佩戴时可听清的对话、保持长语音连续，同时避免为微弱背景声投入过量计算。此前 11 分钟录音是按问题筛选的诊断样本，没有人工逐字标注，不能代表全天声音分布。绕过 VAD 后能生成文字，也不能证明其中有必须保留的有效语音。

1.19.10 的独立 WebRTC VAD 补检会把 200 毫秒的连续疑似语音扩展为整个 20 秒候选块。那批样本仍有 560 / 660 秒进入识别核心范围，扩大了处理量。本轮取消这层补检，由 sherpa-onnx 中的 Silero v6 决定语音范围。

不新增音量阈值，不对原音做增益或降噪。保留手机默认 VAD 阈值 0.25 和用户已有设置。响度不能单独代表可懂度，不能将此次未检出的片段直接标为“太弱”或“纯噪声”。

## 实现

- 移除 `SherpaVAD`、`VADContinuation` 和窗口规划器中的独立补检输入。未选中的范围提交非语音处理进度，不送 ASR。
- 保留 Silero 的连续状态、2 秒停顿合并、300 毫秒语句边缘、最长 20 秒核心窗口和最多 1 秒跨窗口上下文。保留时间戳归属、相邻结果对齐、原生时钟切换和空重复段处理。
- 新策略标识为 `silero6-speech-only-v3`。按新到旧继承 `selective-archive-v2`、`complete-coverage-v1` 和 v4 的已完成记录，避免升级重跑历史。
- 从 SwiftPM 产品、目标和依赖中移除 `MoMoAcousticVAD`，并排除 `AcousticActivity.swift`。自动安全检查阻止了删除旧源码，因此历史源码和许可仍保留在仓库。当前构建不包含该组件。
- 模型文件、量化方式、Core ML 接入、手表同步周期和输入框实时识别路径保持现有配置。

## 本轮结果

仍使用原来 11 段本地副本，每段 60 秒，在独立临时资料库中运行生产协调器。测试明确设置手机默认阈值 0.25，并记录实际阈值和策略指纹。未标注副本只提供诊断数据；不再把旧 ASR 输出字数当作召回率断言。

| 指标 | 本轮结果 |
| --- | ---: |
| 原音总时长 | 660 秒 |
| 选中核心范围 | 185.87 秒，28.2% |
| 跳过范围 | 474.13 秒，71.8% |
| 实际 ASR 输入，含上下文 | 193.87 秒，29.4% |
| 原生识别耗时 | 4.34 秒 |
| 协调器总耗时 | 8.89 秒 |

这是 Mac 上 sherpa CPU 识别的单轮诊断。上一轮测试使用库默认阈值 0.5，本轮对齐手机默认 0.25，因此不把两轮耗时差写成相同条件下的加速倍数。上述比例也不能换算为全天节电或手机每小时录音的处理时间。

## 验证与限制

本机轻量测试包直接链接仓库的语音、资料库和生产协调器源码，分批完成以下验证：

- 公开中文语句跨文件、跨识别窗口、跨两分钟任务，以及取消后恢复时，核对完整参考文字。
- 数字静音和非零背景噪声跳过 ASR，同时提交完整处理进度。
- 连续 VAD 状态复用、原生时钟切换、分页取消和已完成历史继承。
- 同一正常音量语句叠加背景噪声后，新路径与原有 Silero 切段路径的正文一致。该混合样本两条路径均把“开放”识别为“开饭”，而直接识别完整语句可得到“开放”。这是仍存在的切段上下文敏感问题，不能用这个用例宣称准确率提高；测试保留该已知差异。
- SwiftPM 清单中已没有补检产品或目标；新编译的测试程序和回放程序均没有 `fvad_` 或 `AcousticActivity` 符号。

回归覆盖了此次改动涉及的连续性、跳过范围和升级行为。尚未用带人工标注的全天录音验证漏检率，也未测量真机能耗。诊断结果保存在忽略目录 `tmp_agent_output/vad-normal-speech-20261023/`；个人录音和正文不提交到仓库。
