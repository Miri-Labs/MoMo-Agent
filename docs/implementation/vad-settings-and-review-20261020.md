# 语音检测阈值与临时数据修复

设置 → 高级设置 → 语音检测提供 VAD 阈值调节。手机默认使用 `0.25`，可选范围为 `0.05～0.95`，步长为 `0.05`。选择保存在手机本地，支持恢复默认值。数值越低，越容易检出轻声，也越可能把噪声当成语音。

## 设置生效方式

每批分析开始时读取一次阈值。正在分析的批次继续使用原值，下一批使用新值。阈值变化时，在既有串行分析队列中更换 VAD 实例。识别模型、已注册的转录窗口和已生成的文字继续保留。

资料库原有的配置指纹与检查点身份保持稳定。手机启动时由 `PhoneSpeechSettings` 将实际默认值或已保存的选择传给引擎。共享 `SpeechConfiguration` 的旧默认参数保留，用于兼容已有档案身份；不能直接修改它来实现手机偏好，否则会触发历史范围重新分析。每次分析的诊断记录另存实际 `vadThreshold`。

## 10 月 19、20 日的临时数据修复

用户明确要求按日期补查仅用于本次数据修复。已移除日期选择、补查按钮及页面回调；高级设置只保留阈值调节。资料库补查方法与协调器入口仅在 `DEBUG` 下编译，Release 包检查将这些符号列为禁止项。

临时维护代码按以下步骤处理：

1. 协调器取消当前普通分析任务并释放读取租约。用户暂停状态保持不变，有独立系统批次运行时返回忙碌状态。
2. Archive 按音频实际时间计算范围，支持跨午夜的长会话。目录日期不作为选择依据。
3. 在一个事务中重新开放仍保留原音的 `no_speech` 区间。排除已有转录窗口和已有正文覆盖的区间，保留区间外的处理记录。
4. 更新检查点和待处理标志，清除相关分析输入缓存。普通转录队列继续执行，应用重启后仍可领取这些范围。
5. 新文字沿用现有提交路径写入版本记录、时间线和搜索索引，并保留对应的原音位置。

维护操作保留旧正文及措辞，只重开仍有原音的遗漏范围。重复提交不会在尚未处理的同一区间叠加任务。

## 阈值设置与维护逻辑的验证

- 18 项 Archive 调度测试通过。新增用例覆盖限定时间范围、旧正文保留、新增正文可搜索和定位、重复补查、重开资料库、跨午夜、活动分析冲突及原音缺失。
- 2 项语音引擎测试通过，包括真实 Silero/Core ML 模型测试：切换阈值后新批次记录正确参数，旧窗口仍可识别，无效数值被拒绝。
- 5 项手机设置和协调器测试通过，覆盖默认 `0.25`、保存恢复、非法旧值、既有语言设置，以及真实录音补查在暂停和重启后的执行。
- iPhone App 与内嵌 Watch App 的 Debug 无签名构建通过，版本为 `1.14.0`。
- 包检查确认手机、手表和 Widget 的版本与共享配置一致，模型资源哈希正确。对 Debug 包执行 Release 检查时，“不含测试资料”和“不含调试入口”两项按预期未通过；本轮未生成发布包。

这些测试使用 Mac 上的真实模型、SQLite 和生产协调器。它们不代表用户手机上的 10 月 19、20 日录音已经完成补查。该数据仍在手机上，本轮设备连接不可用，尚未读取完整原音、执行补查或核对新增文字。

本次产品改动只新增阈值设置。连续分析和分批重置 VAD 所产生的差异仍需单独验证；降低阈值不构成两种执行方式结果一致的证明。

已删除设置页、导航层及运行时的补查回调。阈值与语言设置的 4 项测试、协调器的 1 项真实录音维护测试、Archive 的 3 项维护测试通过，iPhone 与内嵌 Watch 的 Debug 无签名构建通过。单独编译 `NoSpeechReview.swift` 时，不启用 `DEBUG` 的 SIL 输出不含 `reopenNoSpeech`；该检查覆盖编译条件，完整 Release 包尚未重新构建。
