## 已实现的行为

### 恢复与错误分类

- 链路错误使用明确的 URL/POSIX 白名单；ATS、TLS、证书、解码及取消不再一概当作网络瞬断。已验证 SOCKS 端点上的 `.badURL` 兼容保留。
- Tailnet 节点与连接池分别有代次；挂起或替换连接池会取消并移除旧代理自检。自检的旧成功、旧失败不能修改新连接池状态。自动与显式节点修复共用默认 60 秒的重建间隔。
- Mac 自检被配置策略拒绝、且先前的成功证据已过期时，报告 `needs_setup`，不继续伪装重连或重建节点。保留原 ATS CIDR 例外。
- 手机前台、路径变化、手动重试使用同一恢复入口；并发触发合并，补发一轮待处理意图。场景、恢复任务和 store 身份均校验；旧任务清理不清除新任务。
- 聊天与笔记立即恢复。健康数据、来源、通知、插画和批量上传在当前场景收到已认证响应后启动，移除固定 2.5 秒计时放行。
- 同场景中新成功晚于旧探测发起时，旧探测的瞬时失败不能覆盖新成功。连接恢复回调只在状态恢复或本轮前台首次确认时触发。
- 聊天与订阅指数退避加入随机抖动，保留 `Retry-After` 下限；鉴权失败仍关闭自动访问，只有显式验证当前凭据成功后重开。
- 诊断加入恢复 attempt、scene generation、触发原因和取消/认证/失败结果；不写入正文、凭据或地址。

### 笔记与上传隔离

- 笔记下载、整理状态读取和原文上传分开；笔记刷新不扫描录音库，也不等待上传回执或慢整理状态接口。
- 新增独立 `memories-cache.json`，完整分页成功后原子提交。保留旧 `context.json` 的笔记字段作为降级检查点；回退旧版本时看到的是该旧检查点，重新联网后校准。
- 笔记任务取消时立即替换代次和移除句柄；删除成功后旧笔记响应不能覆盖新缓存。上传回执只合并最新来源状态，不能重写笔记数组或上次同步时间。
- 笔记缓存损坏不会阻断原文 outbox 的打开；错误可见，原文件保留，下一次成功获取完整快照后替换。跨 library/instance 身份不一致仍拒绝使用。
- 完整 `Source.spans` 保留；说话人修正仍在上传通道、上传之前执行。
- 来源扫描每页保存，回执每 10 条保存，减少整份状态反复编码。落盘前总是基于最新 State 合并；检查点间发生进程退出最多重投未落盘回执，仍用既有幂等身份。
- 瞬时网络失败、429/可重试 5xx、配置错误立即终止本轮余下上传；笔记和上传各自保留服务端 `Retry-After` 等待窗口。窗口覆盖当前进程的前后台及手动恢复，未新增跨进程退避数据库。
- 单条 413/relay 请求过大记录持久失败并保留原文，继续其他条目；不再无限自动重放。手动重试或确认换路由后可重新发送。
- 后台授权到期先取消内层同步，再释放 OS grant/传输；保留现有 25 秒上限及系统 expiration 回调。前台期间同一后台授权到期也会取消其对应上传。

最终模拟器运行：iPhone 17 Pro / iOS 27.0 / arm64，`PhoneContextDeliveryTests` 7 项、`RemoteContextSyncTests` 18 项，共 **25 项通过、0 失败、0 跳过**。最后一次运行包含全部最终源码改动；结果摘要见 [XCTest JSON](reviews/connection-upgrade-final-tests.json)。

模拟器日志出现既有录音库 `commitReceivedChunk`、`timelineDaySnapshot` 的性能预算告警（最大约 1.1 秒），不将测试通过解读为达到真机性能门槛。最终运行没有前一轮 fixture 生命周期中的 SQLite 文件提前删除告警；测试清理已改成弱引用并取消未完同步。

关键故障注入：500 条合成 outbox 在首个 503 后只发一次 POST，笔记仍可独立落盘；413 不循环重传且手动重试可恢复；429 等待期间笔记可刷新；上传回执不会覆盖新 source revision；旧下载不能复活删除的笔记；慢 review 接口不延迟笔记读取；损坏的笔记缓存不丢 outbox。这里的耗时仅属本机 fixture，不代表真实网络 P95。

测试初次构建的两项环境问题已纠正：Xcode 的 `/tmp` 与 `/private/tmp` 符号链接导致 SPM 二进制提取失败，改用独立用户 DerivedData；全局 `-sdk iphonesimulator` 错误覆盖了 Watch SDK，移除后由 destination 自动选 SDK。均未修改产品工程以绕过错误。

## 现场与集成边界

本次只读回读到运行 Mac 的版本为 `0.6.20 / 111`，工作树配置为 `0.6.21 / 112`；版本漂移意味着不能用当前源码直接认定 11:02 断线的唯一根因。没有替换已安装应用，没有合并、推送或改变主会话工作树。

最终模拟器产物实际回读：iPhone 与内嵌 Watch 均为 `0.6.21 / 112`；未为开发验证另发发布版本。

后续集成需要先对齐主线、打包并回读两端实际版本，再执行方案 P4 的冷启动、45 分钟/2 小时后台、切网、Mac 睡眠和 24 小时验证。P3 之前仍使用现有笔记分页接口和前台轮询，不宣称已实现轻量 revision 或解决所有跨页并发写入情况。
