## 安装结果

- Release 真机构建成功。手机包和独立 Watch 包均通过签名校验；手机内嵌 Watch 包与独立包一致，版本检查通过。
- 手机覆盖安装成功，设备查询返回 1.17.0，启动成功。安装前后的接收清单由 3,397 段增加至 3,401 段，原有片段没有从清单中消失。此检查验证接收清单的保留，没有逐段重读音频。
- 手表尚未完成更新。一次开发镜像状态检查和随后三次串行独立安装均在开发隧道建立阶段失败，返回 CoreDevice 4000 / RemotePairing 1001。安装日志没有进入 AppInstall，不能把手机内嵌 Watch 包当作腕上更新成功的证据。

手表连接日志显示，蓝牙控制通道的配对验证成功，设备也返回了网络隧道服务地址。第二次安装期间，Mac 在 AWDL 接口发现对应的 `_rp-tunnel._tcp` 服务；TCP 隧道仍未建立，约 16.5 秒后触发内部超时。第三次尝试先保持点对点服务发现，结果相同。Mac 的 AWDL 接口处于 active；系统代理排除 `*.local`。这些结果不能证明 VPN、锁屏或开发镜像是根因。

本轮没有卸载应用、清除资料、重置配对、切换网络或重启连接服务。Xcode 界面读取也因屏幕捕获失败而不可用。

采样前后转录诊断计数保持为 30 次操作、10 个识别窗口，最后状态为 `waitingForContext`，没有新增本地识别完成记录。自动总结仍在运行，日志记录了多次 `MoMoAgent.AgentProviderFailure / 1`。这个结构体桥接成 NSError 后的通用数字不能区分具体的服务失败类别，尚不能判定是认证、网络或返回格式问题。

第一次成功的短时调用栈采样记录系统温度等级 **Fair**。其 256 个 CPU 样本主要落在界面更新和 WebKit 调度路径。随后 65 秒采样获得 5,975 个 CPU 样本，其中 `AutomaticInsights.process` 命中 3,665 次，`timelineDaySnapshot` 命中 2,916 次，`validTimelineSummaryRevisions` 命中 2,322 次，`validateTimelineSummary` 命中 1,397 次。这些是包含子调用的计数，彼此重叠，不能相加。剩余的周期性开销仍集中在自动总结的时间线重建与来源校验；短时采样确实会漏掉这部分。较长采样的温度等级也为 Fair。没有摄氏温度传感器读数，也没有测量机身表面温度。

本轮主进程短时内存稳定。旧版本的高负载样本与本轮任务积压、运行阶段不同，不能据此计算同条件优化百分比，也不能由这几分钟排除长时间内存泄漏。
