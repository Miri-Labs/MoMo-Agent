# iPhone 读取、回听与聊天加载修复

用户报告资料更新显示错误 0、读取记录慢、回听启动慢，并要求空聊天首页居中 MoMo、开聊移到顶部、聊天历史局部加载。

## 已定位的问题与改动

- 手机资料快照有 1,014 个音频片段、757 条待确认回执。旧自动恢复逻辑为统计回执数量调用完整回执读取，对原音及 manifest 逐个做哈希校验。现改为 SQL 数量查询；实际投递采用每页最多 32 条的游标，每个文件完成后让出 Archive actor。SQLite 查询已结束、哈希文件句柄已关闭后才挂起，不跨挂起持有事务或文件句柄。重启、重放和确认依旧由持久回执表负责，队列数量不代替原音校验。
- 单纯的回执确认、控制消息完成或空对账不再触发整库刷新。新音频、录音结束、中断和标记仍触发内容更新。启动显式加载资料，不再依赖空对账触发刷新，并移除启动时重复的一轮文件核对和投影。
- 整段回听排序原先为每个 chunk 扫描一次 epoch，现按 epoch 聚合一次后关联排序。选中时间范围回听只读取相交片段，不展开同一 session 的全部录音。冻结时间轴、缺失片段、逐片段租约、原音哈希与删除/修订屏障保留。
- 原生播放器清除 `isPlaying` 与送达结束回调之间增加最长 250ms 的交接状态，避免将正常结束误判为暂停、打断下一片段。交接期间保持进度，只有真实结束回调才判成功；没有回调的意外停止仍进入可恢复的暂停。用户暂停、停止、系统中断与取消继续立即处理。新增无结束回调的受控原生边界测试，真实短引用回放继续检查 4,000 帧终点及重播。
- 同一天内同一个 session 的录音摘要只构建一次，避免每个 epoch 重复计算。
- JSON 日期编解码复用两份受锁保护的 ISO 8601 格式器，避免每个片段重复创建、配置格式器。编码仍先取整至毫秒，再保留既有整秒/小数秒分支；解码仍兼容两者。并发回归逐字节对照原格式器的输出，保护历史投影、manifest 与哈希兼容性。
- 文件维护失败与资料读取分开处理。已存录音仍加载；错误显示具体阶段及底层 SQLite 错误码，成功维护只清除自身错误。原始“错误 0”的具体底层失败在这轮副本中未复现，不能将诊断改进写成该故障已经复现并修复。
- 空首页中央与会话顶部共用一个实时 Avatar 和名字 MoMo，使用 0.44 秒弹簧位置/尺寸过渡；减弱动态效果时直接切换。聊天恢复只显示消息区域的局部骨架屏，保留输入与导航，完成恢复前禁用发送。空首页不闪过历史占位。
- 点击 Avatar 右下角的手表小标，原地显示小型状态浮层，包含录音状态、更新时间和上次报告的待确认片段；从浮层可进入完整录音与同步页。状态继续按真实采样、接收时间及新鲜度判断，不把旧报告显示成实时连接。
- 波形按片段渐进发布，首个片段完成就显示，后续更新最多约每 150ms 一次，并显示生成进度。尚未解码的区域留空；加载中与确实无可用波形分别显示。开始播放时取消卡片上的重复预览解码，播放不等待整段波形。
- 波形 RMS 使用 Accelerate 向量计算，缓存改为每片段 1,028 字节的固定 Float32 二进制，仍兼容旧 JSON 缓存。原始音频不转码、不改写；引用仍严格按原采样帧裁切。缓存保留 64 个内存条目，磁盘每新增 16 个条目及每轮完成时批量清理至 256 个，避免每片段枚举目录。原音哈希、逐片段租约、取消及删除/修订校验继续保留；向 UI 发布前已关闭解码文件并释放租约。
- 首次发送时立即显示原生消息，网页和滚动背景在加载前按当前主题设置；网页 CSS 在桥接数据到达前也遵循系统主题。等待网页首帧绘制后再交接显示，空页或旧会话的回调不能撤掉原生首条消息。
- 新增 UI 回归暴露了两个点击问题：浮层纯文字按钮的中间空白未计入命中区域；流式回复结束后的最近聊天排序变化发生在触点获取与实际点击之间。前者改成至少 44pt 的完整矩形命中区域；后者在抽屉打开期间固定行顺序，标题和忙碌状态仍持续更新，关闭后按最新顺序展示。

## 参考与测量边界

通过 ego-browser 查看 Claude.ai 的实际首页及当次加载的[入口 bundle](https://assets-proxy.anthropic.com/claude-ai/v2/assets/v1/index-VdV7IdY5.js)，观察到可编辑外壳与历史占位分开加载；本实现采用相同的交互原则，继续使用 SwiftUI 和现有本地渲染资源。

手机资料只读复制到被忽略的本机临时目录。SQLite `quick_check` 通过；原始录音与聊天内容未提交或上传。Mac 上相同 778 行的旧/新播放排序 SQL 分别为 1.326 秒和 0.00408 秒，逐行结果一致。该数据仅衡量 SQL，不是手机点击到出声的耗时。

另通过 Mac 系统 `/usr/lib/libsqlite3.dylib`（3.54.0）复测同一查询，旧/新分别为 0.560 秒和 0.00269 秒。不同运行的系统负载和缓存不同，不将两组绝对耗时混算。选中单片段的本地 Swift 元数据读取为毫秒级；完整读取、哈希校验和原生播放器启动分别验证。
