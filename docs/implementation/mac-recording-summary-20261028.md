# 录音总结交给 Mac

手机不配置模型 API Key。总结跟随 Mac 当前选用的 Hermes 模型：Mac 选用已登录的 Codex 时，消耗该账号适用的 Codex 额度；若选用 API 模型，API Key 仍只保存在 Mac。手机原有的本地转写、原音和转录阅读保持原样。

## 数据流

1. 手机时间线继续使用已有独立总结卡片。加载可总结的录音窗口时，保存待发送请求；正文按 `summaryRevision` 校验。
2. `POST /context/v1/summaries` 使用现有配对鉴权和 Tailscale/RTC 通道，将转录文本送到 Mac。返回持久化任务回执，不等待完整模型回复。
3. Mac 使用原有 Hermes `/v1/runs` 执行，复用 Mac 的登录配置。总结采用独立的 `momo-summary-…` 会话，关闭工具、个人记忆注入、后台记忆整理与工作目录上下文，不进入正常聊天。
4. Mac 保存结果；手机前台每 5 秒补取待完成总结，写入本地缓存并更新原卡片。离线、重新打开、请求回执丢失不需要重新提交聊天消息。

Mac 已接纳的总结独立于手机生命周期。手机离线时尚未发送的请求保存在手机，恢复前台并重新连上 Mac 后发送；不承诺 iOS 被挂起或强退后持续联网。Mac 需处于可运行、可连接状态。

## 一致性与边界

- 同一资料库和正文版本返回相同任务与结果，重试不会重复消耗模型额度。进行中的转录有新版本时，Mac 合并尚未开始的旧版本请求，手机不显示过期结果。
- 手机回传前再次核对原文版本。已删除录音、过期版本或错误会话的结果不会重新进入卡片。录音原文仍由现有资料同步和删除策略管理。
- 长文本按 UTF-8 字符边界分段，先逐段总结，再合并全部段落总结；不静默截断。单请求正文上限 2 MB，超出会拒绝而不是总结前半段。
- 原生运行的接纳回执与完成状态分开处理。丢失接纳回执时沿用幂等键；超过 Hermes 保留期限而仍不确定是否执行时停为 `needs_review`，不盲目重跑。
- 仅确定失败的运行可进行最多两次额外尝试；空结果、异常结果、身份不一致不伪装成功。待检查任务保留在 Mac 的 `recording_summaries` 表中。
- 这是录音展示用的派生总结。Hermes 原有录音记忆整理和 Dream 仍走自己的触发链路，不从总结卡片另建一份长期记忆。

## 验证

- Python：`uv run --no-project python -m unittest discover -s Tests/AgentRuntime -p test_recording_summary.py -v`：9 项，覆盖 HTTP 鉴权、持久队列、丢回执、到期防重复执行、手机断开后的完成、Unicode 全文分段合并和版本隔离。
- 既有记忆整理与转录摄取回归：分别 10 项、5 项通过。
- ContextStore 9 项通过；访问层 17 项中 13 项通过、4 项因当前测试解释器缺少原生 WebRTC 依赖跳过。总结的 POST/GET 路由与鉴权已覆盖，未把跳过项记为真实跨网验证。
- 手机同步/缓存测试在 macOS 运行真实 Foundation 代码和 ArchiveStore，HTTP 使用测试响应：`uv run --no-project python Tests/Support/run-recording-summary-tests.py`。覆盖离线保存、重开后 POST 接纳/GET 完成、缓存复用和删除后旧总结不可见；不等于手机实机验收。
- 隔离 Hermes profile 使用 Mac 已登录的真实 Codex，通过生产 HTTP 入口接纳测试录音；此后停止客户端请求，生产 dispatcher 仍完成总结。重新 GET 读回结果，重复 POST 取回同一结果，没有第二次模型调用。实际构造出的 Agent 工具集合为空，没有工具调用或记忆写入。
- 实机安装及跨网验收单独记录；本次真实模型验证不冒充手机端到端验证。
- 已整合 main 的桌面标题栏修复。Mac、正式手机与内嵌手表 Release 构建通过，1.39.0 手机安装包的 29 项校验通过。本轮尚未安装到设备；Mac 总结服务仍需随新版运行源码一并更新后，手机新入口才可使用。

真实模型测试录音包含“周五下午三点发布第一版，小林检查文案；搜索只是提议”，以及伪装成指令的转录内容。结果正确保留已决定/未决定的区别，未执行转录中的指令。
