# 连续录音的语音覆盖修复

日期：2026-10-22。代码版本：1.19.9。

后续 1.19.10 已将全量间隙核验改为[选择性语音复核](selective-speech-review-20261022.md)，并保留本版完成的历史结果。以下记录对应 1.19.9。

**同日复核：** 用户指出全量核验削弱了 VAD 节省计算的作用。后续实验确认，本页的识别覆盖测试不能证明召回与效率要求已经同时解决。全量间隙核验仍在此版本代码中，尚未有验证通过的替代策略；详见 [VAD 召回与计算量复核](vad-efficiency-review-20261022.md)。

本次按三个要求改动：转录准确、不漏语音、长语音连续。用户明确要求不补跑本次已经漏掉的历史录音。升级保留已有正文及旧版已完成的无语音判定，只对未完成工作和后续收到的音频使用新流程。

## 发现的问题

抽查时，手机已收到的 5,562 个分片均已完成处理，7,203 个分析窗口也已完成，没有积压的识别失败。这只能证明已接收范围处理完毕。旧流程会把 VAD 判定为无语音的范围直接计为完成，普通重试不会重新识别这些范围。

选取 11 段一分钟原音副本，在隔离资料库中比较模型与识别结果。其中包含 4 段旧 VAD 全部漏检的样本、2 段语音对照和 5 段静音或噪声对照。该样本集用于定位问题，不用于估计全部录音的漏检率。

| 样本开始时间 | v4 检出时长 | v5 检出时长 | v6 检出时长 | 新流程是否得到正文 |
| --- | ---: | ---: | ---: | --- |
| 10:32:45 | 0 秒 | 0 秒 | 0 秒 | 是 |
| 11:37:59 | 0 秒 | 0 秒 | 0 秒 | 是 |
| 15:30:59 | 0 秒 | 47.126 秒 | 37.642 秒 | 是 |
| 18:37:59 | 0 秒 | 24.104 秒 | 23.464 秒 | 是 |

这组对比使用阈值 0.25。后两段的 v4 逐帧概率最高值分别约为 0.098 和 0.169，尚未进入切窗逻辑就被判为无语音。直接识别原音能得到正文，因此仅等待队列或重试传输不能修复此处遗漏。前两段在 v6 下仍未检出，说明更换模型也不足以解决全部遗漏。

对同一组样本，k2 发布的 v4 与 Silero 官方 v4 的逐帧概率最大差异不超过 0.00000203，未发现导出过程损坏模型的证据。降低阈值、放大音量及高通处理也未能稳定修复所有样本；本次不将这些经验参数作为唯一补偿措施。

## 处理流程

推理继续使用 sherpa-onnx 1.13.8 和 ONNX Runtime 1.28.2。SenseVoice、FunASR Nano 保留既有 Core ML EP 配置，没有加入其他推理框架。Silero 使用官方 v6.2.3 原版 ONNX，通过 sherpa 已有的 v5/v6 状态接口运行，不重新量化。来源和 SHA256 见 [语音依赖](../../Native/SpeechVendor/README.md)。

1. 原音持久接收后，协调器取得有界的待处理范围，不等待录音结束事件。
2. VAD 连续读取同一录音，保留循环状态。它负责寻找语句边界，不再决定哪些原音永远不进入 ASR。
3. 检出的语句保留原来的 0.3 秒边缘填充。剩余间隙也生成识别窗口，确保已接收核心范围完整覆盖。
4. 长段按最多 20 秒的核心范围识别。长段内部及处理批次边界可借用最多 1 秒已收到的相邻原音作上下文；核心范围互不重叠，也不超出当前处理范围。间隙核验也借用相邻语音，减少独立识别短噪声产生的假词。
5. SenseVoice 使用现有最多两个窗口的批量识别。Nano 保持上游固定 batch=1。输入框语音不等待归档凑批。
6. 每个结果通过 SQLite 提交后才成为持久进度。取消、删除或过期结果不推进正文；重建后从已提交位置继续。

不能把所有原音机械地切成带长静音的固定窗口。开发中的公开短句回归曾在这种切法下把“开放”识别为“开饭”。最终实现保留 VAD 找到的干净语句窗口，单独核验间隙；该公开短句回归已通过。

一小时测试还发现，自动语言识别会在数值全为零的音频上生成“我”等假词。最终实现对完整解码后全为零的输入直接提交空结果；其余输入只裁掉首尾精确为零的采样点，并把识别时间戳移回原始时间轴。这个检查没有音量阈值，轻声、噪声中的语音及其他非零采样仍进入 sherpa ASR。裁剪不改变原音文件。

### 跨窗口正文

有可靠 token 时间戳时，先按不重叠的核心时间范围分配正文，再对齐前一个已持久化窗口的末尾。对齐同时要求文字和原音时间接近，避免把真实的连续重复词误删。相邻窗口查询使用按配置、录音和核心结束位置建立的索引，避免每个窗口重新扫描整段历史。

无法把 token 映射回正文时，例如数字规整改变拼写，或后端没有时间戳，保留完整识别文本。这个保守分支可能保留少量重复，不根据不可靠的时间戳删除文字。原始识别结果、token 和时间戳仍完整保存。

文件边界和两分钟处理批次边界可以借用已持久接收的相邻原音。额外读取使用现有租约，原音缺失时不能虚构上下文。尚未到达手机的语音属于传输完整性问题，本次的 ASR 覆盖策略不能替代传输核对。

### 升级与历史结果

新策略使用独立配置指纹。首次运行时，资料库事务将已知旧版的完成窗口及无语音覆盖继承到新指纹，保留原描述和结果用于追溯。已有正文及其版本不变，不因模型升级重新生成全文。

未完成的冻结任务保持原范围：完成部分继承，未完成部分按新策略准备。用户暂停状态保留。后续新分片从已完成位置继续。迁移有持久标记，重复调用只检查标记，不反复扫描历史。测试同时检查旧结果不重跑和新音频仍能进入处理。

## Long sequence 的取舍

Silero v6.2.2 起提供离线 sequence ONNX，支持 16 kHz 输入。其输入将连续 512 采样点帧及上下文组合成序列，默认一次处理 512 帧，即 16.384 秒。它保留顺序循环状态，主要减少运行库调用次数，不会自动修复低概率漏检。

同一组 11 段原音在 Mac 单线程 CPU 上测试：逐帧 v6 约需 0.143–0.149 秒处理一分钟，sequence 约需 0.085 秒；逐帧概率完全一致，VAD 部分约快 1.68 倍。这不是整条 ASR 流程或手机吞吐的加速比。

当前固定版本的 sherpa VAD C API 接收逐帧模型，sequence 模型的输入输出不同，不能只替换文件。本次生产代码使用 sherpa 已支持的 v6 连续状态接口。独立 sequence 运行仅用于对比，没有加入 App。后续若手机测量证明 VAD 调用开销明显，再在同一 sherpa 桥接层内增加 sequence 支持。

参考的一手实现：

- [Silero 官方版本记录](https://github.com/snakers4/silero-vad/releases)、[sequence 使用说明](https://github.com/snakers4/silero-vad/blob/v6.2.3/examples/onnx_sequence/README.md)、[sequence 实现](https://github.com/snakers4/silero-vad/blob/v6.2.3/src/silero_vad/sequence_vad.py)：模型版本、序列状态及调用方式。
- [SenseVoice 官方长音频示例](https://github.com/FunAudioLLM/SenseVoice/blob/main/long_audio_no_vad.py)：长音频可以使用有界重叠识别，VAD 不是识别的必需前置门槛。
- [faster-whisper VAD 实现](https://github.com/SYSTRAN/faster-whisper/blob/master/faster_whisper/vad.py)：迟滞阈值、上下文填充和按静音切分。其规则不等于当前 sherpa 的最短连续检出规则，不能直接照搬参数并假设行为相同。

一小时测试的其余部分是人工补的数值零，零值输入会直接完成，所以不能用该速度推算有持续环境声的全天录音。计时包括模型加载、VAD、原音读取、识别和资料库提交，不包括音频构造、导入和构建。证据为 `verified-sparse-hour/throughput.json` 与 `speech-diagnostics.json`。测试总计为 49 个 Swift 测试函数和 3 个 Python 测试函数，部分函数带多个参数用例。

副本回归只判断是否产生正文及时间覆盖，未进行人工逐字标注，不能据此声称自然语音准确率或零漏词。测试使用当前 SenseVoice 路径；Nano 的新策略质量与时延仍需单独测量。

未检出音频现在也进入 ASR，计算量会高于旧版直接跳过的路径。真实 iPhone 上一小时录音五分钟内处理、后台调度延迟、峰值内存和发热仍是独立验收项。本次没有完成新版 App 的真机安装，也没有用 Mac 结果代替真机结论。
