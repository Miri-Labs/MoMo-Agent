## 2. 已确认的产品与技术范围

- Watch 是声音采集端；iPhone 保存资料并进行本地中文转写。SE2 与 iPhone 17 Pro 是目标设备，当前先做软件和模拟器。
- iPhone 首页是助理聊天。用户可直接派活，Pi Agent 自动获得必要的近期文字，并用工具读取原稿和保存计划。
- Agent Kit 使用 Pi / pi-durable，通过 PiDurableKit 接入；文本模型走外部 API。产品预设为百炼北京地域，真实 Agent 验收已获授权使用 OpenRouter。
- 转写采用 SenseVoiceSmall、Silero VAD、sherpa-onnx / ONNX Runtime。本版不包含本地文本模型、MCP、自建云端录音库、向量检索或系统日历写入。
- SwiftUI 使用系统控件和原生 Liquid Glass。最近一次用户反馈要求录音详情优先展示内容、回听和提问，文件管理放到次级入口。
- 18 小时持续采集是目标。模拟器或等量输入通过不能替代真实佩戴、后台、续航和 WatchConnectivity 验收。

先读 [AGENTS.md](../../AGENTS.md)、项目级 [Ponytail](../../.agents/skills/ponytail/SKILL.md) 与 [SwiftUI Expert](../../.agents/skills/swiftui-expert-skill/SKILL.md)，再按 [代码组织](../plan/code-organization.md)、[执行计划](../plan/v0.1-execution-plan.md) 和 [E2E 方案](../plan/e2e-test-plan.md) 继续。完整剩余项见 [完成审计](completion-audit.md)。

### B. HTTPS 超时阶段与故障服务器

`j17-app-03` 的 `testBodyFirstByteDeadline` 期望 `.bodyFirstByte`，实际是 `.responseHeaders`。探针确认服务器已发送 headers，但当前 Foundation 可能等到 8 秒首段 body 抵达，才触发 `didReceive(response)`。`task.response` 在等待期间为 nil，`URLSession.bytes` 也延迟；metrics 的真实响应起点只能事后取得。

因此，服务端 `headers_sent` 与 App 可观察到 headers 是两件事。已有证据支持约 2 秒期限生效，但不支持“四类期限都在 iOS 真实传输中分别通过”。候选改法是准确命名这个平台场景，并核对服务已发送 headers、0 body、客户端 `.responseHeaders` 期限；另保留 SDK 明确进入 `bodyFirstByte` 后的状态测试。**暂停时宿主测试仍保留原名及 `.bodyFirstByte` 断言，候选改法尚未落地。** 不可通过提前发送正文或放宽时间要求掩盖问题。

服务器还发现 `FaultHandler.finish` 覆盖标准库连接清理方法，导致重复写 SSE 结尾。已改为 `finish_stream` 并通过 15 个自检。service-03 曾基于修后源码启动，但未执行 `j17-app-04`，目前没有服务进程。
