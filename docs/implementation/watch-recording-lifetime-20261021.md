# 手表录音按 App 运行期间计时

用户要求移除手表“结束录音”，关闭 App 即结束本次录音。更多页删除该按钮及确认弹窗；录音信息标注“本次录音”。录音中仍可静音和标记。

每次进程启动都回到“轻触以开始”，时长为零。点击开始创建新的 session；同一进程内静音、恢复和系统音频中断继续属于本次录音。时长沿用真实采样帧与已保存片段的统计，静音和未录到声音的中断时间不累加。抬腕、息屏、回表盘和再次进入仍沿用当前录音，不把普通后台切换当成结束。

启动恢复先关闭旧进程的 epoch，并将旧 session 的 recording / paused 意图置为 stopped。旧录音、标记、已确认片段的时长及待同步队列全部保留。后台检查旧文件时，新录音仍可先开始；后续恢复不会关闭新 writer。

同步继续由已封口片段驱动，当前批次间隔为 5 分钟。旧的结束按钮只是额外保存尾段并触发一次立即同步。新流程在启动恢复完成后立即尝试补传，不等待下一批定时同步，也不要求用户先开始新录音。

watchOS 可以在没有通知的情况下终止进程，见 [Apple 的状态切换说明](https://developer.apple.com/documentation/watchkit/handling-common-state-transitions)。因此不能把强制关闭当成一次必定能执行的保存或发送回调。已经交给系统的传输由系统调度；尚未提交的片段保留在本地，下次启动恢复后补传。正在写入的 AAC 尾段只恢复可解码范围，不把重开 App 的时间当成上次录音的结束时间，也不虚构完整尾段。

验证：Mac 上运行生产 Recording / Archive 模块的定向测试，13 项通过，覆盖录音中和静音后重开、旧原音保留、重复恢复、短批次提前放行、标记和损坏尾段处理。Swift 语法检查通过。手表 UI 和原生集成用例已按新行为调整，本轮不运行模拟器。

Mac 的 J08-a 实际 SIGKILL 检查通过：生产 AAC writer 已保存的 1 秒原音保持字节和帧数一致，标记及中断事件在两次恢复间保持身份一致，旧 session 变为 stopped。未封口的 0.25 秒尾段无法独立解码，原文件和草稿原样保存在 Repair。此结果覆盖 Mac 上的录音文件与恢复逻辑，不代表真实手表关闭后的系统投递已验证。证据在 `tmp_agent_output/watch-recording-lifetime-20261021/forced-exit-check-03/`。

强杀检查器原先要求恢复后继续保持 recording，已按本次行为更新为：强杀后、恢复前保持原账本；恢复后为 stopped。前两次运行记录保留，其中一次路径错误、一次旧断言失败，均不计为通过。
