# MoMo 点击动效清晰度修复

用户截图显示点击 MoMo 时，头顶轮廓发虚，并出现随角色倾斜的矩形底。旧实现通过 SwiftUI keyframe 对整个透明 WKWebView 做缩放、旋转和位移，让网页图层参与了这些变换。

本轮将相同的 780ms 弹跳、压缩和轻晃移入 SVG 的独立 `g` 图层，原生 WKWebView 的位置和尺寸保持固定。网页视口增加 50% 透明余量，SVG 坐标同步调整为 450×450；角色静止时的可见尺寸和原生点击区域不变，跳起时头顶仍在视口内。没有新增滤镜、位图帧或依赖，也没有修改原 Avatar 的几何与闲置动作。

连续点击从当前姿态接续，最多运行一个点击动画循环，绘制上限为 60fps，结束后释放。闲置动作继续使用原来的 24fps；离开页面、进入后台、减少动态效果或销毁时停止点击动作。减少动态效果时的渲染参数通过原生结构化桥接传递。

## 验证

证据位于该 worktree 的 `tmp_agent_output/20261017-avatar-greeting-crisp/`。

- 两项原生回归通过：动效期间原生网页视口固定、SVG 内部变换持续变化、角色不裁切、背景透明、可见尺寸保持、重复点击正常结束，以及减少动态效果和停止状态。原有 Avatar 实际绘制与闲置/停止检查也通过，见 `avatar-regression-03.xcresult`。
- 两项默认字号 UI 回归通过：首次点击输入框打开软件键盘；手表小标、状态浮层、完整录音页、前后台和重启后的 MoMo 保持可用，见 `avatar-regression-02.xcresult`。该轮唯一失败是新测试在第二次点击结束前就检查结束状态，随后改成等待实际结束条件并保留 2 秒上限，原生补测通过。最初的测试编译错误及后续记录均保留。
- 已检查暗色动效中间帧 `dark-vector-greeting.png`，轮廓清楚，没有看到倾斜矩形底。此截图来自真实 WKWebView 与原生宿主。
- 手机 Release 1.0 (7) 及内嵌 Watch 包构建成功，生产源码为 `623fa07`；328 个构建输入前后哈希一致。真实产物 19/19 静态检查、深度严格签名校验通过。测试等待条件的后续改动不影响生产代码。

本轮没有安装到物理手机或手表。按用户要求，设备安装等待明确通知；模拟器截图与测试不代替新版的手机视觉验收。
