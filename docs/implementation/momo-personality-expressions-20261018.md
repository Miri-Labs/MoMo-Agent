# MoMo 的场景与性格表情

> 历史记录：用户随后指出此版变化太小，并要求眼睛也有明显变化。新的幅度、眼型和动图见 [1.7.2 眼型与动作加强](momo-expressive-motion-20261018.md)。

2026-10-18，源码版本 1.7.1。用户要求参考动画的原理后，按 MoMoAgent 的场景和性格改动，不能原封不动搬入。

## 设计取舍

现有 `MoMoAgent/Prompts/Defaults/SOUL.md` 强调直接、自然、篇幅相称、有判断；既有首页动作允许一点好奇和俏皮。表情据此表达「我在听、我在想、我在做、我听到了」，动作随任务收放。没有修改文字人格，也没有按聊天内容猜测用户情绪。

参考 [GrokBot 动画解剖](https://github.com/ArvinYin1/grokbot-animation-anatomy) 对几何、表情过渡与状态编排的分离思路。删除上一轮复制的播放器、recipes、提取器与构建时轮廓数据；这次的眼部尺寸、弯曲、倾斜、视线偏移、动作和持续时间均按 MoMo 单独编写。现有 MoMo 的身体引擎继续按原许可证复用。

| 场景 | MoMo 的表现 |
| --- | --- |
| present：日常在场 | 保留熟悉的竖向圆润眼睛和既有首页好奇转头 |
| listening：输入或读取历史 | 稍微睁开、目光朝向用户，不假装正在接收麦克风录音 |
| thinking：等待与推理 | 一侧眼睛略收、视线轻抬，温和歪头，无独立身体漂移 |
| working：真实工具执行 | 双眼稳住，以较小的 ±7° 转头表达专注 |
| speaking：正文输出 | 放松眼神、较开放的 ±12° 朝向，不按 token 反复弹跳 |
| settled：一次回复完成 | 一次柔和眯眼；1.5 秒后开始回到日常在场 |
| concerned：请求或上下文整理失败 | 轻微不对称、保持目光，不惊吓、发怒或沮丧 |
| greeting：空闲时被点击 | 有一点不对称的笑意；首页轻弹、顶部小点头，结束回到实际状态 |

忙碌时点击只短暂切到 listening，并做 2 个 SVG 坐标的轻点头，520ms 后继续当前工作。空闲首页的轻弹幅度为 22，顶部为 8；不再按第三次点击制造惊讶。打开旧的已完成会话直接显示 present，只有从思考、执行或输出进入完成才给结束反馈。介绍页继续展示相同角色与原品牌图标。

## 实现

- `Vendor/BibleStrongAvatar/momo-expressions.js` 用圆润胶囊加弯曲中心线生成眼部顶点，没有参考表情坐标。八组参数共享 64 点的顺序，随后走已有头部表面投影、眨眼和裁剪。
- `momo-expression-runtime.js` 对参数施加临界阻尼形状的缓动，按场景以 240–450ms 收到目标。中途切换从当前参数继续，重复状态不重启；完成后的收回由同一个帧时钟管理，没有新增定时器。
- 保留正常 30 / 低电量 15 次几何绘制每秒、后台/隐藏暂停、减少动态效果与销毁清理。静态模式直接绘制当前状态，不安排自动收回的时钟。
- 原生 `PersonalAgentExpression` 改为八个场景名，沿用同一 WKWebView 参数桥并传递会话 ID；结束反馈只认同一会话，切换到其他历史也不会误触发。原品牌等待动画、手表小标、MoMo 轮廓和首页到顶部的同一角色保持原职责。

## 验证

17 项头像测试、19 项聊天核心测试、品牌动画测试及离线资源校验通过。新增验证完成反馈自动收回且重复快照不重播、旧会话无庆祝、忙碌点击的轻回应，以及 64 种有向切换的 5 个时刻、两只眼睛共 640 份投影轮廓无自相交。既有动画、眨眼、连续中断、静态零调度和低电量预算回归通过。
