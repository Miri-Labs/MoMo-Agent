# 手机记忆阅读页

用户截图的问题是大灰卡片、独占一行的菜单、重复的「MoMo 的记忆」，以及直接占据阅读开头的来源 UUID/版本号。本次采用 standard 原生阅读样式：比较过缩小原卡片与无卡片列表，选择细分隔线列表，让正文占主要空间。

列表每条最多预览四行，并明确提供「查看全文」。日期与已有的归属/执行未核标记放在次要信息行；只识别约定的开头来源戳，不改写记忆、生成新摘要或删除正文中的标识。格式未知、没有正文的记录按原文显示。详情保留完整文字和证据，可以选择、分享及确认后忘记。原文改变/模型推断状态继续显示，不把未核对内容变成确定事实。

同步状态缩成可展开的一行，保留等待数量、核对数量、失败和旧版修改提示。同步状态仍由 PhoneContextSync 所有；详情按 ID 读取最新记忆，删除后返回列表，失败留在详情并显示错误。确认框属于当前页，并有明确的取消动作。

## 验证与范围

- Xcode 27 / iOS 27，iPhone 17 Pro 模拟器、系统默认字号；不添加或运行大字号测试。
- MoMoAgentRemote 构建；独立 loopback 假服务提供普通、来源戳、待核对、长内容样本，不连接个人 Mac 数据。
- 单独执行真实 MemoryPreview 类型的 Swift 断言：来源戳解析、未核标记、普通日期、正文 UUID、异常格式和没有正文的回退；同样的契约加入 iPhone integration tests。
- UI 测试覆盖列表进入全文、全文 UUID/版本保留、忘记后取消、返回重进、长文末尾保留及对比度/点击区域/控件语义检查。浅色和深色测试均通过（分别 65.8 秒、54.9 秒）；深色通过模拟器系统外观切换单独运行，不能依赖 `-AppleInterfaceStyle` 启动参数（实测不会切换此页面）。
- 静态 SwiftUI 风险扫描无发现。使用原生导航、菜单和警告框，没有增加自定义动画、材质或高频计算循环。

物理手机、VoiceOver 实际朗读和完整减少动态效果/透明度组合尚未验证；没有新的手机安装包或真机安装。本次只提交手机界面、对应本地化和测试，保留其他任务正在修改的说话人引擎及版本文件。

设计自评为暂定 84/100（证据上限）：平台 14/15、布局 14/15、原生语义 14/15、交互 18/20、动效材质 13/15、可访问性 5/10、实现 6/10。未做的设备与辅助技术验收不计为通过，不宣称已达到完整质量门槛。

复现：先以 `uv run --no-project --with aiohttp python Tests/AgentRuntime/serve_chat_interaction_fixture.py --memory` 启动隔离服务，按既有模拟器配对导入生成的 manifest；运行 `MoMoAgentRemoteUITests/MemoryReadingTests/testPreviewFullTextAndReversibleActions`。切换外观使用 `xcrun simctl ui <专用模拟器 UUID> appearance light|dark`。测试只取消忘记操作，不删除个人数据；服务必须使用 `--memory` 才提供样例。
