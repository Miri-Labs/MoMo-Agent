## 这次值得借鉴的改动

| 方向 | Auday 披露的做法 | MoMo Agent 的处理 |
| --- | --- | --- |
| 识别质量与性能分开选择 | 高效自动处理，高精度按需处理；局部恢复不永久改变之后窗口的执行配置 | 保持现有 SenseVoice CPU 基线；新增模型须单独比较中文错误率、漏检、时间映射、内存与后台取消 |
| 小声与困难片段 | 数值标定、质量校验、较小窗口恢复；可靠时间范围再交给播放 | 需要同一夹具上的质量对照，不直接打开未经测量的降噪或放大 |
| 接收与派生处理分开 | 可靠接收确认先完成，后续处理独立排队 | 现有持久回执、原音租约与增量管线继续使用；本轮修复重复交付错误唤醒处理的问题 |
| 空闲工作 | 事件触发，未变化的资格判断和上下文可复用 | 完全相同且仍有效的录音重传只重发回执，不重新标记分析，不重排波形或刷新整库 |
| 进度与恢复 | 按处理阶段展示，保留已完成工作 | 现有日期批次、采样范围和 checkpoint 已对应；补传恢复仍必须唤醒处理 |
| 播放处理与识别输入 | 播放可处理，识别保留原始输入与时间位置 | 保持原音和引用坐标；未启用有损静音省略 |
| 身份与上下文 | 本人登记独立、匹配不确定时保留未知 | 暂不加入声纹登记或从一个“我”字推断说话人 |

以上为公开实现说明，未购买或运行 Auday，未独立测量其识别率、加速路径或续航。实现细节与实际收益由我们自己的回归验证。[更新长文](https://x.com/whoisbaifu/status/2111450362720944593)

## 高精度模型的可验证候选

WhisperKit 是适合另行比较的本地 Core ML 路线。其官方项目当前推荐压缩的 Large v3 Turbo（`large-v3-v20240930_626MB`）用于 iOS/macOS 的高准确率场景，并提供按设备选择模型的能力。这是 **MoMo Agent 的候选**，不代表已确认 Auday 使用该型号；模型文件体积也不等于手机峰值内存。[官方项目](https://github.com/argmaxinc/argmax-oss-swift)

接入前应固定代码、权重与 tokenizer 版本，用现有公开语音质量工具和相同原音比较中文及中英混说、低音量、无语音、重复输出与时间戳。随后在手机上验证模型加载、每个有界窗口的延迟、峰值内存、暂停及后台到期。保留 CPU 路线与按窗口恢复；模型与语言参数必须进入配置指纹，不能复用另一个模型的 checkpoint。当前没有该候选的实测质量与手机资源结果，因此本轮没有替换生产识别模型。

## 本轮代码范围

`ArchiveStore.commitReceivedChunk` 区分首次接收、有效副本重传与原音恢复。有效副本重传继续校验和重发原回执，保留已经完成的分析状态；原音缺失或归档状态恢复时重新唤醒。接收协调器只为实际内容变化通知转写、资料库和波形准备。此结果枚举只在本地代码中使用，不修改 WatchConnectivity 的线协议。

旧实现的失败回归确认：同一已完成片段重传 50 次，会产生 150 次 SQLite 行更新，并重新将该 epoch 标记为待检查。修复后只有第一次重传将已确认的回执重新设为待发送，合计 1 次行更新；后续交付保留待发送状态和已经完成的分析，不重排波形或触发整库刷新。完整校验原音仍然保留。此数值来自小型受控夹具，不代表手机整体 CPU 或耗电降低相同比例。

169 项档案测试、2 项跨设备对账恢复测试、12 项 iPhone 接收层原生测试通过。新增原生回归同时检查原音补传成功后仍通知一次，以及损坏补传失败后仍更新可用状态且不生成波形。崩溃恢复工具已通过编译，适配新增的本地恢复结果。

签名 Release 构建、27 项实际包检查及深度严格签名检查通过。版本为 **1.6.3**，内部构建序号为 27，手机及内嵌 Watch/Widget 版本一致。专用模拟器验证后已删除。本轮没有验证手机实际耗电，也没有得到新模型的中文质量对照结果。
