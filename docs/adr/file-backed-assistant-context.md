# 文件化的助理人格与记忆

日期：2026-10-15。用户要求参考 Hermes Agent 的 system prompt / SOUL.md 架构，迁入 MoMo Agent。

采用 Hermes 的职责划分：SOUL.md 管人格，USER.md 管用户资料，MEMORY.md 管精简的跨对话记忆；产品权限、来源与时间规则由程序拥有，录音上下文单独注入。研究来源和固定版本见 [源码分析](../research/hermes-prompt-architecture.md)。不引入桌面终端、项目目录发现、人格预设市场或第二套 Agent 循环。

这些 Markdown 文件由 MoMoAgent 存在现有 Agent 私有目录的 `Persona/`，首次使用从包内默认人格建立。设置页只调用文档读取、条件保存和恢复默认接口，不拼提示词、不接触 Pi。文件有 UTF-8 字节上限、严格解码、原子写入、文件锁和版本检查；损坏或超限明确报错，不吞错后继续发送旧缓存。

注入顺序固定为人格 → 产品规则 → 用户资料/长期记忆 → 本轮录音摘录。人格只出现一次；资料以 JSON 编码，不能改变工具权限。无内容的人格明确使用默认值，空资料不制造事实。默认人格保留直接、自然回答、不播报查录音过程的要求，计划能力继续移除。

Hermes 在会话开始/压缩重建时冻结文件快照。本应用调整为每个**新逻辑请求**捕获快照，随 request ID 持久化；同一请求的模型/工具循环、失败重试和进程重启均沿用它。下一条新消息才读取最新文件。这样设置修改可及时生效，同时不会在半次工具循环中改变人格或让重试换上下文。Pi 已有分段提示词存储继续负责缓存，不增加自己的模型循环。

新增一个 `memory` 工具，仅可读写 USER/MEMORY；SOUL 和产品规则不开放给模型修改。仅在用户要求记住、纠正或忘记长期信息时写入，不能从录音命令自动保存，不用于待办或计划。写入要求当前版本并返回确认；中断写工具不自动重放，恢复后可读取确认。设置编辑与工具写入共用同一校验路径，冲突不能覆盖新内容。

模型侧支持 `read / add / patch / remove`；多项变更通过同一目标的 `operations` 批次提交。条目采用 Hermes 的完整分隔符 `\n§\n`，新增去重，局部修改只换唯一匹配的原文，整条删除回报被删除内容。批次只检查最终容量，任一步失败均不落盘；连续三次写入失败后本轮不再接受记忆写入。整份文档编辑仅留给设置页，不向模型提供整份覆盖工具。

用户清空资料会影响后续新请求；已发出的 API 请求、现有聊天文字和同一请求的持久恢复快照不会因此被撤回。设置中明确展示这一生效边界及发送范围。
